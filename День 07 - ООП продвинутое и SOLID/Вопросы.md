**1. Что такое MRO?**
<details><summary>Ответ</summary>
Method Resolution Order — порядок поиска методов/атрибутов в иерархии классов. Вычисляется C3-линеаризацией: подклассы раньше родителей, порядок родителей сохраняется.
</details>

**2. Что выведет `D().m()`?**
```python
class A:
    def m(self): print("A")
class B(A):
    def m(self): print("B")
class C(A):
    def m(self): print("C")
class D(B, C): pass
```
<details><summary>Ответ</summary>
`B`. MRO: D → B → C → A; метод найден в B, дальше поиск прекращается.
</details>

**3. Что выведет цепочка с `super()`?**
```python
class D(B, C):
    def m(self):
        print("D"); super().m()
# при B.m и C.m, каждый вызывает super().m()
```
<details><summary>Ответ</summary>
`D`, `B`, `C`, `A` — `super()` идёт по MRO, а не к прямому родителю. Это кооперативное множественное наследование.
</details>

**4. Что такое метакласс?**
<details><summary>Ответ</summary>
Класс, экземплярами которого являются классы. По умолчанию `type`. Используется в ORM, регистрации классов, валидации интерфейса.
</details>

**5. Зачем `__slots__`?**
<details><summary>Ответ</summary>
Ограничивает набор атрибутов и убирает `__dict__`, экономя память. Минус — нельзя добавлять новые атрибуты, сложнее с множественным наследованием.
</details>

**6. Абстрактный класс vs интерфейс в Python?**
<details><summary>Ответ</summary>
Абстрактный класс (`ABC`) может иметь реализованные методы и состояние. Интерфейс — абстрактный класс, где все методы абстрактные. `Protocol` задаёт интерфейс без наследования.
</details>

**7. Перечисли SOLID.**
<details><summary>Ответ</summary>
SRP, OCP, LSP, ISP, DIP — единственная ответственность, открытость/закрытость, подстановка Лисков, разделение интерфейсов, инверсия зависимостей.
</details>

**8. Приведи пример нарушения LSP.**
<details><summary>Ответ</summary>
`Penguin(Bird)` с методом `fly()`, который бросает исключение, ломает код, ожидающий, что любая `Bird` умеет летать. Решение — разделить иерархию на летающих/нелетающих.
</details>

**9. Что такое инъекция зависимостей (DIP)?**
<details><summary>Ответ</summary>
Передача зависимости извне через абстракцию (интерфейс), а не создание конкретного класса внутри. Позволяет легко подменять реализации и тестировать.
</details>

**10. Реализуй Singleton двумя способами.**
<details><summary>Ответ</summary>

```python
# 1) через __new__
class S1:
    _i = None
    def __new__(cls):
        if cls._i is None:
            cls._i = super().__new__(cls)
        return cls._i

# 2) через метакласс
class SingletonMeta(type):
    _i = {}
    def __call__(cls, *a, **kw):
        if cls not in cls._i:
            cls._i[cls] = super().__call__(*a, **kw)
        return cls._i[cls]
```
</details>

## Мини-задача
Реализуй паттерн Strategy: класс `Sorter` принимает стратегию сортировки и применяет её к списку.
<details><summary>Решение</summary>

```python
class Ascending:
    def sort(self, data): return sorted(data)
class Descending:
    def sort(self, data): return sorted(data, reverse=True)

class Sorter:
    def __init__(self, strategy):
        self.strategy = strategy
    def run(self, data):
        return self.strategy.sort(data)

print(Sorter(Ascending()).run([3, 1, 2]))    # [1, 2, 3]
print(Sorter(Descending()).run([3, 1, 2]))   # [3, 2, 1]
```
</details>
