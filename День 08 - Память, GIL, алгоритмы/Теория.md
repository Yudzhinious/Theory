# День 8 — Память, GIL и алгоритмы

> Цель: объяснить, как Python управляет памятью, что такое GIL и уметь оценить сложность алгоритма.

---

## 0. Коротко о главном

- **Память** в CPython освобождается двумя механизмами: подсчётом ссылок (немедленно) и циклическим сборщиком (для циклов).
- **GIL** — глобальная блокировка: в один момент байт-код выполняет только один поток.
- **Big-O** — язык оценки роста затрат алгоритма при росте данных.
- **Timsort** — стандартная сортировка Python: `O(n log n)` и стабильная.

Аналогия для refcount: у каждого объекта «счётчик жильцов». Пока хоть кто-то на него ссылается — объект жив. Как только счётчик стал нулём — объект убирают.

---

## 1. Подсчёт ссылок (Reference Counting)

Основной механизм освобождения памяти в CPython. Каждый объект хранит **счётчик ссылок** (`refcount`).

- Новая ссылка → +1, удаление ссылки → -1.
- Когда счётчик = 0 → память освобождается **немедленно**.

```python
import sys
a = [1, 2, 3]
sys.getrefcount(a)   # 2 (a + временная ссылка в getrefcount)
b = a
sys.getrefcount(a)   # 3
del b
sys.getrefcount(a)   # 2
```

### Пошагово

1. `a = [1, 2, 3]` — создан список, refcount = 1 (ссылка `a`).
2. `sys.getrefcount(a)` временно добавляет аргумент функции → счётчик 2.
3. `b = a` — теперь две переменные смотрят на список, refcount = 2 (плюс временная).
4. `del b` — удалили `b`, refcount вернулся к 1.

### Почему `getrefcount` всегда показывает +1

Аргумент передаётся в функцию по ссылке, что временно увеличивает счётчик. Поэтому реальное число ссылок обычно на единицу меньше.

### Проблема: циклические ссылки

```python
class Node:
    pass

a = Node()
b = Node()
a.other = b
b.other = a       # цикл
del a, b          # счётчики не станут нулём
```

Каждый ссылается на другого, поэтому refcount никогда не дойдёт до нуля. Тут на помощь приходит циклический GC.

## 2. Циклический GC и поколения

Дополнительный механизм, который периодически ищет недостижимые **циклы**.

- **Поколения:** 0 (молодые), 1, 2 (старые). Молодые проверяются чаще («большинство объектов умирают молодыми»).
- Пороги по умолчанию: `(700, 10, 10)`.
- `gc.collect()`, `gc.disable()`, `gc.get_threshold()`.

```python
import gc
a, b = Node(), Node()
a.parent = b; b.parent = a
del a, b
gc.collect()   # соберёт цикл
```

### Как работают поколения

| Поколение | Что там | Как часто проверяется |
|---|---|---|
| 0 | новые объекты | при 700 аллокациях |
| 1 | пережили сборку 0 | каждые 10 сборок поколения 0 |
| 2 | долгожители | каждые 10 сборок поколения 1 |

Порог `(700, 10, 10)` означает: собрать поколение 0 после 700 «созданий минус удалений», поколение 1 — раз в 10 сборок 0-го, поколение 2 — раз в 10 сборок 1-го.

### Пример проверки

```python
import gc

print(gc.get_threshold())    # (700, 10, 10)
print(gc.isenabled())        # True
gc.disable()                 # отключить (осторожно!)
gc.enable()
gc.collect()                 # принудительная полная сборка
```

### Зачем отключать GC

Иногда в критичных по производительности участках GC отключают, чтобы избежать пауз. Но тогда нужно вручную следить за памятью и включать обратно.

## 3. `weakref` — слабые ссылки

Слабая ссылка **не увеличивает** счётчик, поэтому не мешает удалению и не создаёт цикл.

```python
import weakref
child.parent = weakref.ref(root)   # слабая ссылка
child.parent()                     # доступ: вызов как функция; None, если объект удалён
```

Применение: ссылки «ребёнок → родитель», кэши.

### Пример

```python
import weakref

class Node:
    def __init__(self, name):
        self.name = name
    def __repr__(self):
        return f"Node({self.name})"

root = Node("root")
ref = weakref.ref(root)

print(ref())        # Node(root)
del root
print(ref())        # None — объект удалён
```

### Слабые словари

```python
import weakref

cache = weakref.WeakValueDictionary()
cache["key"] = Node("временный")
print(cache["key"])       # есть
del ...
print(cache.get("key"))   # может исчезнуть, если на объект нет ссылок
```

`WeakValueDictionary` автоматически удаляет записи, когда на значение не остаётся сильных ссылок.

## 4. GIL (Global Interpreter Lock)

**GIL** — глобальная блокировка интерпретатора CPython: в один момент только **один поток** выполняет байт-код Python.

**Следствия:**
- Потоки **не дают** параллелизма для CPU-задач (работают по очереди на одном ядре).
- Потоки **полезны** для I/O: GIL отпускается во время ожидания I/O.
- Для CPU-параллелизма — `multiprocessing` (у каждого процесса свой GIL).

**Зачем GIL:** упрощает управление памятью (refcount без блокировок), ускоряет однопоточный код, упрощает C-расширения.

**Как обойти:** `multiprocessing`, C-расширения (NumPy/Pandas отпускают GIL), `numba`/`Cython`.

> Детали и код: `[[Многопоточность, многопроцессорность, асинхронность]]` (День 9).

### Когда потоки помогают, а когда нет

| Задача | Потоки (`threading`) | Процессы (`multiprocessing`) |
|---|---|---|
| Скачивание файлов | да | да (дороже) |
| Чтение БД/сети | да | да |
| Сложные вычисления | нет (GIL) | да |
| Общий объект в памяти | легко | сложно (сериализация) |

### Аналогия

GIL — как один микрофон в комнате: говорить может только один человек. Если кто-то ушёл ждать (I/O), микрофон свободен, и другой может говорить. Но если все хотят считать вслух одновременно — придётся ждать очереди.

## 5. Big-O: сложность алгоритмов

| Нотация | Название | Пример |
|---|---|---|
| O(1) | константа | доступ к элементу списка/словаря |
| O(log n) | логарифм | бинарный поиск, поиск в B-tree |
| O(n) | линейная | перебор списка |
| O(n log n) | — | эффективные сортировки |
| O(n²) | квадрат | вложенные циклы, bubble sort |
| O(2ⁿ) | экспонента | наивный Фибоначчи, подмножества |

Оценивают **худший** случай (иногда средний). Память тоже оценивают: O(1) vs O(n).

### Как оценивать

1. Уберите константы: `O(3n)` → `O(n)`.
2. Оставьте самый быстрорастущий член: `O(n² + n)` → `O(n²)`.
3. Вложенные циклы перемножаются: два цикла по `n` → `O(n²)`.
4. Деление задачи пополам → `O(log n)`.

### Примеры кода

```python
# O(1) — не зависит от размера
def first(items):
    return items[0]

# O(n) — один проход
def total(items):
    s = 0
    for x in items:
        s += x
    return s

# O(n^2) — двойной цикл
def pairs(items):
    for i in items:
        for j in items:
            pass

# O(log n) — бинарный поиск
def bsearch(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target:
            return mid
        if arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```

### Сложность типовых операций

| Операция | Сложность |
|---|---|
| `list[i]` | O(1) |
| `list.append` | O(1) амортизированно |
| `x in list` | O(n) |
| `dict[k]` | O(1) в среднем |
| `x in dict/set` | O(1) в среднем |
| `list.insert(0, x)` | O(n) |
| `sorted(list)` | O(n log n) |

**Типичная ошибка:** искать элемент в списке внутри цикла — `O(n²)`. Замените список на множество: `if x in set_` — `O(1)`.

## 6. Сортировки и Timsort

- **Timsort** — стандартная сортировка Python (`list.sort`, `sorted`). Гибрид merge sort и insertion sort, использует «уже отсортированные куски» (runs). Сложность **O(n log n)**, на почти отсортированных данных — близко к O(n). **Стабильная.**
- **Быстрая сортировка (quicksort)** — O(n log n) в среднем, O(n²) в худшем.
- **Сортировка слиянием (merge sort)** — всегда O(n log n), стабильная, требует O(n) памяти.
- **Пузырьковая (bubble)** — O(n²), учебная.

```python
sorted([3, 1, 2])                       # [1, 2, 3]
sorted(["bb", "a"], key=len)            # ['a', 'bb']
```

**Стабильность** важна при сортировке по нескольким ключам.

### Что значит «стабильная»

Равные элементы сохраняют исходный порядок.

```python
data = [("b", 2), ("a", 1), ("b", 1)]
print(sorted(data, key=lambda x: x[1]))
# [('a', 1), ('b', 1), ('b', 2)]
# два элемента с ключом 1: 'a' был раньше 'b' и остался раньше
```

### Сортировка по нескольким ключам

```python
students = [("Аня", 5), ("Боря", 3), ("Вера", 5)]
# сначала по оценке (убыв.), при равенстве — по имени
students.sort(key=lambda s: s[0])
students.sort(key=lambda s: s[1], reverse=True)
print(students)   # [('Аня', 5), ('Вера', 5), ('Боря', 3)]
```

Благодаря стабильности второй `sort` не перемешает равные оценки.

### Сравнение сортировок

| Алгоритм | Среднее | Худшее | Память | Стабильна |
|---|---|---|---|---|
| Timsort | O(n log n) | O(n log n) | O(n) | да |
| Quicksort | O(n log n) | O(n²) | O(log n) | нет |
| Merge sort | O(n log n) | O(n log n) | O(n) | да |
| Bubble sort | O(n²) | O(n²) | O(1) | да |

## 7. Базовые структуры и приёмы

- **Хеш-таблица** — основа `dict`/`set`, O(1) в среднем.
- **Стек** (LIFO) — `list`/`deque`.
- **Очередь** (FIFO) — `deque`.
- **Связный список** — вставка/удаление O(1), доступ O(n).
- **Two pointers** — два указателя для задач на массивах.
- **Скользящее окно** — подмассивы/подстроки.
- **Бинарный поиск** — O(log n) на отсортированных данных.
- **Динамическое программирование** — разбиение на подзадачи (Фибоначчи, рюкзак).

```python
# Бинарный поиск
import bisect
arr = [1, 3, 5, 7]
bisect.bisect_left(arr, 5)   # 2
```

### Two pointers

```python
def has_pair(nums, target):
    nums.sort()
    lo, hi = 0, len(nums) - 1
    while lo < hi:
        s = nums[lo] + nums[hi]
        if s == target:
            return True
        if s < target:
            lo += 1
        else:
            hi -= 1
    return False

print(has_pair([1, 2, 3, 4], 7))   # True
```

### Скользящее окно

```python
def max_sum_window(nums, k):
    window = sum(nums[:k])
    best = window
    for i in range(k, len(nums)):
        window += nums[i] - nums[i - k]
        best = max(best, window)
    return best

print(max_sum_window([1, 2, 3, 4, 5], 2))   # 9
```

### Стек и очередь

```python
from collections import deque

stack = [1, 2, 3]
stack.append(4)     # push
stack.pop()         # pop → 4 (LIFO)

queue = deque([1, 2, 3])
queue.append(4)     # в конец
queue.popleft()     # из начала → 1 (FIFO, O(1))
```

**Ошибка:** использовать `list.pop(0)` как очередь — это `O(n)`, потому что сдвигаются все элементы. Берите `deque`.

## 8. Мини-итог и связки

- Refcount освобождает объект сразу, но не справляется с циклами.
- Циклический GC работает по поколениям, чаще проверяя молодые объекты.
- `weakref` не мешает удалению — удобно для кэшей и обратных ссылок.
- GIL ограничивает потоки в CPU-задачах; для вычислений — процессы.
- Big-O описывает рост; помните про амортизированную и среднюю сложность.
- Timsort быстр и стабилен; стабильность помогает при многоуровневой сортировке.
- Хеш-таблицы, two pointers, окно, бинарный поиск и DP — базовый арсенал.
