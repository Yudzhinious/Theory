# День 8 — Память, GIL и алгоритмы

> Цель: объяснить, как Python управляет памятью, что такое GIL и уметь оценить сложность алгоритма.

---

## 1. Подсчёт ссылок (Reference Counting)

Основной механизм освобождения памяти в CPython. Каждый объект хранит **счётчик ссылок** (`refcount`).

- Новая ссылка → +1, удаление ссылки → -1.
- Когда счётчик = 0 → память освобождается **немедленно**.

```python
import sys
a = [1, 2, 3]
sys.getrefcount(a)   # 2 (a + временная ссылка в getrefcount)
b = a
sys.getrefcount(a)   # 3
del b
sys.getrefcount(a)   # 2
```

**Проблема:** циклические ссылки не удаляются (счётчик никогда не станет 0).

## 2. Циклический GC и поколения

Дополнительный механизм, который периодически ищет недостижимые **циклы**.

- **Поколения:** 0 (молодые), 1, 2 (старые). Молодые проверяются чаще («большинство объектов умирают молодыми»).
- Пороги по умолчанию: `(700, 10, 10)`.
- `gc.collect()`, `gc.disable()`, `gc.get_threshold()`.

```python
import gc
a, b = Node(), Node()
a.parent = b; b.parent = a
del a, b
gc.collect()   # соберёт цикл
```

## 3. `weakref` — слабые ссылки

Слабая ссылка **не увеличивает** счётчик, поэтому не мешает удалению и не создаёт цикл.

```python
import weakref
child.parent = weakref.ref(root)   # слабая ссылка
child.parent()                     # доступ: вызов как функция; None, если объект удалён
```

Применение: ссылки «ребёнок → родитель», кэши.

## 4. GIL (Global Interpreter Lock)

**GIL** — глобальная блокировка интерпретатора CPython: в один момент только **один поток** выполняет байт-код Python.

**Следствия:**
- Потоки **не дают** параллелизма для CPU-задач (работают по очереди на одном ядре).
- Потоки **полезны** для I/O: GIL отпускается во время ожидания I/O.
- Для CPU-параллелизма — `multiprocessing` (у каждого процесса свой GIL).

**Зачем GIL:** упрощает управление памятью (refcount без блокировок), ускоряет однопоточный код, упрощает C-расширения.

**Как обойти:** `multiprocessing`, C-расширения (NumPy/Pandas отпускают GIL), `numba`/`Cython`.

## 5. Big-O: сложность алгоритмов

| Нотация | Название | Пример |
|---|---|---|
| O(1) | константа | доступ к элементу списка/словаря |
| O(log n) | логарифм | бинарный поиск, поиск в B-tree |
| O(n) | линейная | перебор списка |
| O(n log n) | — | эффективные сортировки |
| O(n²) | квадрат | вложенные циклы, bubble sort |
| O(2ⁿ) | экспонента | наивный Фибоначчи, подмножества |

Оценивают **худший** случай (иногда средний). Память тоже оценивают: O(1) vs O(n).

## 6. Сортировки и Timsort

- **Timsort** — стандартная сортировка Python (`list.sort`, `sorted`). Гибрид merge sort и insertion sort, использует «уже отсортированные куски» (runs). Сложность **O(n log n)**, на почти отсортированных данных — близко к O(n). **Стабильная.**
- **Быстрая сортировка (quicksort)** — O(n log n) в среднем, O(n²) в худшем.
- **Сортировка слиянием (merge sort)** — всегда O(n log n), стабильная, требует O(n) памяти.
- **Пузырьковая (bubble)** — O(n²), учебная.

```python
sorted([3, 1, 2])                       # [1, 2, 3]
sorted(["bb", "a"], key=len)            # ['a', 'bb']
```

**Стабильность** важна при сортировке по нескольким ключам.

## 7. Базовые структуры и приёмы

- **Хеш-таблица** — основа `dict`/`set`, O(1) в среднем.
- **Стек** (LIFO) — `list`/`deque`.
- **Очередь** (FIFO) — `deque`.
- **Связный список** — вставка/удаление O(1), доступ O(n).
- **Two pointers** — два указателя для задач на массивах.
- **Скользящее окно** — подмассивы/подстроки.
- **Бинарный поиск** — O(log n) на отсортированных данных.
- **Динамическое программирование** — разбиение на подзадачи (Фибоначчи, рюкзак).

```python
# Бинарный поиск
import bisect
arr = [1, 3, 5, 7]
bisect.bisect_left(arr, 5)   # 2
```
