# День 16 — Интерпретаторы и байт-код

> Цель: объяснить, как Python исполняет код, что такое CPython/PyPy и зачем нужен `.pyc`.

---

## 1. Python — компилируемый или интерпретируемый?

Формально: **и то, и другое**. Исходник компилируется в **байт-код**, который затем исполняется **виртуальной машиной** (интерпретация). То есть сначала компиляция, потом интерпретация.

```
исходник .py → компилятор → байт-код .pyc → PVM (виртуальная машина) → результат
```

Сравнение с другими языками:
- **C/C++** — компилируются в машинный код заранее (ahead-of-time).
- **Java** — компилируется в байт-код JVM, исполняется JIT/интерпретатором.
- **Python (CPython)** — компилируется в байт-код CPython, исполняется в PVM.

---

## 2. Байт-код и модуль `dis`

```python
import dis

def add(a, b):
    return a + b

dis.dis(add)
# LOAD_FAST a, LOAD_FAST b, BINARY_OP +, RETURN_VALUE
```

Байт-код — низкоуровневые инструкции для виртуальной машины. Он не привязан к железу (в отличие от машинного кода).

---

## 3. `.pyc` и `__pycache__`

При импорте модуля CPython кэширует скомпилированный байт-код в `__pycache__/module.cpython-312.pyc`. При следующем импорте, если исходник не менялся, байт-код берётся из кэша — быстрее.

- `.pyc` создаётся **только для импортируемых** модулей (главный скрипт не кэшируется).
- `__cached__` модуля указывает на `.pyc`.
- Байт-код не является «защитой» кода — его можно декомпилировать.

## 4. Реализации Python

| Реализация | Особенности |
|---|---|
| **CPython** | эталонная, на C, с GIL. Используется по умолчанию |
| **PyPy** | JIT-компиляция, часто быстрее для CPU-кода, но хуже с C-расширениями |
| **Jython** | на JVM, интеграция с Java |
| **IronPython** | на .NET |
| **MicroPython** | для микроконтроллеров |
| **GraalPy** | на GraalVM |

> В Python 3.13+ появился экспериментальный CPython без GIL (free-threaded). До этого GIL — часть CPython, а не языка.

---

## 5. Интерпретация vs компиляция vs JIT

- **Интерпретация** — исполнение инструкций по одной во время работы.
- **Компиляция (AOT)** — перевод в машинный код заранее.
- **JIT (Just-In-Time)** — компиляция «горячих» участков во время выполнения (PyPy, JVM). Компромисс: быстрее интерпретации, дороже старт.

---

## 6. Как CPython исполняет программу

1. **Лексер/парсер** → **AST** (абстрактное синтаксическое дерево).
2. **Компилятор** → байт-код.
3. **PVM** (Python Virtual Machine) выполняет байт-код, управляя стеком и объектами.

```python
import ast
tree = ast.parse("x = 1 + 2")
print(ast.dump(tree, indent=2))
```

---

## 7. GIL и интерпретатор

GIL — деталь **реализации CPython**, а не языка. Именно из-за него потоки не дают CPU-параллелизма. В PyPy/Jython GIL ведёт себя иначе (Jython вообще без GIL). Это частый уточняющий вопрос.
