## 1. Конвейер компиляции CPython

```
исходник
  → tokenizer (лексер)
  → parser (PEG, 3.9+) → AST
  → symbol table (области видимости)
  → compiler → code object (байт-код)
  → PVM (интерпретация)
```

### Пошагово

1. **Tokenizer** — режет текст на токены (`def`, `x`, `+`, отступы).
2. **Parser** — строит **AST** (абстрактное синтаксическое дерево). С Python 3.9
   используется **PEG-парсер** (более выразительные грамматики).
3. **Symbol table** — определяет, какие имена локальные, свободные (замыкание),
   глобальные. От этого зависит, будет ли `LOAD_FAST` или `LOAD_GLOBAL`.
4. **Compiler** — обходит AST и генерирует **code object** с байт-кодом.
5. **PVM** — исполняет байт-код.

- **AST** — дерево синтаксиса (`ast`), используется инструментами (линтеры,
  рефакторинг, форматтеры).
- **Symbol table** определяет локальные/свободные/глобальные имена.

```python
import ast
ast.dump(ast.parse("x = 1 + 2"), indent=2)
```

```python
# Обход AST: найти все имена переменных
import ast
tree = ast.parse("a = 1\nb = a + 2")
for node in ast.walk(tree):
    if isinstance(node, ast.Name):
        print(node.id, "load" if isinstance(node.ctx, ast.Load) else "store")
# a store / a load / b store
```

## 2. Code object и кадры (frames)

### Code object

Функция хранит **code object** с метаданными и байт-кодом:

```python
def f(a, b=1):
    x = a + b
    return x

f.__code__.co_varnames   # ('a', 'b', 'x')
f.__code__.co_argcount   # 2
f.__code__.co_consts     # (None,) или (None, 1) в зависимости от версии
f.__code__.co_names      # () — глобальные/атрибутные имена
f.__code__.co_code       # сырые байты байт-кода
f.__code__.co_filename   # путь к файлу
f.__code__.co_firstlineno # номер первой строки
```

| Атрибут | Что хранит |
|---|---|
| `co_varnames` | имена локальных переменных и аргументов |
| `co_argcount` | число позиционных аргументов |
| `co_consts` | константы (числа, строки, docstring, `None`) |
| `co_names` | имена глобальных/атрибутов |
| `co_code` | сырые байты байт-кода |
| `co_freevars` | имена из замыкания |
| `co_cellvars` | имена, захваченные вложенными функциями |

### Frame

**Frame** — контекст выполнения: локальные переменные, стек, позиция в байт-коде.
Каждый вызов функции создаёт новый frame.

```python
import sys, inspect

def inner():
    frame = sys._getframe()
    print(frame.f_code.co_name)      # 'inner'
    print(frame.f_lineno)            # текущая строка
    return inspect.currentframe().f_back   # кадр вызывающего

inner()
```

Аналогия: code object — это «чертёж функции» (один на функцию), frame — «рабочий
стол» конкретного вызова (свой у каждого вызова).

## 3. Байт-код

```python
import dis
dis.dis(f)
```

- **Стек-машина:** инструкции кладут/снимают значения со стека.
- Частые опкоды: `LOAD_FAST`, `LOAD_CONST`, `LOAD_GLOBAL`, `STORE_FAST`,
  `BINARY_OP`, `CALL`, `RETURN_VALUE`, `JUMP`.
- `dis.Bytecode(f)` — программный доступ к инструкциям.

```python
import dis
for instr in dis.get_instructions(f):
    print(instr.offset, instr.opname, instr.argval)
```

### Опкоды по группам

| Группа | Примеры | Смысл |
|---|---|---|
| Загрузка | `LOAD_FAST`, `LOAD_CONST`, `LOAD_GLOBAL` | положить на стек |
| Сохранение | `STORE_FAST`, `STORE_NAME` | снять со стека в переменную |
| Арифметика | `BINARY_OP` | бинарная операция |
| Вызовы | `CALL`, `CALL_FUNCTION` | вызов функции |
| Переходы | `JUMP`, `POP_JUMP_IF_FALSE` | ветвления/циклы |
| Возврат | `RETURN_VALUE` | вернуть результат |

### Разбор примера

```python
import dis
dis.dis("x = a + b")
```

Упрощённо: `LOAD_NAME a`, `LOAD_NAME b`, `BINARY_OP +`, `STORE_NAME x`. Сначала
оба операнда на стеке, затем операция, затем результат в переменную.

## 4. Оптимизации компилятора

- **Constant folding:** `1 + 2` сворачивается в `3` ещё на этапе компиляции.
- **Peephole optimizer** — локальные оптимизации байт-кода (убрать лишние
  загрузки/сохранения).
- `-O` / `-OO` — убирает `assert` и docstrings; задаёт `__debug__ = False`.
- **Specializing adaptive interpreter** (3.11+) — байт-код адаптируется к типам
  во время выполнения (например, `BINARY_OP` запоминает, что складывались int).

```python
import dis

# constant folding: результат уже 3 в константах
dis.dis("x = 1 + 2")
print(compile("x = 1 + 2", "<s>", "exec").co_consts)   # (3, None)
```

```python
# assert исчезает при -O
assert 1 == 2, "никогда"     # при python -O просто ничего не проверит
```

> Типичная ошибка: полагаться на `assert` для проверки входных данных в
> продакшене. С `-O` проверка исчезнет. Используйте явный `if ...: raise`.

### `__debug__`

```python
if __debug__:
    print("отладочная информация")   # не выполнится под -O / -OO
```

## 5. `.pyc` и магия

- `.pyc` содержит **magic number** (привязан к версии Python) + timestamp/hash +
  маршаллизованный code object.
- Несовместимость версий → перекомпиляция.
- Байт-код **можно декомпилировать** (не защита кода).
- `py_compile`, `compileall` — ручная компиляция.

```python
import py_compile
py_compile.compile("module.py")     # создаст __pycache__/module.*.pyc
```

```bash
python -m compileall .              # скомпилировать все модули в дереве
```

### Формат `.pyc` (упрощённо)

```
[magic number 4 байта][флаги 4 байта][mtime или hash][размер][marshal(code object)]
```

Magic number меняется между версиями — поэтому кэш 3.11 не используется в 3.12.

## 6. Импорт-система: finders и loaders

- `sys.meta_path` — список **finders** (`PathFinder`, `BuiltinImporter`,
  `FrozenImporter`).
- Finder возвращает **spec**, loader загружает и исполняет модуль.
- Хуки импорта (PEP 302/451) позволяют кастомную загрузку (zip, сеть).
- `importlib.import_module`, `importlib.util.spec_from_file_location`.

### Как происходит `import my_module`

1. Проверяется `sys.modules` (кэш уже импортированных).
2. Если нет — идут по `sys.meta_path`, ищут finder.
3. Finder возвращает `ModuleSpec` (где файл, какой loader).
4. Loader читает/компилирует модуль в code object.
5. Code object исполняется в namespace модуля.
6. Модуль кладётся в `sys.modules`.

```python
import importlib
mod = importlib.import_module("json")           # импорт по строке
print(mod.__name__)                              # 'json'

# Импорт из произвольного файла
import importlib.util
spec = importlib.util.spec_from_file_location("m", "path/to/m.py")
m = importlib.util.module_from_spec(spec)
spec.loader.exec_module(m)
```

### Типичные ошибки

```python
# Плохо: изменяемый импорт в горячем цикле — import каждый раз лезет в sys.modules
for _ in range(1_000_000):
    import math       # медленно

# Хорошо: один импорт наверху файла
import math
for _ in range(1_000_000):
    math.sqrt(2)
```

Циклический импорт:

```python
# a.py: from b import B
# b.py: from a import A   -> ImportError / частично инициализированный модуль
# Решение: локальный импорт внутри функции или TYPE_CHECKING
```

## 7. `compile`, `exec`, `eval`

```python
code = compile("x = 1 + 2", "<string>", "exec")
ns = {}
exec(code, ns)
print(ns["x"])           # 3

print(eval("2 + 2"))     # 4
```

- `exec` — выполнить код (инструкции); `eval` — вычислить **выражение**.
- `compile(source, filename, mode)` — получить code object; `mode` бывает
  `"exec"`, `"eval"`, `"single"`.
- `eval`/`exec` с пользовательским вводом — **опасны** (RCE — выполнение
  произвольного кода на сервере).

```python
# ОПАСНО: пользователь может выполнить что угодно
eval(input("Введите выражение: "))   # введёт __import__('os').system('rm -rf /')

# Безопаснее: ast.literal_eval — только литералы
import ast
ast.literal_eval("[1, 2, {'a': 3}]")   # ок, без выполнения кода
```

| Функция | Что делает | Риск |
|---|---|---|
| `eval` | вычисляет выражение | высокий |
| `exec` | выполняет код | высокий |
| `ast.literal_eval` | только литералы | низкий |

> Типичная ошибка: использовать `eval` для парсинга JSON/чисел. Для этого есть
> `json.loads`, `int`, `float`, `ast.literal_eval`.

## 8. Альтернативные реализации

- **PyPy** — JIT, быстрее CPU-код, но C-расширения работают хуже.
- **Jython/IronPython** — JVM/.NET.
- **MicroPython** — микроконтроллеры.
- **GraalPy** — GraalVM.
- **Free-threaded CPython** (3.13+, PEP 703) — экспериментально без GIL.
- **Cython / mypyc / Nuitka** — компиляция Python в C/машинный код для скорости.

| Реализация | Платформа | GIL | Особенность |
|---|---|---|---|
| CPython | C | да | эталон |
| PyPy | RPython | да | JIT |
| Jython | JVM | нет | Java-интеграция |
| MicroPython | MCU | да | очень маленький |
| GraalPy | GraalVM | нет | JIT, polyglot |
| free-threaded CPython | C | нет | эксперимент (3.13+) |

### Про free-threaded CPython

PEP 703 добавляет сборку без GIL. Это позволяет настоящий параллелизм потоков,
но пока экспериментально и с оговорками по производительности однопоточного кода.
