# День 19 — Cookies, безопасность веба и API-адресация

> Цель: разобрать cookies, CORS/CSRF/XSS, TLS и структуру API-адресов.

---

## 1. Cookies

**Cookie** — небольшой фрагмент данных, который сервер отправляет клиенту, а браузер прикладывает к последующим запросам к тому же домену.

**Установка:** заголовок `Set-Cookie` в ответе; далее браузер шлёт `Cookie: name=value`.

**Атрибуты cookie:**
| Атрибут | Смысл |
|---|---|
| `Domain` | на какой домен отправлять |
| `Path` | для каких путей |
| `Expires` / `Max-Age` | срок жизни (иначе — сессионная) |
| `HttpOnly` | недоступна из JS (защита от XSS) |
| `Secure` | отправлять только по HTTPS |
| `SameSite` | `Strict`/`Lax`/`None` — защита от CSRF |

```
Set-Cookie: session_id=abc123; HttpOnly; Secure; SameSite=Lax; Max-Age=3600
```

**Cookies vs Web Storage:**
- Cookies автоматически уходят на сервер (и ограничены ~4 КБ).
- `localStorage`/`sessionStorage` живут в браузере, доступны только JS, не отправляются автоматически (токены часто хранят здесь, но это уязвимо к XSS).

---

## 2. HTTPS и TLS

- **HTTP** — открытый текст, порт **80**. **HTTPS** — HTTP поверх TLS, порт **443**.
- TLS обеспечивает: **шифрование** (конфиденциальность), **целостность**, **аутентификацию сервера** (сертификат от CA).
- Handshake: клиент и сервер договариваются о шифрах, проверяют сертификат, обмениваются ключами.
- Cookies с флагом `Secure` передаются только по HTTPS.

## 3. CORS (Cross-Origin Resource Sharing)

Механизм **браузера** (не атака!), управляющий кросс-доменными запросами.

- **Origin** = схема + хост + порт. Другой origin → кросс-доменный запрос.
- Для «сложных» запросов браузер шлёт предварительный **preflight** (`OPTIONS`) с `Access-Control-Request-Method`.
- Сервер отвечает заголовками `Access-Control-Allow-Origin`, `-Methods`, `-Headers`, `-Credentials`.

```python
# FastAPI
from fastapi.middleware.cors import CORSMiddleware
app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://example.com"],
    allow_methods=["*"],
    allow_headers=["*"],
    allow_credentials=True,
)
```

> CORS защищает **пользователя в браузере**, а не сервер от прямых запросов (curl их не блокирует).

## 4. CSRF и XSS

**CSRF (Cross-Site Request Forgery):** злоумышленник заставляет браузер аутентифицированного пользователя отправить нежелательный запрос.
Защита: CSRF-токены, `SameSite` cookies, проверка `Origin`/`Referer`.

**XSS (Cross-Site Scripting):** внедрение чужого JS на страницу.
Защита: экранирование пользовательских данных, CSP (Content-Security-Policy), `HttpOnly` cookies.

**SQL-инъекции:** не склеивать SQL со строками; использовать параметризованные запросы (или ORM).

## 5. Анатомия URL / API-адреса

```
https://api.example.com:443/v1/users/42?active=true&limit=10#section
└┬─┘   └──────┬───────┘└┬┘└┬┘└───┬───┘└─────────┬────────┘└──┬──┘
scheme       host      port path           query          fragment
```

- **scheme** — `http`/`https`.
- **host** — домен (с поддоменом, часто `api.`).
- **port** — 80/443 по умолчанию (можно опускать).
- **path** — ресурс, `/users/42`.
- **query** — параметры `?key=value&...`.
- **fragment** — якорь, на сервер не отправляется.

**Path-параметры** (`/users/{id}`) — идентификация ресурса.
**Query-параметры** (`?limit=10&sort=desc`) — фильтрация, сортировка, пагинация.

---

## 6. Проектирование API

- **Версионирование:** `/v1/users` или заголовок `Accept: application/vnd.api+json;version=1`.
- **Пагинация:** `?limit=20&offset=40` (offset) или `?page=3&size=20`, либо cursor-based (`?after=...`).
- **Фильтрация/сортировка:** `?status=active&sort=-created_at`.
- **Множественные параметры:** `?ids=1,2,3` или `?id=1&id=2`.
- **Rate limiting:** заголовки `X-RateLimit-Limit/Remaining/Reset`, ответ `429 Too Many Requests`.
- **HATEOAS:** ссылки на связанные ресурсы в ответе (высший уровень зрелости REST).
