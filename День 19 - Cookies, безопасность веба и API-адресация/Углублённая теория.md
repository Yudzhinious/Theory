# День 19 — Углублённая теория: безопасность веба и API

Дополнение к `Теория.md`.

## 1. Cookies глубоко (RFC 6265)

- **SameSite:** `Strict` (не отправлять при кросс-сайте), `Lax` (GET-навигация), `None` (нужен `Secure`).
- **Префиксы:** `__Secure-` (требует `Secure`), `__Host-` (требует `Secure`, без `Domain`, `Path=/`).
- **Third-party cookies** — блокируются современными браузерами.
- **Session fixation** — атака подмены session id; защита — смена id после логина.
- Храни только идентификатор сессии, не чувствительные данные.

---

## 2. TLS / HTTPS глубоко

- **Handshake:** согласование версии/шифров, обмен ключами (ECDHE — forward secrecy), проверка сертификата.
- **Сертификат** подписан CA; цепочка доверия; **SNI** — выбор сертификата по домену.
- **HSTS** — заголовок, заставляющий браузер использовать только HTTPS.
- **Certificate pinning** — привязка к конкретному сертификату (мобильные приложения).

---

## 3. Аутентификация/авторизация глубоко

- **JWT-атаки:** `alg=none`, подмена HS256/RS256, отсутствие проверки `exp`/`iss`/`aud`, слабый секрет.
- **Refresh token rotation** + reuse detection.
- **Scopes/roles** — авторизация на уровне прав (`RBAC`/`ABAC`).
- **Session vs JWT:** сессии легко отозвать, JWT — stateless; часто комбинируют.

## 5. CORS глубоко

- **Simple request** (GET/POST с простыми заголовками) vs **preflight** (`OPTIONS`) для «сложных».
- `Access-Control-Allow-Credentials: true` несовместим с `Allow-Origin: *`.
- **Preflight cache** через `Access-Control-Max-Age`.
- CORS — защита браузера; **не** защита сервера.

---

## 6. CSRF и XSS глубоко

- **CSRF-защита:** synchronizer token, double-submit cookie, `SameSite`, проверка `Origin`.
- **XSS типы:** reflected, stored, DOM-based. Защита: экранирование вывода, **CSP**, `HttpOnly`, sanitization.
- **Clickjacking:** `X-Frame-Options: DENY`, `frame-ancestors` в CSP.
- **Security headers:** `Content-Security-Policy`, `Strict-Transport-Security`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`.

---

## 7. API-безопасность

- **API keys** — для сервисов; **OAuth** — для пользователей.
- **Rate limiting** и квоты; `429`.
- **Idempotency-Key** для безопасных повторов.
- **Mass assignment** — валидируй входные схемы (Pydantic), не принимай «всё поле».
- **BOLA/BFLA** — проверяй, что пользователь имеет доступ к **конкретному** объекту/функции.

## 8. Дизайн API: сравнение

| | REST | GraphQL | gRPC |
|---|---|---|---|
| Формат | JSON/HTTP | JSON/HTTP | Protobuf/HTTP2 |
| Гибкость | фикс. эндпоинты | клиент выбирает поля | строгие контракты |
| Стриминг | ограничен | subscriptions | да (bidirectional) |
| Лучше для | публичные API | гибкий фронт | сервис-сервис |

- **Webhooks** — push-уведомления; подпись запроса (HMAC) для доверия.
- **Пагинация cursor-based** стабильнее offset при частых изменениях.
- **URL encoding:** пробелы/спецсимволы (`%20`, `+`), защита от path traversal (`../`).
