# День 17 — Модули, пакеты, окружения, метаданные

> Цель: понимать импорты, `__name__ == "__main__"`, виртуальные окружения и интроспекцию.

---

## 1. Модуль и пакет

- **Модуль** — файл `.py`.
- **Пакет** — каталог с `__init__.py`, объединяющий модули в иерархию.

```text
myapp/
├── __init__.py
├── models.py
└── services/
    ├── __init__.py
    └── user.py
```

`__init__.py` может быть пустым (помечает пакет) или содержать инициализацию/реэкспорт.

---

## 2. Импорты

```python
import math                       # импорт модуля
from math import sqrt             # импорт имени
from math import sqrt as s        # с псевдонимом
from myapp.services.user import get_user
```

- **Абсолютный импорт** — от корня проекта (предпочтительно).
- **Относительный** — внутри пакета: `from . import user`, `from .. import models`.
  - `.` — текущий пакет, `..` — родительский.
  - Не работает при запуске файла напрямую; нужно `python -m myapp.services.user`.

---

## 3. Поиск модулей: `sys.path` и `sys.modules`

Порядок поиска:
1. Кэш уже импортированных модулей — `sys.modules`.
2. Встроенные модули (`sys`, `os`).
3. Каталоги из `sys.path`: каталог скрипта → `PYTHONPATH` → site-packages.

```python
import sys
print(sys.path)
sys.path.append("/my/path")       # временное добавление
```

Повторный `import` берёт модуль из `sys.modules`, не перезагружая. Принудительно — `importlib.reload(mod)`.

**Циклический импорт** (`A` импортирует `B`, `B` — `A`) вызывает ошибки. Решения: вынести общий код в третий модуль или делать ленивый импорт внутри функции.

## 4. `if __name__ == "__main__"`

При прямом запуске файла `__name__ == "__main__"`; при импорте — имя модуля.

```python
def main():
    print("запуск")

if __name__ == "__main__":     # только при прямом запуске
    main()
```

Это позволяет использовать файл и как скрипт, и как библиотеку без побочных эффектов при импорте.

## 5. Метаданные и интроспекция

| Атрибут | Что хранит |
|---|---|
| `__name__` | имя модуля/класса/функции (`"__main__"` для точки входа) |
| `__file__` | путь к файлу модуля |
| `__doc__` | docstring |
| `__dict__` | пространство имён (атрибуты) |
| `__annotations__` | аннотации типов |
| `__module__` | имя модуля, где определён объект |
| `__qualname__` | полное имя (для вложенных) |
| `__bases__` / `__mro__` | родители / порядок разрешения методов |
| `__closure__` | захваченные переменные замыкания |
| `__code__` | байт-код функции |

```python
import inspect
inspect.signature(some_func)     # сигнатура функции
inspect.getmembers(obj)          # все атрибуты
dir(module)                      # список имён
```

**Зачем:** фреймворки (Pydantic читает `__annotations__`, декораторы используют `functools.wraps`), сериализация (`__dict__` → JSON), отладка.

## 6. Виртуальные окружения и зависимости

- **venv** — изолированное окружение с собственным интерпретатором и пакетами.

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate

pip install fastapi
pip freeze > requirements.txt
pip install -r requirements.txt
```

- **pip** — менеджер пакетов (PyPI).
- **requirements.txt** — список зависимостей.
- **pyproject.toml** — современный стандарт метаданных проекта и зависимостей (PEP 517/518).
