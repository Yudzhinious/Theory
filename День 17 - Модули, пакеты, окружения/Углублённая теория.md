## 1. Как реально работает `import`

1. Проверка `sys.modules` (кэш).
2. Поиск через **finders** в `sys.meta_path`.
3. Создание **spec** (module spec) и загрузка **loader**.
4. Исполнение модуля в его namespace.
5. Сохранение в `sys.modules`.

```python
import importlib, sys
mod = importlib.import_module("math")
sys.modules["math"] is mod    # True
```

- `importlib.util.spec_from_file_location` — импорт из произвольного файла.
- **Import hooks** (`MetaPathFinder`) позволяют кастомные источники (zip, БД, сеть).

## 2. Пакеты и `__init__.py`

- Обычный пакет — каталог с `__init__.py`.
- **Namespace packages** (PEP 420) — без `__init__.py`, могут объединять части из разных мест.
- `__all__` в модуле/пакете управляет `from pkg import *`.
- Реэкспорт в `__init__.py` для удобного API:

```python
# mypkg/__init__.py
from .models import User
from .services import create_user
__all__ = ["User", "create_user"]
```

## 3. Циклические импорты

- A импортирует B, B импортирует A → частично инициализированные модули.
- Решения: вынести общий код в третий модуль; **ленивый импорт** внутри функции; импорт по `TYPE_CHECKING` для типов.

```python
def handler():
    from .heavy import do_work   # ленивый импорт
    return do_work()
```

## 4. Метаданные пакета

```python
from importlib.metadata import version, entry_points
version("fastapi")
entry_points(group="console_scripts")
```

- **Entry points** — точки входа CLI/плагинов (`[project.scripts]`).
- `importlib.resources` — доступ к файлам внутри пакета (шаблоны, данные).

## 5. Упаковка: wheel, sdist, pyproject

- **sdist** (`.tar.gz`) — исходники; **wheel** (`.whl`) — собранный дистрибутив.
- `pyproject.toml` (PEP 518/621) — стандарт метаданных и сборки.

```toml
[build-system]
requires = ["setuptools>=68"]
build-backend = "setuptools.build_meta"

[project]
name = "myapp"
version = "0.1.0"
dependencies = ["fastapi", "sqlalchemy>=2"]
```

```bash
python -m build        # создаёт sdist + wheel
```

## 6. Менеджеры зависимостей и lock-файлы

| Инструмент | Особенность |
|---|---|
| `pip` + `requirements.txt` | базовый |
| `poetry` | зависимости + сборка + lock |
| `pipenv` | Pipfile + lock |
| `uv` | очень быстрый (Rust), замена pip/venv |
| `conda` | научный стек, свои пакеты |

- **Lock-файл** фиксирует точные версии всех транзитивных зависимостей → воспроизводимость.
- **Разрешение зависимостей** — поиск совместимых версий; конфликты версий — частая боль.

## 7. Виртуальные окружения

- `venv` создаёт изолированный `site-packages` и копию/ссылку на интерпретатор.
- `sys.prefix` отличается в venv; активация меняет `PATH`.
- `site`-модуль добавляет `site-packages`; `.pth`-файлы расширяют пути.

```bash
python -m venv .venv
.venv\Scripts\activate      # Windows
python -m pip install -U pip
```

## 8. Интроспекция

```python
import inspect
inspect.signature(func)
inspect.getmembers(obj)
inspect.getsource(func)
vars(obj)          # __dict__
dir(obj)           # все имена
getattr(obj, "x", default)
```

`inspect` используется декораторами, фреймворками, автодокументацией.
