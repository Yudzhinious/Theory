# День 14 — Вопросы

Финальный день. Ответь на всё без подглядывания — это твой mock-экзамен.

---

**1. Опиши путь изменения в git: от файла до удалённого репозитория.**
<details><summary>Ответ</summary>
Working directory → `git add` → staging area → `git commit` → local repo → `git push` → remote.
</details>

**2. `git merge` vs `git rebase`?**
<details><summary>Ответ</summary>
merge создаёт merge-коммит и сохраняет историю ветвления; rebase переносит коммиты, делая историю линейной, но переписывает её (нельзя на публичных ветках).
</details>

**3. `git reset --soft/mixed/hard`?**
<details><summary>Ответ</summary>
soft — отменяет коммит, изменения остаются в staging; mixed (по умолчанию) — изменения в рабочем каталоге; hard — удаляет коммит и изменения безвозвратно.
</details>

**4. Зачем `git revert` вместо `reset` на публичной ветке?**
<details><summary>Ответ</summary>
`revert` создаёт новый коммит, отменяющий изменения, не переписывая историю — безопасно для общей ветки.
</details>

**5. Что такое unit-тест и чем отличается от интеграционного?**
<details><summary>Ответ</summary>
Unit проверяет изолированную единицу (функцию/класс). Интеграционный проверяет взаимодействие нескольких компонентов (например, приложение + БД).
</details>

**6. Как тестировать код с внешними зависимостями?**
<details><summary>Ответ</summary>
Через моки (`unittest.mock`, `pytest-mock`) — подменять обращения к БД/сети, проверяя логику изолированно.
</details>

**7. Что такое чистая архитектура?**
<details><summary>Ответ</summary>
Подход, при котором бизнес-логика не зависит от фреймворков, БД и UI; зависимости направлены внутрь, к домену (порты и адаптеры, DIP).
</details>

**8. Что такое PEP 8 и зачем линтеры?**
<details><summary>Ответ</summary>
PEP 8 — стандарт оформления кода Python. Линтеры/форматтеры (ruff, black, isort) автоматически следят за стилем и ошибками.
</details>

**9. Императивный vs декларативный подход?**
<details><summary>Ответ</summary>
Императивный описывает «как» делать (пошагово), декларативный — «что» нужно получить (например, SQL, comprehension).
</details>

**10. Что должен включать хороший pet-проект для стажировки?**
<details><summary>Ответ</summary>
FastAPI (или Django), БД с ORM и миграциями, аутентификация, тесты, Docker, README, git-история. Умение рассказать о сложностях и решениях.
</details>

## Блиц на 20 вопросов (из теории дня)

1. `is` vs `==` → идентичность vs значение.
2. Изменяемые типы → list/dict/set.
3. dict → хеш-таблица, O(1) средн.
4. Декоратор → обёртка функции, `@wraps`.
5. Генератор → ленивый, одноразовый, экономит память.
6. LEGB → Local→Enclosing→Global→Built-in.
7. MRO → C3-линеаризация; `super()` идёт по MRO.
8. SOLID → SRP, OCP, LSP, ISP, DIP.
9. GC → refcount + циклический GC + поколения.
10. GIL → один поток на байт-код; обход через multiprocessing.
11. threading (I/O) / multiprocessing (CPU) / asyncio (много I/O).
12. ACID + уровни изоляции.
13. Индексы → ускоряют поиск, замедляют запись.
14. Партиционирование (внутри) / шардирование (по серверам) / репликация (копии).
15. REST → stateless, ресурсы, методы, коды.
16. PUT (полная замена) vs PATCH (частичная).
17. Сессии (сервер) vs JWT (stateless).
18. WSGI (sync) vs ASGI (async, WebSocket).
19. Django (full-stack) vs FastAPI (API).
20. Docker: image — шаблон, container — экземпляр; контейнер легче VM.
