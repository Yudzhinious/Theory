## 1. Git изнутри

### Git как база объектов

Git хранит не «разницу между версиями», а **снимки** (snapshots) файлов.
Всё содержимое — это объекты четырёх типов:

- **blob** — содержимое файла (без имени!).
- **tree** — каталог: список пар «имя → blob/tree».
- **commit** — снимок: ссылка на tree, автор, сообщение, ссылка на родителя.
- **tag** — именованная ссылка на объект (обычно коммит).

```
commit ──> tree (корень)
             ├── blob  README.md
             └── tree  src/
                   └── blob main.py
```

- **Refs:** ветки и теги — указатели на коммиты; `HEAD` — текущая позиция
  (обычно ссылка на ветку).
- **Index (staging)** — промежуточный снимок, из которого делается коммит.
- Объекты **неизменяемы** и адресуются хешем (SHA-1, в новых репозиториях
  возможен SHA-256). **Packfiles** — сжатое хранение объектов.

### Полезные команды для «внутренностей»

```bash
git cat-file -p HEAD        # показать содержимое коммита
git cat-file -t HEAD        # тип объекта (commit)
git rev-parse HEAD          # полный хеш
git ls-tree HEAD            # дерево файлов коммита
git reflog                  # журнал перемещений HEAD (спасение после reset)
```

### Reflog — спасательный круг

Даже после `git reset --hard` коммит ещё живёт в reflog ~90 дней.

```bash
git reflog                       # находим потерянный хеш abc1234
git switch -c rescue abc1234     # создаём ветку на нём
```

> Типичная ошибка: паниковать после неудачного `reset`. Сначала `git reflog`.

## 2. Рабочие процессы

| Модель | Суть | Когда |
|---|---|---|
| **Feature branch / GitHub Flow** | короткая ветка + PR | большинство команд |
| **Trunk-based** | частые мелкие мержи в main, feature flags | зрелый CI/CD |
| **GitFlow** | develop/release/hotfix | релизные циклы (сложнее) |

### Полезные инструменты

- **`git bisect`** — бинарный поиск коммита, сломавшего код.

```bash
git bisect start
git bisect bad                 # текущий — сломан
git bisect good v1.0           # v1.0 работал
# git сам переключает коммиты, вы отвечаете good/bad
git bisect good   # или git bisect bad
git bisect reset  # в конце
```

- **`git cherry-pick <hash>`** — перенести отдельный коммит в текущую ветку.
- **`git rebase -i HEAD~3`** — интерактивно: `squash` (склеить), `reword`
  (переписать сообщение), `drop` (удалить), `edit`.
- **`git stash`** — спрятать изменения (`stash pop` — вернуть).
- **Hooks** (`pre-commit`) — запуск проверок перед коммитом.

### Код-ревью через Pull Request

1. Ветка → push → открыть PR.
2. Описание: что и зачем.
3. CI-гейты: линт, тесты, сборка.
4. Ревьюеры оставляют комментарии.
5. Правки → approve → merge (squash/merge/rebase).

> Типичная ошибка: огромный PR на 2000 строк. Ревьюер не может его осмыслить.
> Дробите на маленькие PR.

## 3. Тестирование глубоко

### Пирамида тестов

```
        /\        e2e        (мало, медленно)
       /  \
      /____\      integration (средне)
     /      \
    /________\    unit        (много, быстро)
```

### Фикстуры pytest

**Фикстура** — подготовка состояния (клиент, БД, тестовые данные), которая
переиспользуется в тестах.

```python
import pytest

@pytest.fixture
def client():
    return make_client()

@pytest.fixture
def user(client):
    return client.create_user("alice")   # фикстуры могут зависеть от фикстур

def test_profile(client, user):
    assert client.get(f"/users/{user.id}").status_code == 200
```

Области видимости фикстур: `function` (по умолчанию), `class`, `module`,
`package`, `session`. Чем шире — тем быстрее, но выше риск «загрязнения».

```python
@pytest.fixture(scope="session")
def db_engine():
    engine = create_engine(TEST_DB_URL)
    yield engine
    engine.dispose()
```

**`conftest.py`** — файл, где pytest автоматически ищет общие фикстуры (не нужно
импортировать).

### Параметризация и маркеры

```python
@pytest.mark.parametrize("a,b,expected", [(1, 1, 2), (2, 3, 5)])
def test_add(a, b, expected):
    assert a + b == expected

@pytest.mark.slow                       # свой маркер
def test_heavy(): ...

def test_raises():
    with pytest.raises(ValueError):
        int("x")
```

Запуск: `pytest -m "not slow"` — пропустить медленные.

### Моки

```python
from unittest.mock import patch, MagicMock

# patch подменяет атрибут на время теста
@patch("myapp.send_email")
def test_signup(mock_send):
    signup("a@b.com")
    mock_send.assert_called_once_with("a@b.com")

# MagicMock умеет всё: вызывает, индексируется, итерируется
m = MagicMock()
m.foo().bar.return_value = 42
assert m.foo().bar() == 42
```

Полезные утверждения: `assert_called_once_with`, `assert_not_called`,
`mock.call_args`, `mock.side_effect = ValueError` (сымитировать ошибку).

### Monkeypatch

```python
def test_env(monkeypatch):
    monkeypatch.setenv("DEBUG", "1")     # временно меняем окружение
    monkeypatch.setattr("myapp.TIMEOUT", 1)
    # после теста всё откатится автоматически
```

### Coverage и TDD

- **Coverage** (`pytest --cov`) — доля выполненного кода. 100% ≠ отсутствие
  багов, но помогает найти непротестированные ветки.
- **TDD** — red → green → refactor: сначала падающий тест, потом код, потом
  улучшение.
- **Фабрики данных** (`factory_boy`), транзакционные тесты (откат после каждого).

> Типичная ошибка: тестировать мок вместо реального поведения. Мок проверяет
> «как вызвали», а не «правильно ли работает».

## 4. Отладка и профилирование

### pdb команды

| Команда | Действие |
|---|---|
| `n` (next) | следующая строка |
| `s` (step) | войти в вызов |
| `c` (continue) | продолжить до breakpoint |
| `p`/`pp` | напечатать значение |
| `l` (list) | показать исходник |
| `w` (where) | стек вызовов |
| `b` (break) | поставить точку останова |
| `q` (quit) | выйти |

### Логирование

- `logging` с уровнями DEBUG/INFO/WARNING/ERROR/CRITICAL.
- **Structured logs** (JSON) удобно парсить в ELK/Loki.
- **Correlation id** — идентификатор запроса, чтобы связать логи разных сервисов.

```python
import logging
logger = logging.getLogger(__name__)
logger.info("user=%s action=login", user_id)   # structured-подобный формат
```

### Профилирование

| Инструмент | Что показывает |
|---|---|
| `timeit` | время маленького куска кода |
| `cProfile` + `pstats` | вызовы и время по функциям |
| `py-spy` | сэмплирующий профилировщик, для прода |
| `line_profiler` | время по строкам |
| `memory_profiler` | потребление памяти |

```python
import cProfile
cProfile.run("heavy()")

# или
import pstats, cProfile
cProfile.run("heavy()", "out.prof")
pstats.Stats("out.prof").sort_stats("cumulative").print_stats(10)
```

> Важно: «преждевременная оптимизация — корень всех зол» (Кнут). Сначала
> измерьте, потом оптимизируйте.

## 5. Архитектура

### Layered (слои)

```
presentation → application → domain → infrastructure
```

Каждый слой знает только о соседнем «внутреннем». Внешние слои зависят от
внутренних, не наоборот.

### Clean Architecture / Hexagonal

**Зависимости направлены внутрь**; домен не знает о фреймворках и БД. Связь —
через интерфейсы (**порты**), реализуемые **адаптерами**.

```python
# Порт (интерфейс) в домене
from typing import Protocol

class UserRepository(Protocol):
    def get(self, id: int) -> "User": ...

# Адаптер (инфраструктура)
class SqlUserRepository:
    def get(self, id):
        return self.session.get(UserModel, id)
```

### DDD (базово)

- **Сущность (Entity)** — объект с идентичностью (пользователь с id).
- **Value Object** — неизменяемое значение без идентичности (деньги, email).
- **Агрегат** — группа объектов с корнем (Order + OrderLines).
- **Репозиторий** — доступ к агрегатам.
- **Ubiquitous language** — единый язык бизнеса и кода.

### Dependency Rule

Внутренние слои не зависят от внешних. Это частный случай **DIP** из SOLID:
зависим от абстракций, не от реализаций.

### 12-factor app

| Фактор | Смысл |
|---|---|
| Конфиг в env | не хардкодить секреты |
| Stateless-процессы | легко масштабировать |
| Логи в stdout | сбор централизованно |
| Паритет сред | dev/prod похожи |
| Dependencies явно | requirements/lock |

> Типичная ошибка: домен импортирует `fastapi`/`sqlalchemy`. Тогда бизнес-логику
> нельзя протестировать без инфраструктуры, а смена фреймворка ломает всё.

## 6. Качество кода

- **PEP 8** — стандарт оформления.
- **ruff** (линт + формат), **black** (формат), **isort** (импорты),
  **mypy** (типы).
- **pre-commit** — автоматический прогон перед коммитом.

```yaml
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.4.0
    hooks:
      - id: ruff
      - id: ruff-format
```

Принципы: **DRY** (не повторяйся), **KISS** (проще), **YAGNI** (не пиши то,
что не нужно сейчас), осмысленные имена, маленькие функции.

| Принцип | Антипример |
|---|---|
| DRY | копипаста одной логики в 5 местах |
| KISS | «умный» однострочник вместо читаемого кода |
| YAGNI | абстракция «на будущее», которая не используется |
