## 1. Git изнутри

- Объекты: **blob** (содержимое файла), **tree** (каталог), **commit** (снимок + ссылка на родителя), **tag**.
- **Refs:** ветки и теги — указатели на коммиты; `HEAD` — текущая позиция.
- **Index (staging)** — промежуточный снимок.
- Объекты неизменяемы и адресуются хешем (SHA-1/SHA-256). **Packfiles** — сжатие.

```bash
git cat-file -p HEAD        # содержимое коммита
git rev-parse HEAD          # хеш
git reflog                  # журнал перемещений HEAD (спасение)
```

## 2. Рабочие процессы

- **Feature branch / GitHub Flow** — короткие ветки + PR.
- **Trunk-based** — частые мелкие мержи в main, feature flags.
- **GitFlow** — develop/release/hotfix (сложнее, для релизных циклов).
- Код-ревью через **Pull Request**: описание, тесты, ревьюеры, CI-гейты.

Полезное: `git bisect` (бинарный поиск бага), `git cherry-pick`, интерактивный `rebase -i` (squash/reword), `git stash`, hooks (pre-commit).

## 3. Тестирование глубоко

- **Пирамида тестов:** много unit, меньше integration, мало e2e.
- **pytest:** фикстуры (`@pytest.fixture`), `conftest.py`, параметризация, маркеры, `monkeypatch`.
- **Моки:** `unittest.mock.patch`, `MagicMock`; изолируй внешние зависимости (сеть, БД).
- **Coverage** (`pytest --cov`), **TDD** (red-green-refactor).
- **Фабрики данных** (factory_boy), фикстуры БД, транзакционные тесты.

```python
import pytest

@pytest.fixture
def client():
    return make_client()

@pytest.mark.parametrize("a,b,expected", [(1, 1, 2), (2, 3, 5)])
def test_add(a, b, expected):
    assert a + b == expected

def test_raises():
    with pytest.raises(ValueError):
        int("x")
```

## 4. Отладка и профилирование

- **pdb:** `breakpoint()`, команды `n` (next), `s` (step), `c` (continue), `p`/`pp` (печать), `l` (код), `q` (выход), `w` (stack).
- **Логирование** вместо print: `logging` с уровнями, structured logs (JSON), correlation id.
- **Профилирование:** `cProfile` + `pstats`, `timeit`, `py-spy` (сэмплирующий, для прода), `line_profiler`, `memory_profiler`.

```python
import cProfile
cProfile.run("heavy()")
```

## 5. Архитектура

- **Layered (слои):** presentation → application → domain → infrastructure.
- **Clean Architecture / Hexagonal (Ports & Adapters):** зависимости направлены **внутрь**; домен не знает о фреймворках и БД.
- **DDD (базово):** сущности, value objects, агрегаты, репозитории, ubiquitous language.
- **Dependency Rule:** внутренние слои не зависят от внешних; связь — через интерфейсы (порты).
- **12-factor app:** конфиг в env, stateless, логи в stdout, паритет сред.

```python
# Порт (интерфейс) в домене
class UserRepository(Protocol):
    def get(self, id: int) -> User: ...

# Адаптер (инфраструктура)
class SqlUserRepository:
    def get(self, id): ...
```
