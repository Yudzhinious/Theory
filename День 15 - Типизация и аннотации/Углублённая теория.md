## 1. Вариативность (variance)

Вариативность отвечает на вопрос: **можно ли подставить контейнер с более узким
типом туда, где ждут контейнер с широким**.

- **Ковариантность** — `Sequence[Dog]` можно использовать как `Sequence[Animal]`
  (только чтение). Порядок типов сохраняется.
- **Контравариантность** — аргументы функций; направление обратное.
- **Инвариантность** — `list` изменяемый → `list[Dog]` **не** является
  `list[Animal]`.

```python
from typing import Sequence, Callable

class Animal: ...
class Dog(Animal): ...

def feed(animals: Sequence[Animal]) -> None: ...
feed([Dog()])          # ок: Sequence ковариантен (только читаем)

def handle(f: Callable[[Animal], None]) -> None: ...
def take_dog(d: Dog) -> None: ...
# handle(take_dog)    # ошибка mypy: Callable контравариантен по аргументу
```

Почему `list` инвариантен? Потому что его можно **менять**:

```python
xs: list[Animal] = [Dog()]
xs.append(Cat())       # теперь там кот — если бы list[Dog] подошёл, была бы дыра
```

Аналогия: корзина с надписью «фрукты» (Sequence) — можно положить яблоко.
Коробка «яблоки» (list) — туда нельзя класть грушу, поэтому она не «коробка
фруктов», хотя яблоки и фрукты.

| Тип | Вариативность |
|---|---|
| `Sequence`, `Iterable`, `Mapping` | ковариантен по значению |
| `Callable` | контравариантен по аргументам, ковариантен по возврату |
| `list`, `dict`, `set` | инвариантен |
| `TypeVar(covariant=True)` | объявляете сами |

```python
from typing import TypeVar
T_co = TypeVar("T_co", covariant=True)      # для «производителей»
T_contra = TypeVar("T_contra", contravariant=True)  # для «потребителей»
```

## 2. Продвинутые конструкции `typing`

| Конструкция | Назначение |
|---|---|
| `ParamSpec` | типизация декораторов (сохраняет сигнатуру) |
| `Concatenate` | добавляет аргумент к `ParamSpec` |
| `@overload` | несколько сигнатур для одной функции |
| `Annotated[T, meta]` | тип + метаданные (валидация, DI) |
| `Self` | возвращаемый тип = текущий класс |
| `Never` / `NoReturn` | функция не возвращает управление |
| `TypeGuard` | сужение типа |
| `TypedDict` + `NotRequired`/`Required` | частичные словари |
| `Protocol` + `TypeVar` | дженерик-протоколы |

### `@overload` — разные сигнатуры

```python
from typing import overload

@overload
def parse(x: int) -> int: ...
@overload
def parse(x: str) -> str: ...
def parse(x):                 # реальная реализация (без аннотаций или с Any)
    return x

reveal_type(parse(1))         # int
reveal_type(parse("a"))       # str
```

### `Annotated` — тип + метаданные

```python
from typing import Annotated
from pydantic import Field

UserId = Annotated[int, "pk"]

# В FastAPI метаданные задают ограничения и документацию
def get_user(user_id: Annotated[int, Field(gt=0)]): ...
```

### `Self` — fluent-интерфейс

```python
from typing import Self

class Builder:
    def add(self, x: int) -> Self:
        return self            # возвращает тип наследника, а не Builder
```

### `ParamSpec` — типизация декораторов

Без `ParamSpec` обёртка теряет сигнатуру (mypy видит `*args, **kwargs`).

```python
from typing import ParamSpec, TypeVar, Callable
P, R = ParamSpec("P"), TypeVar("R")

def logged(f: Callable[P, R]) -> Callable[P, R]:
    def wrapper(*a: P.args, **k: P.kwargs) -> R:
        print("call")
        return f(*a, **k)
    return wrapper

@logged
def add(a: int, b: int) -> int:
    return a + b

add(1, 2)        # mypy знает сигнатуру (int, int) -> int
```

### `TypeGuard` — сужение типа

```python
from typing import TypeGuard

def is_str_list(xs: list[object]) -> TypeGuard[list[str]]:
    return all(isinstance(x, str) for x in xs)

xs: list[object] = ["a", "b"]
if is_str_list(xs):
    reveal_type(xs)     # list[str]
```

### `Never` / `NoReturn`

```python
from typing import NoReturn

def fail(msg: str) -> NoReturn:
    raise RuntimeError(msg)      # управление не вернётся
```

## 3. Forward references и `TYPE_CHECKING`

Иногда тип ещё не определён (класс ссылается на себя) или импорт тяжёлый/циклический.

```python
from __future__ import annotations   # отложенные аннотации (строки)

class Node:
    def __init__(self, next: Node | None = None):  # работает благодаря future-импорту
        self.next = next
```

Без `from __future__ import annotations` пришлось бы писать `"Node"` в кавычках
(строка — forward reference).

`TYPE_CHECKING` — импорт только для анализатора, не в рантайме:

```python
from typing import TYPE_CHECKING
if TYPE_CHECKING:
    from expensive import Heavy     # mypy видит, интерпретатор — нет

def process(x: "Heavy") -> None: ...
```

### Зачем `from __future__ import annotations`

- Позволяет писать `list[int]` даже на старых версиях.
- Ускоряет импорт (аннотации не вычисляются).
- Но: библиотеки, читающие типы в рантайме (Pydantic), должны уметь их
  разворачивать (`get_type_hints`). Pydantic v2 это делает.

## 4. `dataclasses` глубоко

```python
from dataclasses import dataclass, field, InitVar

@dataclass(slots=True, frozen=True)
class Point:
    x: int
    y: int = 0
    tags: list[str] = field(default_factory=list)
    raw: InitVar[str] = ""

    def __post_init__(self, raw):
        print("raw передан, но не сохранён:", raw)
```

- `slots=True` (3.10+) — экономия памяти (нет `__dict__`).
- `frozen=True` — неизменяемость + `__hash__` (можно класть в set).
- `InitVar` — параметр только для `__post_init__`, не поле.
- `field(compare=False)` — исключить поле из сравнения.
- Наследование: поля с дефолтами должны идти **после** полей без дефолтов.

```python
# Правильное наследование
@dataclass
class Base:
    x: int

@dataclass
class Derived(Base):
    y: int = 0     # дефолт после обязательного поля — ок
```

### `slots=True` — что это даёт

| | Без slots | Со slots |
|---|---|---|
| Память на объект | выше (`__dict__`) | ниже |
| Скорость доступа | быстрее/сопоставимо | обычно быстрее |
| Новые атрибуты | можно добавить | нельзя |

## 5. Pydantic vs dataclass vs attrs

| | dataclass | attrs | Pydantic |
|---|---|---|---|
| Валидация | нет | опц. | да |
| Парсинг/сериализация | нет | частично | да |
| Скорость | высокая | высокая | v2 быстрая (Rust) |
| Рантайм-проверки | нет | нет | да |
| JSON-схема | нет | нет | да |
| Когда | внутренние DTO | гибкие модели | вход/выход API |

Правило выбора:

- Внутренняя структура без внешних данных → **dataclass**.
- Данные из API/файла/env, которые надо валидировать → **Pydantic**.
- Нужны конвертеры/валидаторы и производительность → **attrs**.

## 6. mypy и строгий режим

```ini
# mypy.ini
[mypy]
strict = True
warn_unused_ignores = True
disallow_untyped_defs = True
warn_return_any = True
no_implicit_optional = True
```

- `# type: ignore[code]` — точечно подавить конкретную ошибку (с кодом!).
- **Stubs** (`.pyi`) для неаннотированных библиотек.
- **`py.typed`** — маркер в пакете, что он поставляет типы.
- `reveal_type(x)` — показать выведенный тип (для отладки типов).

```python
x = [1, 2, 3]
reveal_type(x)     # note: Revealed type is "builtins.list[builtins.int]"
```

### Почему строгий режим

| Настройка | Что ловит |
|---|---|
| `disallow_untyped_defs` | функции без аннотаций |
| `warn_return_any` | неявный `Any` в возврате |
| `no_implicit_optional` | `x: int = None` без `Optional` |
| `strict` | включает всё выше |

> Типичная ошибка: `# type: ignore` без кода. Через полгода непонятно, что
> именно игнорировалось. Пишите `# type: ignore[arg-type]`.

## 7. Где типы работают в рантайме

- **Pydantic/FastAPI** читают `__annotations__` для валидации/OpenAPI.
- **`typing.get_type_hints(func)`** — получить разрешённые типы (с учётом
  forward references).
- `Annotated` + метаданные используют DI-фреймворки.
- `@runtime_checkable` Protocol — `isinstance` по наличию методов.

```python
from typing import get_type_hints

def f(x: int, y: "str") -> bool: ...

print(get_type_hints(f))
# {'x': <class 'int'>, 'y': <class 'str'>, 'return': <class 'bool'>}
```

```python
import typing

class HasLen(typing.Protocol):
    def __len__(self) -> int: ...

@typing.runtime_checkable
class HasLenRT(typing.Protocol):
    def __len__(self) -> int: ...

# isinstance(HasLenRT())  # можно; с обычным Protocol — нельзя
```
