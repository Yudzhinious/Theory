# День 15 — Типизация и аннотации

> Цель: уверенно использовать `typing`, объяснить, что такое `Protocol`, `Generic`, и зачем нужен статический анализ.

---

## 1. Зачем аннотации типов

Python остаётся динамическим, но **аннотации типов** документируют ожидаемые типы и проверяются статически (mypy/pyright). Они **не влияют** на выполнение (кроме библиотек вроде Pydantic/FastAPI, которые читают `__annotations__`).

```python
def greet(name: str, times: int = 1) -> str:
    return f"Hello, {name}! " * times

print(greet.__annotations__)
# {'name': <class 'str'>, 'times': <class 'int'>, 'return': <class 'str'>}
```

Аннотации хранятся в `__annotations__`. На собесе это частый вопрос.

## 2. Базовые конструкции `typing`

```python
from typing import Optional, Union, Any, Callable

def find(id: int) -> Optional[str]: ...      # str | None
def parse(x: Union[int, str]) -> int: ...     # int | str (Python 3.10+: x: int | str)
def apply(f: Callable[[int], int], x: int) -> int: ...
def log(data: Any) -> None: ...
```

- `Optional[T]` == `Union[T, None]`.
- `Any` — отключает проверку.
- `Callable[[арг...], возврат]` — тип функции.
- С Python 3.10 можно писать `int | str` вместо `Union`.

**Встроенные дженерики (3.9+):**
```python
def first(xs: list[int]) -> int: ...
def mapping() -> dict[str, list[tuple[int, str]]]: ...
```
Старый стиль: `List[int]`, `Dict[str, int]` из `typing`.

## 3. Специальные типы

```python
from typing import Literal, TypedDict, Final, ClassVar

def set_mode(mode: Literal["r", "w", "a"]) -> None: ...   # только эти значения

class Movie(TypedDict):
    title: str
    year: int

MAX: Final = 100          # константа
```

- `Literal[...]` — конкретные допустимые значения.
- `TypedDict` — «словарь с фиксированной схемой» (похоже на Pydantic-модель).
- `Final`, `ClassVar` — семантика неизменяемости/принадлежности классу.

## 4. Дженерики: `TypeVar`, `Generic`

Позволяют писать обобщённый код с сохранением типа.

```python
from typing import TypeVar, Generic

T = TypeVar("T")

def first(xs: list[T]) -> T:      # тип возврата = типу элементов
    return xs[0]

class Stack(Generic[T]):
    def __init__(self) -> None:
        self._items: list[T] = []
    def push(self, item: T) -> None:
        self._items.append(item)
    def pop(self) -> T:
        return self._items.pop()
```

`TypeVar` может быть ограничен: `T = TypeVar("T", int, float)`.

## 5. `Protocol` — структурная типизация

Протокол задаёт интерфейс **без наследования**: подходит любой объект с нужными методами (утиная типизация, проверяемая статически).

```python
from typing import Protocol

class Flyer(Protocol):
    def fly(self) -> str: ...

class Bird:
    def fly(self) -> str:
        return "лечу"

def launch(obj: Flyer) -> str:
    return obj.fly()

launch(Bird())     # OK — Bird структурно подходит, хотя не наследуется
```

Разница с ABC: `Protocol` не требует наследования, проверяется анализатором, а не в рантайме (если не `@runtime_checkable`).

## 6. `dataclasses` — короткие классы данных

Автоматически генерирует `__init__`, `__repr__`, `__eq__`.

```python
from dataclasses import dataclass, field

@dataclass
class Point:
    x: int
    y: int = 0
    tags: list[str] = field(default_factory=list)   # для изменяемых

p = Point(1, 2)
print(p)          # Point(x=1, y=2, tags=[])
```

- `frozen=True` — неизменяемый (`__hash__` тоже).
- `default_factory` — для изменяемых значений по умолчанию.

> `dataclass` vs `Pydantic`: dataclass не валидирует данные, Pydantic — валидирует и парсит.

## 7. Статический анализ

```bash
pip install mypy
mypy app.py
```

- **mypy / pyright** — проверяют типы без запуска.
- **Pydantic / FastAPI** — используют аннотации в рантайме для валидации и генерации OpenAPI.
- `# type: ignore` — подавить проверку в конкретной строке.

Аннотации не проверяются во время выполнения: `greet(123)` выполнится, если логика позволяет (если не Pydantic).
