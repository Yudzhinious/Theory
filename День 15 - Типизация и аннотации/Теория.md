## 1. Зачем аннотации типов

### Проблема динамической типизации

Python — динамический язык: тип переменной определяется во время выполнения.
Это гибко, но ошибки типов всплывают только в рантайме.

```python
def greet(name, times):
    return f"Hello, {name}! " * times

greet("Bob", "3")   # TypeError: can't multiply sequence by non-int — только в рантайме
```

Аннотации позволяют **поймать такие ошибки до запуска**, с помощью mypy/pyright.

### Что такое аннотации

**Аннотации типов** — синтаксис для указания ожидаемых типов. Они:

- документируют код;
- проверяются **статически** (mypy, pyright) до выполнения;
- **не влияют** на выполнение (кроме библиотек вроде Pydantic/FastAPI, которые
  читают `__annotations__`).

```python
def greet(name: str, times: int = 1) -> str:
    return f"Hello, {name}! " * times

print(greet.__annotations__)
# {'name': <class 'str'>, 'times': <class 'int'>, 'return': <class 'str'>}
```

Аннотации хранятся в `__annotations__`. На собесе это частый вопрос.

### Аналогия

Аннотации — как разметка на коробках при переезде: «хрупкое», «тяжёлое».
Сам груз от этого не меняется, но грузчику (анализатору) понятнее, как
обращаться.

### Как неправильно / как правильно

```python
# Плохо: тип есть только в комментарии — mypy не поможет
def add(a, b):
    # a: int, b: int -> int
    return a + b

# Хорошо: аннотации — mypy проверит вызовы
def add(a: int, b: int) -> int:
    return a + b
```

## 2. Базовые конструкции `typing`

```python
from typing import Optional, Union, Any, Callable

def find(id: int) -> Optional[str]: ...      # str | None
def parse(x: Union[int, str]) -> int: ...     # int | str (Python 3.10+: x: int | str)
def apply(f: Callable[[int], int], x: int) -> int: ...
def log(data: Any) -> None: ...
```

- `Optional[T]` == `Union[T, None]` — «T или None».
- `Any` — отключает проверку (тип «что угодно»).
- `Callable[[арг...], возврат]` — тип функции.
- С Python 3.10 можно писать `int | str` вместо `Union`.

### Что означает `-> None`

`-> None` значит «функция возвращает None» (используется ради побочных эффектов).
Это **не** то же, что отсутствие аннотации: отсутствие = «неизвестно».

### Встроенные дженерики (3.9+)

```python
def first(xs: list[int]) -> int: ...
def mapping() -> dict[str, list[tuple[int, str]]]: ...
```

Старый стиль: `List[int]`, `Dict[str, int]`, `Tuple[int, str]` из `typing`.
Современный (3.9+) — прямо встроенные типы: `list[int]`, `dict[str, int]`.

| Старый (`typing`) | Новый (3.9+) |
|---|---|
| `List[int]` | `list[int]` |
| `Dict[str, int]` | `dict[str, int]` |
| `Tuple[int, str]` | `tuple[int, str]` |
| `Set[int]` | `set[int]` |
| `Optional[int]` | `int \| None` (3.10+) |

### Типичные ошибки

```python
# Плохо: Callable без параметров принимает ЛЮБУЮ функцию — теряется проверка
from typing import Callable
def run(f: Callable): ...

# Хорошо: укажите сигнатуру
def run(f: Callable[[int], int]): ...
```

```python
# Ловушка: изменяемый аргумент по умолчанию
def add_item(item, box=[]):     # общий список на все вызовы!
    box.append(item)
    return box

add_item(1)   # [1]
add_item(2)   # [1, 2] — сюрприз!

# Правильно
def add_item(item, box=None):
    box = box if box is not None else []
    box.append(item)
    return box
```

## 3. Специальные типы

```python
from typing import Literal, TypedDict, Final, ClassVar

def set_mode(mode: Literal["r", "w", "a"]) -> None: ...   # только эти значения

class Movie(TypedDict):
    title: str
    year: int

MAX: Final = 100          # константа
```

- `Literal[...]` — конкретные допустимые значения (mypy поймает опечатку).
- `TypedDict` — «словарь с фиксированной схемой» (похоже на Pydantic-модель,
  но без валидации в рантайме).
- `Final` — переменную нельзя переприсваивать.
- `ClassVar` — атрибут принадлежит классу, а не экземпляру.

```python
class Config:
    debug: ClassVar[bool] = False    # не попадает в __init__, общий для класса
    name: str                        # атрибут экземпляра
```

### Literal vs Enum

| | `Literal` | `Enum` |
|---|---|---|
| Значения | строки/числа | полноценный тип |
| Рантайм | просто литералы | объекты класса |
| Проверка mypy | да | да |
| Методы/логика | нет | да |

## 4. Дженерики: `TypeVar`, `Generic`

### Зачем дженерики

Позволяют писать обобщённый код, **сохраняя связь типов**. Без них `first`
вернул бы `Any`, и mypy не помог бы.

```python
from typing import TypeVar, Generic

T = TypeVar("T")

def first(xs: list[T]) -> T:      # тип возврата = типу элементов
    return xs[0]

reveal_type(first([1, 2, 3]))     # mypy: int
reveal_type(first(["a", "b"]))    # mypy: str

class Stack(Generic[T]):
    def __init__(self) -> None:
        self._items: list[T] = []
    def push(self, item: T) -> None:
        self._items.append(item)
    def pop(self) -> T:
        return self._items.pop()

s = Stack[int]()      # явная параметризация
s.push(1)
```

`TypeVar` может быть **ограничен** или **связан**:

```python
T = TypeVar("T", int, float)          # только int или float
N = TypeVar("N", bound="Number")      # любой подкласс Number
```

| Форма | Значение |
|---|---|
| `TypeVar("T")` | любой тип |
| `TypeVar("T", int, float)` | ровно int или float |
| `TypeVar("N", bound=Number)` | Number или его подклассы |

## 5. `Protocol` — структурная типизация

Протокол задаёт интерфейс **без наследования**: подходит любой объект с нужными
методами (утиная типизация, проверяемая статически).

```python
from typing import Protocol

class Flyer(Protocol):
    def fly(self) -> str: ...

class Bird:
    def fly(self) -> str:
        return "лечу"

def launch(obj: Flyer) -> str:
    return obj.fly()

launch(Bird())     # OK — Bird структурно подходит, хотя не наследуется
```

Аналогия: чтобы работать «летающим», не нужно вступать в «клуб птиц». Достаточно
уметь летать. Protocol — это «клуб по умению», а не по родословной.

### Protocol vs ABC

| | `Protocol` | `ABC` |
|---|---|---|
| Требует наследования | нет | да |
| Проверка | статически (mypy) | в рантайме (`isinstance`) |
| Рантайм-isinstance | только `@runtime_checkable` | да |
| Когда | утиная типизация | явная иерархия |

```python
from typing import Protocol, runtime_checkable

@runtime_checkable
class Flyer(Protocol):
    def fly(self) -> str: ...

isinstance(Bird(), Flyer)   # True (проверяет наличие метода)
```

> Типичная ошибка: делать Protocol с `@runtime_checkable` и проверять через
> `isinstance` в горячем коде. Это медленно — лучше полагаться на mypy.

## 6. `dataclasses` — короткие классы данных

Автоматически генерирует `__init__`, `__repr__`, `__eq__`.

```python
from dataclasses import dataclass, field

@dataclass
class Point:
    x: int
    y: int = 0
    tags: list[str] = field(default_factory=list)   # для изменяемых

p = Point(1, 2)
print(p)          # Point(x=1, y=2, tags=[])
print(p == Point(1, 2))   # True
```

- `frozen=True` — неизменяемый (`__hash__` тоже генерируется).
- `default_factory` — для изменяемых значений по умолчанию.
- `order=True` — генерирует `<`, `<=`, `>`, `>=`.

```python
@dataclass(frozen=True)
class Money:
    amount: int
    currency: str
```

> `dataclass` vs `Pydantic`: dataclass не валидирует данные, Pydantic —
> валидирует и парсит.

### dataclass vs обычный класс

```python
# Обычный класс — много boilerplate
class Point:
    def __init__(self, x, y=0):
        self.x = x
        self.y = y
    def __repr__(self):
        return f"Point(x={self.x}, y={self.y})"
    def __eq__(self, other):
        return isinstance(other, Point) and (self.x, self.y) == (other.x, other.y)

# dataclass — то же самое автоматически
@dataclass
class Point:
    x: int
    y: int = 0
```

## 7. Статический анализ

```bash
pip install mypy
mypy app.py
```

- **mypy / pyright** — проверяют типы без запуска.
- **Pydantic / FastAPI** — используют аннотации в рантайме для валидации и
  генерации OpenAPI.
- `# type: ignore` — подавить проверку в конкретной строке.

```python
x: int = "hello"        # mypy: error: Incompatible types
x = 1                   # ок
```

Аннотации **не проверяются во время выполнения**: `greet(123)` выполнится, если
логика позволяет (если не Pydantic). Именно поэтому mypy запускают отдельно в CI.

### Где типы всё же работают в рантайме

| Инструмент | Как использует аннотации |
|---|---|
| Pydantic | валидация, парсинг, сериализация |
| FastAPI | валидация + OpenAPI-схема |
| `typing.get_type_hints` | получить типы функции |
| DI-фреймворки | `Annotated`-метаданные |

> Типичная ошибка: думать, что аннотации «защищают» код в рантайме. Нет — это
> инструмент разработчика и анализатора (плюс библиотек, которые их читают).

### Мини-итог

- Аннотации документируют и проверяются mypy, но не влияют на рантайм.
- `Optional`/`Union`/`Literal`/`TypedDict`/`Final` — базовый арсенал.
- `TypeVar`/`Generic` сохраняют связь типов в обобщённом коде.
- `Protocol` — структурная типизация без наследования.
- `dataclass` генерирует boilerplate; Pydantic добавляет валидацию.
