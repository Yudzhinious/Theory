## 1. `list` — динамический массив

- Хранит **массив указателей** на объекты (сами объекты лежат отдельно).
- При `append` ёмкость растёт с запасом (~1.125x), поэтому `append` — **амортизированно O(1)**.
- Вставка/удаление в середине/начале — O(n) (сдвиг указателей).
- `sys.getsizeof(lst)` считает только массив ссылок, не сами объекты.

```python
import sys
sys.getsizeof([])          # ~56 байт
sys.getsizeof([0]*1000)    # ~8056 байт (только указатели)
```

### Что такое «амортизированно O(1)»

Обычно `append` просто кладёт указатель в свободную ячейку — O(1). Но иногда массив заполнен, и нужно:
1. выделить новый массив большего размера;
2. скопировать туда старые указатели (O(n));
3. добавить новый.

Такое «дорогое» расширение случается редко, поэтому в среднем на одну вставку приходится O(1).

```python
import sys

lst = []
prev = sys.getsizeof(lst)
for i in range(20):
    lst.append(i)
    size = sys.getsizeof(lst)
    if size != prev:
        print(f"после {i+1} элементов: размер {size}")
        prev = size
```

Вывод покажет, что размер меняется не каждый раз, а «ступеньками» — это и есть запас ёмкости.

### Почему вставка в начало дорогая

```python
lst = [0, 1, 2, 3, 4]
lst.insert(0, -1)     # все указатели сдвигаются на одну позицию вправо → O(n)
```

При вставке в начало нужно сдвинуть **все** элементы, поэтому O(n). Для частых операций с началом используй `deque`.

### Сравнение list и array

| | `list` | `array.array` |
|---|---|---|
| Что хранит | указатели на любые объекты | сырые числа одного типа |
| Память | больше | компактнее |
| Гибкость | любые типы | только числа |

### Мини-итог

`list` — массив ссылок с запасом ёмкости. Отсюда: `append` дёшев, `insert(0, ...)` дорог, `getsizeof` не учитывает объекты.

## 2. `dict` — хеш-таблица (compact dict, 3.6+)

- Начиная с Python 3.6, dict использует **компактное представление** и **сохраняет порядок вставки** (с 3.7 — гарантированно).
- Внутри — открытая адресация, коэффициент заполнения ~2/3, при превышении — resize.
- Средний доступ O(1), худший (много коллизий) — O(n).
- Ключи должны быть **хешируемыми**; при равных хешах сравниваются через `__eq__`.

```python
d = {"a": 1, "b": 2}
d["c"] = 3           # порядок вставки сохраняется
```

`dict` — рабочая лошадка Python: объекты (`__dict__`), модули, `sys.modules` — всё это словари.

### Как работает хеш-таблица

1. Для ключа вычисляется `hash(key)`.
2. Хеш превращается в индекс массива.
3. Если ячейка свободна — кладём. Если занята (коллизия) — ищем следующую.
4. При поиске: снова вычисляем индекс и идём по цепочке, сравнивая ключи через `==`.

```python
d = {"apple": 1, "banana": 2}
print(hash("apple"))    # большое число (меняется между запусками из-за рандомизации)
print(d["apple"])       # 1 — быстрый доступ по хешу
```

### Что такое коллизия

Два разных ключа могут получить одинаковый индекс. Тогда Python сравнивает их через `==`:

```python
# Псевдокод поиска
# idx = hash(key) % len(table)
# while table[idx] занят:
#     if table[idx].key == key: return value
#     idx = (idx + 1) % len(table)
```

Если хеши плохие и все ключи бьются в одну ячейку, поиск деградирует до O(n).

### Компактное представление

До 3.6 dict хранил «толстые» записи (хеш + ключ + значение) в массиве. С 3.6 добавлен отдельный массив индексов + плотный массив записей, что:
- уменьшило память;
- **сохранило порядок вставки** (записи идут по порядку добавления).

### Ловушка: изменение ключа

```python
d = {}
key = [1, 2]          # ❌ список нехешируем
# d[key] = "x"        # TypeError

# ✅ если ключ должен быть составным — кортеж
d[(1, 2)] = "x"
```

### Мини-итог

`dict` — хеш-таблица с открытой адресацией. Отсюда O(1) в среднем, сохранение порядка (3.7+), требование хешируемости ключей и худший случай O(n).

## 3. `set` / `frozenset`

- По сути — `dict` без значений (только ключи).
- Операции над множествами: `|`, `&`, `-`, `^`; `issubset`, `issuperset`.
- `frozenset` неизменяем и хешируем → может быть ключом `dict` или элементом `set`.
- Проверка `in` — O(1) в среднем.

```python
a = {1, 2, 3}; b = {3, 4}
a & b     # {3}
a | b     # {1, 2, 3, 4}
```

### Операции подробнее

```python
a = {1, 2, 3}
b = {3, 4, 5}

print(a & b)   # {3}          пересечение
print(a | b)   # {1,2,3,4,5}  объединение
print(a - b)   # {1, 2}       разность
print(a ^ b)   # {1,2,4,5}    симметрическая разность
print(a <= {1,2,3,4})   # True — подмножество
```

### `set` vs `frozenset`

```python
s = {1, 2, 3}
s.add(4)              # ✅ изменяемый

fs = frozenset([1, 2, 3])
# fs.add(4)           # ❌ AttributeError

d = {fs: "можно использовать как ключ"}   # ✅
```

### Зачем множества в реальном коде

```python
# Быстрый поиск дубликатов
data = [1, 2, 2, 3, 3, 3]
print(set(data))          # {1, 2, 3}
print(len(set(data)) < len(data))   # True — есть дубликаты

# Быстрое пересечение интересов
user1 = {"python", "sql"}
user2 = {"python", "docker"}
print(user1 & user2)      # {'python'}
```

### Мини-итог

`set` — хеш-множество для проверки принадлежности и операций над множествами. `frozenset` — его неизменяемый, хешируемый собрат.

## 4. `tuple`

- Неизменяемая последовательность; **хешируем**, если все элементы хешируемы.
- Меньше памяти и быстрее `list`.
- Используется для «записей» и как ключ словаря.
- `namedtuple` — читаемость: доступ по имени.

```python
from collections import namedtuple
Point = namedtuple("Point", "x y")
p = Point(1, 2)
p.x        # 1
```

### tuple как запись

```python
point = (3, 4)
x, y = point        # распаковка
print(x, y)         # 3 4

# Возврат нескольких значений — фактически кортеж
def minmax(data):
    return min(data), max(data)

lo, hi = minmax([3, 1, 4, 1, 5])
print(lo, hi)       # 1 5
```

### Хешируемость зависит от содержимого

```python
print(hash((1, 2)))            # ✅
print(hash((1, [2])))          # ❌ TypeError — внутри список
```

### Память: tuple vs list

```python
import sys
print(sys.getsizeof((1, 2, 3)))   # 64
print(sys.getsizeof([1, 2, 3]))   # 80 — list больше
```

### Мини-итог

`tuple` — компактная неизменяемая запись. Идеален для фиксированных наборов и ключей словаря.

## 5. `deque` и другие из `collections`

- **`deque`** — двусвязный список блоков, O(1) на оба конца. `maxlen` для скользящего окна.
- **`Counter`** — счётчик; `most_common`, `elements`, арифметика.
- **`defaultdict`** — фабрика значений по умолчанию.
- **`OrderedDict`** — теперь важен только для `move_to_end`/`popitem(last=False)`.
- **`ChainMap`** — несколько словарей как один (конфиги/окружения).
- **`UserDict`/`UserList`** — удобные базовые классы для наследования.

```python
from collections import deque, defaultdict, ChainMap
dq = deque(maxlen=3)
dq.extend([1, 2, 3, 4])     # хранит [2, 3, 4]
```

### Почему deque быстр на обоих концах

`deque` хранит элементы в блоках, связанных двусвязным списком. Добавление/удаление с любого конца не требует сдвига всех элементов, в отличие от `list`.

```python
import time
from collections import deque

n = 200_000
lst = list(range(n))
dq = deque(range(n))

t0 = time.perf_counter()
for _ in range(n):
    lst.insert(0, 0)     # O(n) каждая
t1 = time.perf_counter()

dq2 = deque(range(n))
for _ in range(n):
    dq2.appendleft(0)    # O(1) каждая
t2 = time.perf_counter()

print("list.insert(0):", round(t1 - t0, 3))
print("deque.appendleft:", round(t2 - t1, 3))
```

### `ChainMap` — объединение словарей

```python
from collections import ChainMap

defaults = {"color": "black", "size": "M"}
user = {"color": "red"}

cfg = ChainMap(user, defaults)
print(cfg["color"])    # red — берётся из первого словаря
print(cfg["size"])     # M — из defaults
```

### `UserDict` — правильное наследование

```python
from collections import UserDict

class LowerDict(UserDict):
    def __setitem__(self, key, value):
        super().__setitem__(key.lower(), value)

d = LowerDict()
d["KEY"] = 1
print(d)               # {'key': 1}
```

> Наследоваться от `dict` напрямую рискованно: некоторые методы не вызывают переопределённые. `UserDict` это учитывает.

### Мини-итог

`collections` — набор структур, закрывающих конкретные сценарии: очередь (`deque`), частоты (`Counter`), группировка (`defaultdict`), конфиги (`ChainMap`), наследование (`UserDict`).

## 6. Сортировка и `key`

- `sorted()`/`list.sort()` — **Timsort**, стабильная, O(n log n).
- `key=` вычисляется один раз на элемент (быстрее `cmp`).
- `operator.itemgetter`/`attrgetter` быстрее лямбд.

```python
from operator import itemgetter
rows = [("b", 2), ("a", 1)]
sorted(rows, key=itemgetter(1))     # по числу
```

Сортировка кортежей — по элементам слева направо (лексикографически).

### Стабильность сортировки

Стабильность значит: элементы с равным ключом сохраняют исходный порядок.

```python
data = [("a", 2), ("b", 1), ("c", 2)]
print(sorted(data, key=lambda x: x[1]))
# [('b', 1), ('a', 2), ('c', 2)] — 'a' и 'c' в исходном порядке
```

### Сортировка по нескольким ключам

```python
people = [("Аня", 30), ("Борис", 25), ("Вера", 30)]
# сначала по возрасту, затем по имени
result = sorted(people, key=lambda p: (p[1], p[0]))
print(result)
# [('Борис', 25), ('Аня', 30), ('Вера', 30)]
```

### `itemgetter` быстрее лямбды

```python
from operator import itemgetter, attrgetter

rows = [("b", 2), ("a", 1)]
print(sorted(rows, key=itemgetter(0)))   # по первому элементу

class P:
    def __init__(self, age): self.age = age
people = [P(30), P(20)]
print([p.age for p in sorted(people, key=attrgetter("age"))])  # [20, 30]
```

### `sort` vs `sorted`

```python
lst = [3, 1, 2]
lst.sort()            # изменяет список на месте, возвращает None
print(lst)            # [1, 2, 3]

new = sorted([3, 1, 2])   # возвращает новый список
print(new)                # [1, 2, 3]
```

### Мини-итог

Timsort стабилен и быстр. `key=` эффективнее «ручного» сравнения. Для составных ключей возвращай кортеж.

## 7. Копирование и вложенность

```python
import copy
shallow = copy.copy(nested)
deep = copy.deepcopy(nested)
```

- `copy.copy` копирует верхний уровень; вложенные объекты общие.
- `deepcopy` рекурсивно; уважает `__copy__`/`__deepcopy__`.
- Срез `lst[:]`, `list(lst)`, `dict(d)` — поверхностные копии.
- **Правило:** неизменяемые объекты копировать не нужно.

### Как deepcopy обходит циклы

`deepcopy` ведёт таблицу уже скопированных объектов (`memo`), поэтому не зацикливается на самоссылающихся структурах.

```python
import copy

a = [1]
a.append(a)          # цикл: a содержит сам себя
b = copy.deepcopy(a) # корректно обработает цикл
print(b[1] is b)     # True — цикл воспроизведён
```

### `__copy__` / `__deepcopy__`

```python
import copy

class Box:
    def __init__(self, value): self.value = value
    def __copy__(self):
        print("поверхностная копия")
        return Box(self.value)
    def __deepcopy__(self, memo):
        print("глубокая копия")
        return Box(copy.deepcopy(self.value, memo))

b = Box([1, 2])
copy.copy(b)          # поверхностная копия
copy.deepcopy(b)      # глубокая копия
```

### Когда копировать не нужно

```python
x = 5            # int неизменяем — копирование бессмысленно
s = "hello"      # str неизменяем
t = (1, 2)       # tuple из неизменяемых — тоже
```

### Мини-итог

Выбор копирования зависит от вложенности и изменяемости. `deepcopy` безопаснее, но дороже; поверхностной копии достаточно, если внутренние объекты не мутируются.

## 8. Полезные встроенные модули

- **`array`** — компактный массив однотипных чисел.
- **`bisect`** — бинарный поиск и вставка в отсортированный список.
- **`heapq`** — куча на списке (min-heap), `nsmallest`/`nlargest`.
- **`itertools`** — комбинаторика и ленивые итераторы.

```python
import bisect, heapq
bisect.insort(lst, x)             # вставка с сохранением порядка
heapq.nlargest(3, data)
```

### `bisect` — поиск в отсортированном списке

```python
import bisect

sorted_list = [1, 3, 5, 7]
pos = bisect.bisect_left(sorted_list, 4)
print(pos)                        # 2 — куда вставить, чтобы сохранить порядок
bisect.insort(sorted_list, 4)
print(sorted_list)                # [1, 3, 4, 5, 7]
```

Сложность поиска — O(log n), вставки — O(n) из-за сдвига.

### `heapq` — очередь с приоритетом

```python
import heapq

nums = [5, 1, 8, 3]
heapq.heapify(nums)
print(nums[0])                    # 1 — минимум всегда в корне
heapq.heappush(nums, 0)
print(heapq.heappop(nums))        # 0

# Топ-3 наибольших
print(heapq.nlargest(3, [5, 1, 8, 3, 9, 2]))   # [9, 8, 5]
```

### `array` — компактность

```python
from array import array

a = array("i", [1, 2, 3])   # массив int
print(a.itemsize)           # 4 байта на элемент
```

### Мини-итог

Стандартная библиотека даёт бинарный поиск (`bisect`), кучу (`heapq`), компактные массивы (`array`) и ленивую комбинаторику (`itertools`). Это часто лучший ответ на «как сделать эффективно».

## 11. Мини-итог дня (углублённый)

1. `list` — динамический массив ссылок, `append` амортизированно O(1).
2. `dict`/`set` — хеш-таблицы, O(1) в среднем, порядок вставки у dict с 3.7.
3. `tuple` компактнее и может быть ключом.
4. `collections` закрывает типовые задачи готовыми структурами.
5. Timsort стабилен; `key=` — эффективный способ сортировки.
6. Копирование бывает поверхностным и глубоким.

**Связка:** хешируемость — из Дня 1; генераторные выражения и `itertools` — мост к Дню 4.
