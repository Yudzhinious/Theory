## 1. HTTP-сессии и надёжность

```python
import requests
s = requests.Session()
s.headers.update({"User-Agent": "Mozilla/5.0"})
s.get(url)   # cookies и соединение переиспользуются
```

- **Redirects** — `allow_redirects`, `history`.
- **Retries + backoff:** `HTTPAdapter` + `Retry`, экспоненциальная задержка + jitter.
- **Таймауты** обязательны (connect/read).
- **Прокси:** `proxies={"https": "http://..."}`.
- **Сжатие** (gzip/br) обрабатывается автоматически.

```python
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry
retry = Retry(total=3, backoff_factor=0.5, status_forcelist=[429, 500, 502, 503])
s.mount("https://", HTTPAdapter(max_retries=retry))
```

### 1.1 Зачем `Session`

Каждый `requests.get` без сессии открывает новое TCP-соединение. `Session`
переиспользует его (keep-alive), хранит cookies и общие заголовки — это заметно
быстрее при множестве запросов к одному домену.

### 1.2 Таймауты: connect vs read

```python
requests.get(url, timeout=(3.05, 27))   # (connect, read)
```

| Таймаут | Что ограничивает |
|---|---|
| connect | Установку соединения |
| read | Ожидание данных после отправки запроса |

> Никогда не ставьте `timeout=None`: зависший запрос может остановить весь парсер.

### 1.3 Экспоненциальный backoff с jitter

```python
import time, random

def backoff(attempt):
    base = 0.5 * (2 ** attempt)
    return base + random.uniform(0, base * 0.1)   # jitter против «толпы»
```

Jitter разносит повторы по времени, чтобы после сбоя все клиенты не ударили разом.

### 1.4 Прокси и смена IP

```python
proxies = {"http": "http://user:pass@proxy:8080",
           "https": "http://user:pass@proxy:8080"}
requests.get(url, proxies=proxies, timeout=10)
```

Прокси нужны при лимитах по IP, но их использование должно уважать ToS.

## 2. Селекторы: CSS, XPath, JSONPath

- **CSS:** `div.item > a.link`, `.price`, `#main a[href]`, `:nth-child`.
- **XPath:** `/html/body//a[@class='x']`, `//span[contains(text(),'цена')]`.
- **lxml** быстрее; поддерживает XPath нативно.
- **JSONPath** для JSON-API (`$..price`), `jmespath`.

```python
from lxml import html
tree = html.fromstring(page)
prices = tree.xpath("//span[@class='price']/text()")
```

### 2.1 Сравнение CSS и XPath

| | CSS | XPath |
|---|---|---|
| Читаемость | Простой | Мощнее, многословнее |
| Поиск по тексту | Ограничен | `contains(text(), ...)` |
| Переход к родителю | Нет | `..` |
| Поддержка | BS4, lxml | lxml, Selenium |

```python
# CSS
soup.select("div.item > a.link")
# XPath-эквивалент
tree.xpath("//div[@class='item']/a[@class='link']")
```

### 2.2 JSONPath / jmespath для API

```python
data = {"items": [{"price": 100}, {"price": 200}]}

# jmespath
import jmespath
jmespath.search("items[*].price", data)     # [100, 200]

# jsonpath-ng
from jsonpath_ng import parse
[float(m.value) for m in parse("$..price").find(data)]   # [100.0, 200.0]
```

### 2.3 Типичная ошибка: хрупкие селекторы

```python
# ПЛОХО: привязка к вёрстке и порядку
soup.select("body > div > div:nth-child(3) > span")   # сломается при редизайне

# ХОРОШО: устойчивые признаки (класс, data-атрибут, семантика)
soup.select("article.product span.price")
```

## 3. BeautifulSoup детали

- Парсеры: `html.parser` (встроенный), `lxml` (быстрый), `html5lib` (терпимый).
- `soup.select(...)` — CSS; `soup.find(...)` — по тегу/атрибуту.
- `get_text(strip=True, separator=" ")`, `attrs`, `parent`, `find_next`.
- Устойчив к «грязному» HTML.

```python
soup.select_one("article h2").get_text(strip=True)
```

### 3.1 Выбор парсера

| Парсер | Скорость | Терпимость | Зависимость |
|---|---|---|---|
| `html.parser` | Средняя | Средняя | Встроен |
| `lxml` | Быстрая | Средняя | `pip install lxml` |
| `html5lib` | Медленная | Высокая | `pip install html5lib` |

### 3.2 Навигация по дереву

```python
tag = soup.select_one(".price")
print(tag.parent.name)          # div — родитель
print(tag.find_next("span"))    # следующий span
print(tag.attrs)                # {'class': ['price']}
print(tag.get("data-id"))       # безопасное значение атрибута или None
```

### 3.3 Извлечение списка карточек

```python
cards = []
for card in soup.select("div.product"):
    cards.append({
        "name": card.select_one(".name").get_text(strip=True),
        "price": card.select_one(".price").get_text(strip=True),
        "url": card.select_one("a")["href"],
    })
print(cards)
```

## 4. Динамические страницы

- **Playwright** (совр.) / **Selenium** — управляют реальным браузером.
- Ожидания: `wait_for_selector`, `wait_for_load_state`.
- Перехват сетевых запросов — можно брать данные из XHR/API вместо парсинга DOM.
- Headless-режим для серверов; stealth-плагины против детекции.

```python
page.goto(url)
page.wait_for_selector(".results")
items = page.query_selector_all(".item")
```

### 4.1 Правильные ожидания

```python
page.goto(url, wait_until="networkidle")   # ждать затишья сети
page.wait_for_selector(".results", state="visible")
page.wait_for_load_state("load")
```

Не используйте `time.sleep(5)` — либо ждём мало (ошибка), либо много (медленно).
Ожидания по условию надёжнее.

### 4.2 Перехват XHR

```python
responses = []
page.on("response", lambda r: responses.append(r) if "/api/" in r.url else None)
page.goto(url)
page.wait_for_selector(".results")
# далее можно взять JSON прямо из responses вместо парсинга DOM
```

### 4.3 Типичная ошибка

```python
# ПЛОХО: фиксированная пауза
page.goto(url); time.sleep(5)

# ХОРОШО: ждать конкретный элемент
page.goto(url); page.wait_for_selector(".results")
```

## 5. Асинхронный scraping

```python
import asyncio, aiohttp

async def fetch(session, url, sem):
    async with sem:                      # ограничение конкурентности
        async with session.get(url) as r:
            return await r.text()

async def main(urls):
    sem = asyncio.Semaphore(10)
    async with aiohttp.ClientSession() as s:
        return await asyncio.gather(*(fetch(s, u, sem) for u in urls))

asyncio.run(main(urls))
```

**Semaphore** защищает и сервер, и тебя (rate limit).

### 5.1 Сравнение моделей конкурентности

| Модель | Механизм | Лучше для |
|---|---|---|
| Синхронно | По одному запросу | Мало страниц |
| Потоки | `ThreadPoolExecutor` | I/O, привычный код |
| Async | `asyncio` | Тысячи запросов |

### 5.2 Обработка ошибок в async

```python
async def fetch(session, url, sem):
    async with sem:
        try:
            async with session.get(url, timeout=10) as r:
                r.raise_for_status()
                return await r.text()
        except aiohttp.ClientError as e:
            print(f"ошибка {url}: {e}")
            return None
```

Без обработки одна упавшая задача «уронит» весь `gather`.

## 6. Scrapy (фреймворк)

- **Spiders** — логика обхода; **Items** — структуры данных; **Pipelines** — очистка/сохранение; **Middlewares** — прокси, headers, retry.
- Асинхронный из коробки, дедупликация, throttling, `robots.txt` по умолчанию.
- Планирование: cron, Airflow, Celery.

```bash
scrapy startproject myproject
scrapy crawl myspider -o out.json
```

### 6.1 Архитектура Scrapy

```text
Engine
 ├── Scheduler  -> очередь запросов (с дедупликацией)
 ├── Downloader -> сеть (+ Middlewares: прокси, retry)
 ├── Spider     -> извлекает данные (yield Item)
 └── Pipelines  -> очистка и сохранение (yield -> JSON/БД)
```

### 6.2 Пример spider

```python
import scrapy

class QuotesSpider(scrapy.Spider):
    name = "quotes"
    start_urls = ["https://quotes.toscrape.com"]

    def parse(self, response):
        for q in response.css("div.quote"):
            yield {
                "text": q.css("span.text::text").get(),
                "author": q.css("small.author::text").get(),
            }
        next_page = response.css("li.next a::attr(href)").get()
        if next_page:
            yield response.follow(next_page, self.parse)
```

### 6.3 Scrapy vs самописный парсер

| | Scrapy | `requests` + BS4 |
|---|---|---|
| Обход страниц | Из коробки | Вручную |
| Конкурентность | Async по умолчанию | Нужно настраивать |
| Дедупликация | Есть | Нет |
| Порог входа | Выше | Низкий |
| Лучше для | Большие краулы | Простые задачи |

## 7. Anti-bot и обход (этично!)

- CAPTCHA, Cloudflare, fingerprinting (TLS/JA3, canvas), динамические токены.
- Средства: ротация прокси/User-Agent, паузы, headless-браузер, официальные API.
- **Сначала ищи API или данные в JSON** — часто проще и легальнее.
- **Не обходи** защиты, если это нарушает ToS/закон.

### 7.1 Как работает детекция

```text
1. User-Agent и заголовки: «слишком ровные» выдают бота.
2. Поведение: мгновенные запросы, без пауз.
3. TLS fingerprint (JA3): библиотеки отличаются от браузеров.
4. JS-челлендж (Cloudflare): нужно выполнить скрипт браузером.
```

### 7.2 Что делать этично

| Ситуация | Действие |
|---|---|
| Есть API | Использовать API |
| Есть robots.txt с Disallow | Не обходить |
| Нужны большие объёмы | Договориться / платный доступ |
| Персональные данные | Не собирать без оснований |
| CAPTCHA | Остановиться, а не обходить |

## 8. Правовые и этические аспекты

- **robots.txt** — уважай.
- **ToS** сайта — читай.
- **Персональные данные** (GDPR, 152-ФЗ) — не собирай без оснований.
- **Авторские права** на контент.
- Нагрузка: не «долби» сервер, ставь паузы и лимиты.

### 8.1 Что попадает под персональные данные

```text
Имя, email, телефон, IP, cookie-id, фото — всё это может быть персональными данными.
Их обработка требует правового основания (GDPR в ЕС, 152-ФЗ в РФ).
```

## 9. Хранение и обработка

```python
import pandas as pd
df = pd.DataFrame(rows)
df.to_csv("out.csv", index=False)
df.to_sql("items", engine, if_exists="append")
```

- JSON/CSV для простого, SQLite/Postgres для объёмов, S3 для файлов.
- Очистка: `pandas`, нормализация типов, дедупликация.
- Идемпотентность: не дублируй записи (уникальные ключи, upsert).

### 9.1 Выбор хранилища

| Объём / задача | Хранилище |
|---|---|
| Пара тысяч строк | CSV/JSON |
| Десятки тысяч | SQLite |
| Миллионы, запросы | Postgres |
| Файлы, изображения | S3 |

### 9.2 Идемпотентность через upsert

```sql
-- Postgres: вставить или обновить по уникальному ключу
INSERT INTO items (url, price) VALUES (%s, %s)
ON CONFLICT (url) DO UPDATE SET price = EXCLUDED.price;
```

Повторный запуск парсера не создаст дубликатов.

### 9.3 Очистка данных

```python
import pandas as pd

df = pd.DataFrame(rows)
df["price"] = (df["price"]
    .str.replace(r"[^\d]", "", regex=True)   # убрать всё кроме цифр
    .astype(float))
df = df.drop_duplicates(subset=["url"])
```

## 10. Сложность и производительность

| Операция | Стоимость | Комментарий |
|---|---|---|
| Сетевой запрос | Десятки–сотни мс | Доминирует |
| Парсинг HTML (lxml) | Миллисекунды | Быстрее сети |
| Async N запросов | ~время самого медленного при конкурентности N | Semaphore важен |
| Потоки | Ограничены GIL, но I/O отпускает | Уступают async |

> Узкое место scraping — **сеть**, а не парсинг. Поэтому асинхронность и keep-alive
> дают больший выигрыш, чем «оптимизация селекторов».

## 12. Мини-итог

- `Session` + retries + backoff + таймауты = надёжные запросы.
- CSS удобнее, XPath мощнее; селекторы делай устойчивыми.
- JS-страницы: Playwright/Selenium или перехват XHR.
- Async + Semaphore ускоряют и защищают сервер.
- Scrapy даёт краулинг, дедупликацию и pipelines из коробки.
- Anti-bot обходи этично: сначала API, уважай robots.txt и ToS.
- Храни данные идемпотентно (upsert) и очищай.
