## 1. Динамическая типизация

Python — язык с **динамической строгой типизацией**:

- **Динамическая** — тип переменной определяется во время выполнения, а не при объявлении.
- **Строгая** — нельзя молча сложить `str` и `int`: `"1" + 1` → `TypeError`.

```python
x = 10        # int
x = "hello"   # та же переменная теперь str — это нормально
```

Переменная — это **имя (ссылка)**, а не «коробка со значением». Имя указывает на объект в памяти.

### Что это значит на практике

```python
x = 10          # создан объект int(10), имя x указывает на него
y = x           # y указывает на ТОТ ЖЕ объект
print(x is y)   # True — это один объект, а не две копии

x = x + 1       # создан НОВЫЙ объект int(11), имя x теперь указывает на него
print(y)        # 10 — объект y не тронут
print(x is y)   # False — теперь это разные объекты
```

### Аналогия

Представьте **бирки на вешалках** в гардеробе. Бирка `x` — это не пальто, а номер, который указывает на конкретное пальто. Когда вы пишете `x = x + 1`, вы не «перешиваете» пальто, а вешаете бирку `x` на другое пальто.

### Три свойства типизации

| Свойство | Значение | Пример |
|---|---|---|
| Динамическая | тип определяется в момент выполнения | `x = 1; x = "a"` — ок |
| Строгая | нет неявных «безопасных» преобразований | `"1" + 1` → `TypeError` |
| Утиная | важен набор методов, а не сам тип | работает, если есть нужный метод |

> Сравнение: в C++ `int x = "a"` не скомпилируется, а в Python — отработает и упадёт только при попытке сложения. В JavaScript `"1" + 1` даст `"11"` (слабая типизация), а в Python — ошибку.

### Мини-итог

Динамическая типизация = гибкость, но цена — ошибки типов видны в рантайме, а не при компиляции. Поэтому важны аннотации типов и тесты (разберём позже).

## 2. Всё — объект

Любое значение в Python — объект. У каждого объекта есть:

- **тип** — `type(obj)`;
- **идентичность** — `id(obj)` (адрес в памяти);
- **значение**;
- **счётчик ссылок** (для сборщика мусора).

Встроенные типы, которые надо знать:

| Категория | Типы |
|---|---|
| Числа | `int`, `float`, `complex`, `bool` |
| Последовательности | `str`, `list`, `tuple`, `range` |
| Множества | `set`, `frozenset` |
| Отображения | `dict` |
| None | `NoneType` |
| Байты | `bytes`, `bytearray` |

`bool` — подкласс `int`: `True == 1`, `False == 0`.

### Что значит «всё — объект»

Даже у числа и строки есть методы и атрибуты:

```python
print(type(42))          # <class 'int'>
print(type("hi"))        # <class 'str'>
print((42).bit_length()) # 6  — у int есть методы!
print("hi".upper())      # HI — у str есть методы

def f():
    pass
print(type(f))           # <class 'function'> — функция тоже объект
```

### Атрибуты объекта

```python
x = 5
print(type(x))      # <class 'int'> — тип
print(id(x))        # адрес, например 140234...
print(x.__class__)  # <class 'int'> — то же, что type(x)
```

### Почему `bool` — подкласс `int`

```python
print(True + True)       # 2 — True ведёт себя как 1
print(True * 10)         # 10
print(isinstance(True, int))   # True
print(sum([True, False, True])) # 2 — удобно считать «галочки»
```

### Мини-итог

Единая объектная модель — причина, по которой Python последователен: везде работают `type`, `id`, методы, атрибуты. Это же основа для интроспекции и метапрограммирования.

## 3. Изменяемые и неизменяемые типы

- **Неизменяемые (immutable):** `int`, `float`, `str`, `tuple`, `frozenset`, `bytes`, `bool`, `None`.
- **Изменяемые (mutable):** `list`, `dict`, `set`, `bytearray`.

```python
s = "abc"
s2 = s
s += "d"          # создаётся НОВЫЙ объект строки, s теперь указывает на "abcd"
print(s2)         # "abc" — старый объект не изменился

lst = [1, 2]
lst2 = lst
lst.append(3)     # изменяем сам объект
print(lst2)       # [1, 2, 3] — обе ссылки видят одно и то же
```

> Частая ловушка: изменяемый объект, переданный в функцию, может измениться внутри неё.

### Пошаговый разбор: неизменяемая строка

```python
s = "abc"          # id(s) = A
s2 = s             # s2 тоже указывает на A
s = s + "d"        # создаётся НОВЫЙ объект "abcd" (id = B)
                   # s указывает на B, s2 всё ещё на A
print(id(s) == id(s2))  # False
print(s, s2)            # abcd abc
```

### Пошаговый разбор: изменяемый список

```python
lst = [1, 2]       # id(lst) = C
lst2 = lst         # lst2 тоже на C
lst.append(3)      # объект C мутирует: [1, 2, 3]
print(id(lst) == id(lst2))  # True
print(lst, lst2)            # [1, 2, 3] [1, 2, 3]
```

### Ловушка с аргументом функции

```python
def add_item(item, box):
    box.append(item)   # мутируем объект, а не переприсваиваем имя
    return box

my_list = [1]
add_item(2, my_list)
print(my_list)         # [1, 2] — исходный список изменился!
```

**Как избежать:** передавать копию `add_item(2, my_list.copy())` или не мутировать аргументы внутри функции (чистые функции).

### Аналогия

- Неизменяемый объект — как **высеченная надпись на камне**: чтобы «поменять», нужно высечь новый камень.
- Изменяемый объект — как **доска с маркером**: можно стирать и дописывать, не меняя саму доску.

### Таблица сравнения

| Свойство | Immutable | Mutable |
|---|---|---|
| Можно менять на месте | нет | да |
| Хешируем | обычно да | нет |
| Может быть ключом `dict` | да | нет |
| Передача в функцию | безопасно | может измениться |
| Примеры | `int`, `str`, `tuple` | `list`, `dict`, `set` |

### Типичная ошибка

```python
# ❌ Как НЕ надо: думаем, что строка меняется на месте
s = "hello"
s.upper()          # метод вернул "HELLO", но никуда его не сохранили
print(s)           # hello — оригинал не изменился

# ✅ Как правильно
s = s.upper()
print(s)           # HELLO
```

### Мини-итог

Изменяемость определяет, «мутируем ли мы объект» или «создаём новый». Это влияет на копирование, передачу в функции и возможность быть ключом словаря.

## 4. `id()`, `is` и `==`

- `id(x)` — адрес объекта в памяти.
- `x is y` — **одна и та же** ли это ссылка (сравнение идентичности).
- `x == y` — **равны ли значения** (вызывает `__eq__`).

```python
a = [1, 2, 3]
b = [1, 2, 3]
a == b   # True  — значения равны
a is b   # False — разные объекты

c = a
a is c   # True  — одна ссылка
```

**Правило:** `is` — только для `None`, `True`, `False`. Всё остальное сравнивай через `==`.

### Наглядно: два списка с одинаковым содержимым

```python
a = [1, 2, 3]     # id = X
b = [1, 2, 3]     # id = Y (другой объект!)
print(a == b)     # True  — содержимое совпадает
print(a is b)     # False — объекты разные
print(id(a), id(b))  # X Y — разные адреса

c = a             # c указывает на X
print(a is c)     # True
```

### Сравнение поведения

| Оператор | Что сравнивает | Метод | Пример |
|---|---|---|---|
| `==` | значения | `__eq__` | `[1] == [1]` → True |
| `is` | идентичность (адрес) | — | `[1] is [1]` → False |
| `is not` | «не тот же объект» | — | `None is not x` |
| `!=` | неравенство значений | `__ne__` | `1 != 2` → True |

### Как правильно проверять на None

```python
x = None

# ✅ правильно
if x is None:
    print("пусто")

# ❌ плохо: сработает для 0, "", [], если объект подменён кастомным __eq__
if x == None:
    print("пусто")
```

### Типичная ошибка

```python
# ❌ Сравнение строк через is — ненадёжно
a = "hello world"
b = "hello world"
print(a is b)   # может быть True или False — зависит от интернирования

# ✅ всегда для строк
print(a == b)   # True гарантированно
```

### Мини-итог

`is` отвечает на вопрос «это тот же самый объект?», `==` — «эти объекты равны по значению?». На собеседовании любят просить пример, где `==` True, а `is` False — это любые два одинаковых списка.

## 5. Интернирование

Python кэширует некоторые неизменяемые объекты, чтобы экономить память.

- Маленькие целые от **-5 до 256** создаются один раз.
- Короткие строки, похожие на идентификаторы, могут интернироваться.
- `None`, `True`, `False` — всегда один объект.

```python
a = 256; b = 256
a is b            # True (интернированы)

a = 257; b = 257
a is b            # обычно False (вне кэша)

x = "hello"; y = "hello"
x is y            # часто True (интернирование строк)
```

### Почему именно -5..256

Разработчики CPython посчитали, что маленькие числа используются чаще всего, и создали их заранее при старте интерпретатора. Список `small_ints` хранится внутри и переиспользуется.

```python
a = 100
b = 100
print(a is b)   # True — оба из кэша

a = 1000
b = 1000
print(a is b)   # обычно False — вне кэша
```

### Интернирование строк

Интернируются строки, которые компилятор может распознать как «похожие на идентификатор» (буквы, цифры, `_`), а также строковые литералы в одном модуле.

```python
a = "abc"
b = "abc"
print(a is b)      # True — короткий литерал интернирован

a = "abc def"
b = "abc def"
print(a is b)      # может быть False — есть пробел, не идентификатор

import sys
a = sys.intern("abc def")
b = sys.intern("abc def")
print(a is b)      # True — принудительно интернировали
```

### Зачем это нужно

- **Экономия памяти**: одна копия вместо многих.
- **Скорость**: сравнение по указателю (`is`) быстрее, чем посимвольное (`==`).
- **Ключи словарей**: интернированные строки ускоряют поиск.

### Важно

Интернирование — **деталь реализации CPython**, а не гарантия языка. В PyPy или в другой версии поведение может отличаться. Поэтому **никогда** не полагайся на `is` для строк и чисел вне `None`/`True`/`False`.

> Подробнее: `[[Id() + is vs '==']]`, `[[Интернирование]]`.

### Мини-итог

Интернирование объясняет, почему `1 is 1` → True, а `[1] is [1]` → False. Но строить логику программы на этом нельзя — это оптимизация, а не контракт.

## 6. Строки

- Строки **неизменяемы**: любая «модификация» создаёт новую строку.
- Индексация и срезы: `s[0]`, `s[-1]`, `s[1:4]`, `s[::-1]` (разворот).
- Полезные методы: `.split()`, `.join()`, `.strip()`, `.replace()`, `.lower()`, `.startswith()`, f-строки.

```python
name = "world"
greeting = f"Hello, {name}!"      # f-строка
"a,b,c".split(",")                 # ['a', 'b', 'c']
",".join(["a", "b", "c"])          # 'a,b,c'
"  hi  ".strip()                   # 'hi'
```

Конкатенация строк в цикле через `+=` — плохо по памяти; лучше собрать список и `"".join(...)`.

### Индексация и срезы

```python
s = "Python"
print(s[0])     # P
print(s[-1])    # n   (последний символ)
print(s[1:4])   # yth (с 1 включительно до 4 не включительно)
print(s[:3])    # Pyt
print(s[3:])    # hon
print(s[::-1])  # nohtyP (разворот)
print(len(s))   # 6
```

### Основные методы

| Метод | Что делает | Пример |
|---|---|---|
| `upper()` / `lower()` | регистр | `"Hi".upper()` → `"HI"` |
| `strip()` | убирает пробелы по краям | `" hi ".strip()` → `"hi"` |
| `split(sep)` | разбивает в список | `"a,b".split(",")` → `['a','b']` |
| `join(iterable)` | склеивает | `"-".join(['a','b'])` → `"a-b"` |
| `replace(a, b)` | замена | `"aaa".replace("a","b")` → `"bbb"` |
| `startswith(x)` | проверка начала | `"http".startswith("ht")` → True |
| `find(x)` | индекс или -1 | `"abc".find("b")` → 1 |
| `count(x)` | число вхождений | `"aaa".count("a")` → 3 |

### Аналогия

Строка — как **надпись на стекле**: чтобы её изменить, проще сделать новую надпись, чем стирать часть.

### Проблема `+=` в цикле

```python
# ❌ Плохо: O(n^2) — на каждой итерации создаётся новая строка
result = ""
for word in ["a", "b", "c", "d"]:
    result += word     # каждый раз новый объект

# ✅ Хорошо: O(n) — собираем список и склеиваем один раз
parts = []
for word in ["a", "b", "c", "d"]:
    parts.append(word)
result = "".join(parts)
```

### Почему O(n²)

Каждая конкатенация копирует всю текущую строку целиком. Суммарно: 1 + 2 + 3 + ... + n = O(n²) копирований символов. `"".join` же заранее знает длины и копирует каждый символ один раз.

### Мини-итог

Строки неизменяемы → любые изменения создают новые объекты. Для массовой сборки используем `join`, для проверок — `startswith`/`in`, для форматирования — f-строки.

## 7. Ввод/вывод

```python
name = input("Как тебя зовут? ")   # всегда возвращает str
age = int(input("Возраст: "))      # приводим тип вручную
print(f"{name}, {age} лет")
```

### `input` всегда возвращает строку

```python
raw = input("Введите число: ")   # пользователь ввёл 42
print(type(raw))                 # <class 'str'>
number = int(raw)                # приводим явно
print(number + 1)                # 43
```

### Безопасный разбор числа

```python
try:
    age = int(input("Возраст: "))
except ValueError:
    print("Это не число!")
```

### `print` и его параметры

```python
print("a", "b", "c")            # a b c (через пробел)
print("a", "b", sep="-")        # a-b
print("без переноса", end="")
print("продолжение")
```

### Мини-итог

`input` — источник строк, поэтому любое числовое значение приводим вручную и желательно оборачиваем в `try/except`.

## 8. Что спрашивают на собеседовании

- Что такое динамическая типизация?
- `is` vs `==` — в чём разница?
- Что такое изменяемый/неизменяемый тип? Приведи примеры.
- Почему `[1,2] is [1,2]` → `False`, а `1 is 1` → `True`?
- Почему строки неизменяемы и как это влияет на конкатенацию в цикле?

### Разбор типового ответа

**Вопрос:** Почему `[1,2] is [1,2]` → `False`, а `1 is 1` → `True`?

**Ответ:** `is` сравнивает идентичность объектов. Два списка `[1,2]` создаются как два независимых объекта в памяти, поэтому у них разные `id` → `False`. Целые числа от -5 до 256 интернируются (кэшируются при старте интерпретатора), поэтому `1` и `1` — один и тот же объект → `True`.

### Ещё вероятные вопросы

- Что вернёт `type(True)`? → `<class 'bool'>`, при этом `isinstance(True, int)` → True.
- Чем опасен изменяемый аргумент по умолчанию? → он сохраняется между вызовами (День 3).
- Что такое refcount? → счётчик ссылок на объект; при 0 объект удаляется.

## 9. Частые ошибки новичков (сводка)

```python
# ❌ 1. Ожидание, что присваивание копирует
a = [1, 2]
b = a
b.append(3)
print(a)          # [1, 2, 3] — не копия!

# ✅ Копия
b = a.copy()      # или a[:], list(a)

# ❌ 2. Проверка на None через ==
if x == None: ...

# ✅
if x is None: ...

# ❌ 3. Сравнение чисел с плавающей точкой через ==
0.1 + 0.2 == 0.3  # False

# ✅
import math
math.isclose(0.1 + 0.2, 0.3)   # True

# ❌ 4. Конкатенация строк в цикле
s = ""
for w in words:
    s += w

# ✅
s = "".join(words)
```

## 10. Мини-итог дня

1. Переменная — это **ссылка (имя)** на объект, а не коробка.
2. Всё — объект с типом, идентичностью и значением.
3. Изменяемость определяет поведение при присваивании и передаче в функцию.
4. `is` — идентичность, `==` — равенство значений; `is` только для `None`/`True`/`False`.
5. Интернирование объясняет «магию» с `1 is 1`, но полагаться на него нельзя.
6. Строки неизменяемы → используем `join`, а не `+=` в цикле.

**Связка с другими темами:** изменяемость напрямую влияет на копирование (День 2), на аргументы по умолчанию (День 3) и на замыкания (День 3).
