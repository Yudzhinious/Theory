## 1. Всё есть объект: структура `PyObject`

В CPython любой объект начинается с двух полей:

```c
typedef struct {
    Py_ssize_t ob_refcnt;   // счётчик ссылок
    PyTypeObject *ob_type;  // указатель на тип
} PyObject;
```

- Переменная — это **имя в пространстве имён** (namespace), указывающее на объект.
- Присваивание `a = b` **не копирует** объект, а добавляет ссылку (+1 к refcount).
- `del a` уменьшает refcount; при 0 объект освобождается.

```python
import sys
a = []
b = a
sys.getrefcount(a)   # 3 (a, b и временный аргумент getrefcount)
```

### Пошаговый разбор refcount

```python
import sys

a = []                       # создан список, refcount = 1 (имя a)
print(sys.getrefcount(a))    # 2: a + временный аргумент

b = a                        # ещё одна ссылка, refcount = 2
print(sys.getrefcount(a))    # 3: a, b, временный

del b                        # удалили имя b, refcount = 1
print(sys.getrefcount(a))    # 2: a + временный
```

### Аналогия

Объект — как **файл, открытый несколькими ярлыками**. Пока есть хотя бы один ярлык (ссылка), файл существует. Когда закрыли последний ярлык, операционная система может освободить файл.

### Что происходит при `del`

```python
a = [1, 2, 3]
b = a
del a            # удалили ИМЯ a, но объект жив, т.к. b ещё ссылается
print(b)         # [1, 2, 3]
```

`del` удаляет **имя**, а не объект. Объект исчезает, когда на него не остаётся ссылок.

### Мини-итог

`ob_refcnt` — основа управления памятью. Понимание refcount объясняет, почему объект живёт, пока на него есть ссылка, и почему циклические ссылки требуют отдельного сборщика.

## 2. Кэширование и интернирование

- **Small int cache:** целые `-5..256` создаются один раз при старте.
- **String interning:** строки, похожие на идентификаторы (буквы/цифры/`_`), могут кэшироваться. Компилятор интернирует строковые литералы.
- **`sys.intern(s)`** — принудительно интернировать строку (ускоряет сравнение по `is` в словарях-ключах).

```python
import sys
sys.intern("long_string_...")   # теперь одна ссылка на равные строки
```

Интернирование — оптимизация **CPython**, а не гарантия языка. Не полагайся на `is` для строк.

### Что именно интернируется

```python
# Целые -5..256
print(256 is 256)     # True
print(257 is 257)     # False (обычно)

# Короткие идентификаторы
print("abc" is "abc")       # True
print("abc def" is "abc def")  # может быть False

# Литералы одного модуля компилятор может объединить
```

### `sys.intern` на практике

```python
import sys

a = sys.intern("очень длинная строка " * 3)
b = sys.intern("очень длинная строка " * 3)
print(a is b)     # True — теперь одна ссылка
```

Зачем: если вы используете много одинаковых строк как ключи (например, имена тегов), интернирование экономит память и ускоряет сравнение.

### Сравнение со сравнением

| Способ | Скорость | Надёжность |
|---|---|---|
| `a is b` (интернированные) | O(1) | зависит от интернирования |
| `a == b` | O(len) | всегда корректно |

### Мини-итог

Интернирование — оптимизация для памяти и скорости. Знать о ней нужно, но применять `is` к строкам нельзя: поведение не гарантировано спецификацией.

## 3. `__eq__`, `__hash__` и контракт равенства

Правило: **если `a == b`, то `hash(a) == hash(b)`** (обратное неверно).

- Переопределяя `__eq__`, ты **теряешь** автоматический `__hash__` (он становится `None`) → объект нельзя класть в `set`/`dict`.
- Для неизменяемых объектов задавай `__hash__` вручную.

```python
class Point:
    def __init__(self, x, y): self.x, self.y = x, y
    def __eq__(self, o): return (self.x, self.y) == (o.x, o.y)
    def __hash__(self): return hash((self.x, self.y))
```

**Hash randomization:** хеши строк рандомизируются при старте (`PYTHONHASHSEED`), чтобы защититься от hash-DoS. Поэтому порядок `set` между запусками может отличаться.

### Почему контракт важен

Если нарушить контракт (`a == b`, но `hash(a) != hash(b)`), объект «потеряется» в словаре:

```python
class Bad:
    def __init__(self, x): self.x = x
    def __eq__(self, o): return self.x == o.x
    def __hash__(self): return id(self)   # ❌ нарушение контракта!

d = {Bad(1): "a"}
print(d.get(Bad(1)))   # None — не нашли, хотя объекты равны
```

### Как правильно

```python
class Good:
    def __init__(self, x): self.x = x
    def __eq__(self, o): return self.x == o.x
    def __hash__(self): return hash(self.x)   # ✅ одинаковый для равных

d = {Good(1): "a"}
print(d.get(Good(1)))   # 'a'
```

### Что происходит по умолчанию

| Определено | `__hash__` |
|---|---|
| ничего | по `id` (объект хешируем) |
| только `__eq__` | становится `None` (не хешируем) |
| `__eq__` + `__hash__` | работает по вашему правилу |

### Мини-итог

Контракт `__eq__`/`__hash__` — фундамент `dict` и `set`. Переопределяешь `__eq__` — почти всегда переопределяй и `__hash__` (или делай объект неизменяемым).

## 4. Истинность (`truthiness`)

`bool(x)` использует `__bool__`, а если его нет — `__len__`:

```python
bool([]) == False
bool(0) == False
bool("") == False
bool(None) == False
bool(object()) == True     # объект без __bool__/__len__ всегда истинен
```

Ловушка: `if x:` для числовых значений `0` может быть нежелательно — используй `if x is not None:`.

### Полная таблица «ложных» значений

| Значение | `bool(...)` |
|---|---|
| `None` | False |
| `False` | False |
| `0`, `0.0`, `0j` | False |
| `""` | False |
| `[]`, `()`, `{}`, `set()` | False |
| `Decimal(0)` | False |
| всё остальное | True |

### Как Python выбирает

```python
class Empty:
    def __len__(self):
        return 0

class Always:
    pass

print(bool(Empty()))    # False — сработал __len__
print(bool(Always()))   # True — нет ни __bool__, ни __len__
```

### Ловушка с `if x`

```python
def process(value=None):
    # ❌ если value == 0, мы ошибочно решим, что оно не передано
    if not value:
        return "нет значения"
    return value

print(process(0))       # "нет значения" — неверно, 0 это валидное значение

# ✅
def process2(value=None):
    if value is None:
        return "нет значения"
    return value

print(process2(0))      # 0
```

### Мини-итог

Истинность — это `__bool__`, затем `__len__`. Когда `0`/пустая коллекция — валидные данные, проверяй через `is None`, а не через `if x`.

## 5. Числа: int, float, Decimal

- **`int`** — произвольной точности (big int). `sys.getsizeof(2**100)` растёт.
- **`float`** — IEEE 754 двойной точности. Классика:

```python
0.1 + 0.2 == 0.3        # False!
round(0.1 + 0.2, 2)     # 0.3
math.isclose(0.1 + 0.2, 0.3)   # True
```

- **`Decimal`** — точная десятичная арифметика (деньги).
- **`Fraction`** — рациональные числа.
- Сравнение float — через `math.isclose`, не `==`.

```python
from decimal import Decimal
Decimal("0.1") + Decimal("0.2") == Decimal("0.3")   # True
```

### Почему `0.1 + 0.2 != 0.3`

Число `0.1` в двоичной системе с плавающей точкой — бесконечная дробь, которую компьютер округляет. Сумма двух округлений не равна округлению суммы:

```python
print(0.1 + 0.2)          # 0.30000000000000004
print(f"{0.1:.20f}")      # 0.10000000000000000555
```

### Как правильно сравнивать float

```python
import math

print(math.isclose(0.1 + 0.2, 0.3))       # True
print(math.isclose(0.1 + 0.2, 0.3, rel_tol=1e-9))  # True
```

### `int` произвольной точности

```python
big = 2 ** 200
print(big)                 # огромное число
print(big.bit_length())    # 201
import sys
print(sys.getsizeof(2**30))   # 32
print(sys.getsizeof(2**300))  # 52 — больше байт
```

### `Decimal` для денег

```python
from decimal import Decimal, getcontext

getcontext().prec = 10
price = Decimal("19.99")
qty = Decimal("3")
print(price * qty)         # 59.97 — точно
```

### `Fraction` для точных дробей

```python
from fractions import Fraction
print(Fraction(1, 3) + Fraction(1, 6))   # 1/2
```

### Таблица сравнения

| Тип | Точность | Скорость | Для чего |
|---|---|---|---|
| `int` | точная | быстрый | целые |
| `float` | ~15-17 знаков | очень быстрый | научные расчёты |
| `Decimal` | настраиваемая | медленнее | деньги |
| `Fraction` | точная | медленнее | дроби |

### Мини-итог

Никогда не сравнивай float через `==`. Для денег — `Decimal`. Для целых Python сам расширяет разрядность.

## 6. Строки и кодировки

- `str` — последовательность **Unicode-кодовых точек**; `bytes` — последовательность байт.
- `s.encode("utf-8")` → `bytes`; `b.decode("utf-8")` → `str`.
- `len(s)` — число символов, `len(s.encode())` — число байт (разные для кириллицы!).

```python
len("привет")                 # 6 символов
len("привет".encode("utf-8")) # 12 байт
```

- **Ошибки кодирования:** `encode(..., errors="ignore"/"replace"/"strict")`.
- Открывай файлы с явным `encoding="utf-8"`.
- Строки неизменяемы; `+=` в цикле — O(n²), используй `"".join(list)`.

### Пошаговый разбор кодировки

```python
s = "привет"
print(len(s))                 # 6 — шесть Unicode-символов
b = s.encode("utf-8")         # bytes
print(b)                      # b'\xd0\xbf\xd1\x80...' 
print(len(b))                 # 12 — кириллица по 2 байта
print(b.decode("utf-8"))      # привет
```

### Почему кириллица — 2 байта

UTF-8 кодирует ASCII (латиница) одним байтом, а большинство кириллических символов — двумя. Поэтому `len(str) != len(bytes)`.

### Обработка ошибок

```python
# ignore — просто пропустить неподходящие байты
b"\xff\xfehello".decode("utf-8", errors="ignore")   # 'hello'

# replace — заменить на символ-заглушку
b"\xff\xfehello".decode("utf-8", errors="replace")  # 'hello'

# strict (по умолчанию) — бросить UnicodeDecodeError
```

### Работа с файлами

```python
# ✅ всегда указывай кодировку
with open("data.txt", "r", encoding="utf-8") as f:
    text = f.read()

# ❌ зависит от системы (на Windows может быть cp1251)
with open("data.txt") as f:
    text = f.read()
```

### Мини-итог

`str` — про символы, `bytes` — про байты. Переход — через `encode`/`decode` с явной кодировкой (почти всегда UTF-8). Явное `encoding=` избавляет от «кракозябр».

## 7. `None`, sentinel и `type` vs `isinstance`

- `None` — единственный экземпляр `NoneType`, сравнивай через `is`.
- Для «отсутствия значения, отличного от None» используют уникальный sentinel-объект: `_MISSING = object()`.
- `type(x) is T` — строгое совпадение; `isinstance(x, T)` — учитывает наследование.
- `isinstance` принимает кортеж/`Union`: `isinstance(x, (int, float))`.

### Зачем sentinel

Иногда нужно отличить «не передано» от «передано None»:

```python
_MISSING = object()   # уникальный объект, с которым ничего не совпадёт

def get(config, key, default=_MISSING):
    if key in config:
        return config[key]
    if default is _MISSING:
        raise KeyError(key)
    return default
```

### `type` vs `isinstance`

```python
class Animal: pass
class Dog(Animal): pass

d = Dog()
print(type(d) is Dog)         # True
print(type(d) is Animal)      # False — тип именно Dog
print(isinstance(d, Animal))  # True — учитывает наследование
```

### Проблема `bool` как подкласса `int`

```python
print(isinstance(True, int))   # True — bool наследуется от int
# если это нежелательно, проверяй type(x) is int
```

### Мини-итог

`is None` — для отсутствия значения; `object()` — для sentinel; `isinstance` — когда важно наследование, `type is` — когда нужна строгая проверка.

## 8. `id()` и его подвох

`id()` возвращает адрес. **Адрес может переиспользоваться** после удаления объекта:

```python
a = [1, 2]
print(id(a))
del a
b = [3, 4]
print(id(b))   # может совпасть с прежним id(a)
```

Поэтому `id` — не «уникальный идентификатор навсегда».

### Почему адрес переиспользуется

Освобождённую память менеджер памяти отдаёт следующему объекту. Это нормально и экономит ресурсы.

```python
print(id(1) == id(1))   # True — один и тот же интернированный объект

# А вот так делать нельзя:
ids = [id(x) for x in range(5)]   # адреса временных объектов могут повториться
```

### Практический вывод

`id` годится для **отладки** («тот же это объект или нет») и для реализации интернирования, но **не** как долговременный уникальный ключ.

### Мини-итог

`id` — адрес на момент вызова. После освобождения объекта адрес может достаться другому. Не сохраняй `id` «на будущее».

## 10. Сборка мусора: краткий обзор

- **Reference counting** — основной механизм: объект удаляется при refcount = 0.
- **Циклический сборщик (gc)** — ловит циклы ссылок, которые refcount не может убрать.

```python
import gc

a = {}
b = {}
a["b"] = b
b["a"] = a        # цикл: refcount у обоих > 0, но они недостижимы
del a, b
gc.collect()      # сборщик циклов освободит память
```

### Мини-итог

Refcount + gc вместе управляют памятью. Знание этого полезно для темы «утечки памяти» (День 8).

## 12. Мини-итог дня (углублённый)

1. Объект = refcount + тип + данные; имя — ссылка на него.
2. Интернирование и small int cache — оптимизации, а не контракт.
3. `__eq__`/`__hash__` связаны контрактом; `dict`/`set` на этом держатся.
4. Истинность — `__bool__`, затем `__len__`.
5. Float неточен; для денег — `Decimal`.
6. `str` и `bytes` — разные миры, кодировка UTF-8 по умолчанию.
