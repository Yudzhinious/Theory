# День 11 — Вопросы

---

**1. Партиционирование vs шардирование?**
<details><summary>Ответ</summary>
Партиционирование делит таблицу на части внутри одного сервера БД. Шардирование распределяет данные по нескольким серверам (узлам).
</details>

**2. Зачем нужно партиционирование?**
<details><summary>Ответ</summary>
Ускоряет запросы (pruning — отбрасывание ненужных партиций), упрощает удаление старых данных (DROP PARTITION быстрее DELETE), улучшает управление.
</details>

**3. Проблемы шардирования?**
<details><summary>Ответ</summary>
Распределённые транзакции (2PC), неэффективные JOIN между шардами, перебалансировка при добавлении шарда, отсутствие глобальных уникальных ключей.
</details>

**4. Зачем репликация?**
<details><summary>Ответ</summary>
Отказоустойчивость (реплика заменяет мастер), масштабирование чтения (запросы на чтение идут на реплики), резервное копирование.
</details>

**5. Master-Slave vs Master-Master?**
<details><summary>Ответ</summary>
Master-Slave — запись только в мастер, чтение с реплик (проще). Master-Master — запись в несколько мастеров, сложнее разрешение конфликтов.
</details>

**6. Что такое CAP-теорема?**
<details><summary>Ответ</summary>
В распределённой системе можно гарантировать только два из трёх: Consistency, Availability, Partition tolerance. При разрыве сети выбирают C или A.
</details>

**7. Что такое ORM? Плюсы и минусы?**
<details><summary>Ответ</summary>
Object-Relational Mapping — работа с БД через объекты. Плюсы: меньше SQL, защита от инъекций, переносимость. Минусы: неэффективные запросы, «магия», сложность отладки.
</details>

**8. Что такое проблема N+1 и как её решить?**
<details><summary>Ответ</summary>
При обращении к связанным объектам в цикле выполняется 1 + N запросов. Решение — eager loading: `joinedload` (JOIN) или `selectinload` (отдельный запрос с IN).
</details>

**9. SQLAlchemy Core vs ORM?**
<details><summary>Ответ</summary>
Core — низкоуровневые выражения, полный контроль, результат как строки/словари. ORM — модели-классы, объекты, автоматическая синхронизация. В 2.x оба используют `select()`.
</details>

**10. Что такое миграции БД и зачем Alembic?**
<details><summary>Ответ</summary>
Версионирование схемы БД. Alembic сравнивает модели с БД, генерирует скрипты `upgrade`/`downgrade` для применения и отката изменений.
</details>

## Мини-задача
Дан `select(User)`, у каждого `User` есть `posts`. Напиши запрос без N+1.
<details><summary>Решение</summary>

```python
from sqlalchemy import select
from sqlalchemy.orm import selectinload

stmt = select(User).options(selectinload(User.posts))
users = session.scalars(stmt).all()
for u in users:
    print(u.posts)   # уже загружено
```
</details>
