# День 9 — Вопросы

---

**1. Чем процесс отличается от потока?**
<details><summary>Ответ</summary>
Процесс имеет своё адресное пространство и память, изолирован. Потоки внутри процесса делят память и требуют синхронизации. В Python у каждого процесса свой GIL.
</details>

**2. Concurrency vs Parallelism?**
<details><summary>Ответ</summary>
Concurrency — задачи прогрессируют поочерёдно (переключение), параллельность — реально одновременно на разных ядрах. В Python параллелизм даёт multiprocessing.
</details>

**3. Когда использовать `multiprocessing`?**
<details><summary>Ответ</summary>
Для CPU-интенсивных задач (расчёты, обработка данных) — процессы обходят GIL и работают на нескольких ядрах.
</details>

**4. Когда `asyncio`, а когда `threading`?**
<details><summary>Ответ</summary>
`asyncio` — много I/O-операций и высокая масштабируемость (тысячи соединений). `threading` — проще для небольшого числа I/O-задач.
</details>

**5. Что такое event loop?**
<details><summary>Ответ</summary>
Цикл событий, который управляет выполнением корутин: запускает их, переключает на `await` и возобновляет, когда I/O готов.
</details>

**6. Что такое корутина?**
<details><summary>Ответ</summary>
Функция, объявленная через `async def`, которая может приостанавливаться на `await` и возвращать управление event loop.
</details>

**7. Почему синхронный `requests.get()` внутри asyncio — плохо?**
<details><summary>Ответ</summary>
Он блокирует поток и весь event loop, останавливая другие задачи. Нужно использовать `aiohttp` или `loop.run_in_executor`.
</details>

**8. Зачем нужны Lock/Semaphore?**
<details><summary>Ответ</summary>
Для защиты критических секций при работе с общими данными в потоках — предотвращают гонки (race conditions).
</details>

**9. Что такое `concurrent.futures`?**
<details><summary>Ответ</summary>
Высокоуровневый модуль с `ThreadPoolExecutor` (I/O) и `ProcessPoolExecutor` (CPU), унифицирующий работу с пулами.
</details>

**10. Почему в multiprocessing на Windows нужен `if __name__ == "__main__"`?**
<details><summary>Ответ</summary>
Windows использует spawn — новый процесс импортирует модуль заново. Без защиты код создания процессов выполнился бы повторно, вызвав бесконечную рекурсию.
</details>

## Мини-задача
Напиши асинхронный код, который параллельно «скачивает» 3 ресурса по 1 секунде каждый — суммарно ~1 сек, а не 3.
<details><summary>Решение</summary>

```python
import asyncio

async def download(name):
    await asyncio.sleep(1)
    return f"done {name}"

async def main():
    results = await asyncio.gather(download("A"), download("B"), download("C"))
    print(results)

asyncio.run(main())   # ~1 секунда
```
</details>
