## 1. Гонки, блокировки, дедлоки

- **Race condition** — результат зависит от порядка выполнения потоков.
- **Deadlock** — потоки ждут друг друга (взаимная блокировка). Условия Коффмана: mutual exclusion, hold-and-wait, no preemption, circular wait.
- **Livelock** — потоки активны, но прогресса нет.
- **Starvation** — поток не получает ресурс.
- Правило: **минимизируй общий изменяемый стейт**; используй очереди вместо общих переменных.

```python
import threading
lock = threading.Lock()
def inc():
    global counter
    for _ in range(100_000):
        with lock:
            counter += 1
```

## 2. Примитивы синхронизации

| Примитив | Смысл |
|---|---|
| `Lock` | мьютекс (не реентерабельный) |
| `RLock` | реентерабельный (тот же поток может взять снова) |
| `Semaphore` | ограничение до N одновременно |
| `Event` | флаг-сигнал (`set`/`wait`) |
| `Condition` | ожидание условия + уведомление |
| `Barrier` | точка синхронизации N потоков |
| `Queue` | потокобезопасная очередь (лучший способ обмена) |

**Producer–consumer** через `queue.Queue`:
```python
import queue
q = queue.Queue(maxsize=10)
```

**Thread-local** — данные, свои для каждого потока:
```python
local = threading.local()
local.user = "x"
```

## 3. `multiprocessing` детали

- **Старт процессов:** `fork` (Unix, копирует память), `spawn` (Windows/macOS по умолчанию, свежий интерпретатор), `forkserver`.
- Из-за `spawn` на Windows обязателен `if __name__ == "__main__"`.
- Обмен: `Queue`, `Pipe`, `Manager` (прокси-объекты), `shared_memory`.
- Данные сериализуются через **pickle** — передавай picklable объекты.
- `Pool`/`ProcessPoolExecutor` — пул воркеров.

```python
from multiprocessing import Pool
if __name__ == "__main__":
    with Pool(4) as p:
        print(p.map(abs, [-1, -2, 3]))
```

## 4. `asyncio` изнутри

- **Event loop** управляет задачами; `await` — точка добровольной отдачи управления.
- **Coroutine → Task → Future:** корутину оборачивают в `Task`, который планируется в цикле; `Future` — «обещание» результата.
- **Блокирующий код замораживает весь цикл** → используй `run_in_executor` или async-библиотеки.

```python
import asyncio

async def main():
    results = await asyncio.gather(*tasks)      # все сразу
    async for r in asyncio.as_completed(tasks): # по мере готовности
        ...

asyncio.run(main())
```

Инструменты: `gather`, `as_completed`, `wait`, `Queue`, `Lock`, `Semaphore`, `timeout` (3.11), `TaskGroup` (3.11).

```python
async with asyncio.TaskGroup() as tg:
    tg.create_task(worker(1))
    tg.create_task(worker(2))
```

## 5. Structured concurrency и `uvloop`

- `TaskGroup` гарантирует: если одна задача падает, остальные отменяются; выход — после всех.
- **`uvloop`** — быстрая замена event loop (на C/libuv), ускоряет asyncio.

## 6. Когда что (уточнённо)

| Сценарий | Инструмент |
|---|---|
| CPU-тяжёлое | `ProcessPoolExecutor`/`multiprocessing` |
| I/O, мало задач | `threading` |
| I/O, тысячи соединений | `asyncio` |
| CPU внутри asyncio | `run_in_executor(ProcessPool)` |

Не смешивай потоки и asyncio без необходимости.
