# День 9 — Многозадачность: threading, multiprocessing, asyncio

> Цель: для любой задачи выбрать правильный инструмент и объяснить, почему.

---

## 0. Зачем вообще многозадачность

Обычная программа выполняет инструкции строго одну за другой. Если она ждёт ответа
от сети или диска, процессор простаивает. Многозадачность позволяет **перекрывать
время ожидания полезной работой**: пока одна задача ждёт данные, другая считает.

Аналогия: один повар (ядро CPU) не может одновременно резать и варить, но пока
суп варится (ожидание I/O), он нарезает салат. Это конкурентность. Если у вас
**два повара** и они режут овощи одновременно — это параллельность.

Три инструмента Python решают разные части этой задачи:

| Инструмент | Модель | Когда |
|---|---|---|
| `threading` | несколько потоков в одном процессе | I/O, простые сценарии |
| `multiprocessing` | несколько процессов | CPU-нагрузка |
| `asyncio` | один поток + событийный цикл | тысячи сетевых соединений |

---

## 1. Процесс vs Поток

- **Процесс** — экземпляр программы со своим адресным пространством и памятью. Процессы изолированы, каждый со своим интерпретатором и GIL.
- **Поток** — «лёгкая» единица внутри процесса, разделяет память с другими потоками. Требует синхронизации.

**Что это значит на практике:**

```python
# Потоки видят одну и ту же переменную:
import threading

shared = []

def append_items(n):
    for i in range(n):
        shared.append(i)          # общий список — нужна осторожность

t1 = threading.Thread(target=append_items, args=(1000,))
t2 = threading.Thread(target=append_items, args=(1000,))
t1.start(); t2.start()
t1.join(); t2.join()
print(len(shared))                # ожидаем 2000
```

```python
# Процессы получают КОПИЮ памяти — изменения не видны родителю:
from multiprocessing import Process

shared = []

def append_items(n):
    for i in range(n):
        shared.append(i)

if __name__ == "__main__":
    p = Process(target=append_items, args=(1000,))
    p.start(); p.join()
    print(len(shared))            # 0 — дочерний процесс писал в свою копию
```

| Свойство | Поток | Процесс |
|---|---|---|
| Память | общая | раздельная (копия) |
| Создание | дешёвое | дорогое |
| Обмен данными | просто (но локи) | сериализация (pickle) |
| Изоляция сбоя | нет: падение роняет всё | да |
| GIL | один на процесс | у каждого свой |
| Стек | общий объём | свой |

## 2. Concurrency vs Parallelism

- **Concurrency (конкурентность)** — несколько задач прогрессируют по очереди (asyncio, потоки).
- **Parallelism (параллельность)** — задачи реально выполняются одновременно на разных ядрах (multiprocessing).

Простой тест, чтобы не путать: конкурентность — про **структуру** программы
(много задач в процессе выполнения), параллельность — про **железо** (одновременное
исполнение на нескольких ядрах).

Аналогия: одна касса в супермаркете и очередь — это конкурентность (обслуживаем
по одному, но быстро переключаемся). Пять касс — параллельность.

> Важно: `asyncio` даёт конкурентность, но **не** параллельность. Один поток —
> одно ядро.

---

## 3. Когда что использовать

| Тип задачи | Инструмент | Почему |
|---|---|---|
| CPU-интенсивные (расчёты, ML) | `multiprocessing` | обходит GIL — у каждого процесса свой |
| I/O-интенсивные (сеть, БД, файлы) | `asyncio` или `threading` | GIL отпускается на время I/O |
| Много соединений (веб-сервер) | `asyncio` | масштабируется на тысячи задач в одном потоке |
| Простые I/O-задачи | `threading` | проще в написании, чем asyncio |

**Как определить тип задачи:** посмотрите, на что уходит время. Если на «мозги»
(вычисления) — CPU-bound. Если на «ожидание» (диск, сеть, БД) — I/O-bound.

> **GIL (Global Interpreter Lock)** — глобальная блокировка интерпретатора CPython:
> в один момент времени байт-код исполняет только один поток. Поэтому потоки не
> ускоряют чистые вычисления. Но при блокирующих операциях (I/O) GIL отпускается.

## 4. `threading`

```python
import threading, time

def worker(name, delay):
    for i in range(3):
        print(f"{name}: {i}")
        time.sleep(delay)

threads = [threading.Thread(target=worker, args=(f"T{i}", 0.3)) for i in range(3)]
for t in threads: t.start()
for t in threads: t.join()
```

Разбор:
1. Создаём три объекта `Thread`, каждому даём функцию (`target`) и аргументы (`args`).
2. `start()` запускает поток — он начинает выполняться конкурентно.
3. `join()` блокирует главный поток, пока воркер не завершится.

Пример вывода (порядок строк может отличаться — это нормально):

```text
T0: 0
T1: 0
T2: 0
T0: 1
T1: 1
T2: 1
...
```

**Синхронизация** нужна при работе с общими данными:
```python
lock = threading.Lock()
def increment():
    global counter
    for _ in range(100_000):
        with lock:          # критическая секция
            counter += 1
```

Без лока операция `counter += 1` не атомарна (чтение → сложение → запись), и два
потока могут перезаписать результат друг друга — это **race condition**.

Примитивы: `Lock`, `RLock`, `Semaphore`, `Event`, `Condition`, `Queue`.

**Как неправильно / как правильно:**

```python
# ❌ Без лока — итог меньше ожидаемого
counter = 0
def bad():
    global counter
    for _ in range(100_000):
        counter += 1          # гонка

# ✅ С локом — итог точный
counter = 0
lock = threading.Lock()
def good():
    global counter
    for _ in range(100_000):
        with lock:
            counter += 1
```

**Правило:** держите критическую секцию как можно короче — длинный лок убивает
всю выгоду от многопоточности.

## 5. `multiprocessing`

```python
from multiprocessing import Pool

def square(x): return x * x

if __name__ == "__main__":          # важно на Windows!
    with Pool(processes=4) as pool:
        print(pool.map(square, range(10)))
```

Вывод:
```text
[0, 1, 4, 9, 16, 25, 36, 49, 64, 81]
```

- `Pool` — пул процессов для `map`/`apply`.
- `Queue`, `Pipe` — обмен данными между процессами.
- `Value`, `Array`, `Manager` — общая память.
- Каждый процесс независим, GIL не мешает.

**Почему `if __name__ == "__main__"`?** На Windows процесс запускается через
`spawn` — заново импортирует модуль. Без защиты код создания пула выполнился бы
рекурсивно и породил бы бесконечное дерево процессов.

**Цена:** каждый процесс = новый интерпретатор Python (~ десятки МБ), а данные
между процессами сериализуются через `pickle`.

## 6. `asyncio` — асинхронность

Однопоточная модель на **событийном цикле**. Корутины (`async def`) добровольно отдают управление на `await` во время I/O.

```python
import asyncio

async def fetch(name, delay):
    print(f"Старт {name}")
    await asyncio.sleep(delay)       # имитация I/O — отдаём управление
    print(f"Конец {name}")
    return name

async def main():
    results = await asyncio.gather(
        fetch("A", 2),
        fetch("B", 1),
    )
    print(results)

asyncio.run(main())
```

Вывод (обратите внимание: B завершается раньше A, хотя запущен вторым):
```text
Старт A
Старт B
Конец B
Конец A
['A', 'B']
```

Разбор по шагам:
1. `asyncio.run(main())` создаёт событийный цикл и запускает `main`.
2. `gather` превращает обе корутины в `Task` и ставит их в очередь цикла.
3. Дойдя до `await asyncio.sleep`, задача отдаёт управление циклу.
4. Цикл переключается на другую готовую задачу, пока первая «спит».
5. Когда таймер истёк, задача снова готова — цикл её продолжает.

**Ключевые понятия:**
- **event loop** — цикл, управляющий корутинами;
- **coroutine** — `async def`;
- **await** — точка передачи управления;
- **Task** — обёртка для конкурентного выполнения;
- **Future** — «обещание» результата.

**Важно:** блокирующий синхронный код (например, `requests.get`) «замораживает» весь цикл. Используй `run_in_executor`:
```python
loop = asyncio.get_running_loop()
result = await loop.run_in_executor(None, blocking_func, arg)
```

> **Как неправильно:** `async def f(): return requests.get(url)` — синхронный вызов
> остановит весь цикл, остальные задачи не выполнятся, пока не придёт ответ.
> **Как правильно:** `httpx.AsyncClient` или `run_in_executor`.

## 7. `concurrent.futures` — высокоуровневый интерфейс

```python
from concurrent.futures import ThreadPoolExecutor, ProcessPoolExecutor

def task(n): return n * n

with ThreadPoolExecutor(max_workers=4) as ex:      # для I/O
    results = list(ex.map(task, range(10)))

with ProcessPoolExecutor() as ex:                  # для CPU
    results = list(ex.map(task, range(10)))
```

`concurrent.futures` — единый интерфейс `submit`/`map`/`Future` поверх и потоков,
и процессов. Меняете исполнитель — меняете модель исполнения, код вызова тот же.

```python
from concurrent.futures import ThreadPoolExecutor, as_completed

with ThreadPoolExecutor(max_workers=8) as ex:
    futures = [ex.submit(task, i) for i in range(5)]
    for fut in as_completed(futures):   # по мере готовности
        print(fut.result())
```

## 8. Сравнение

| | threading | multiprocessing | asyncio |
|---|---|---|---|
| Параллелизм CPU | нет (GIL) | да | нет |
| Модель | потоки | процессы | один поток + event loop |
| Память | общая (нужны локи) | раздельная | общая (кооперативно) |
| Накладные расходы | средние | высокие | низкие |
| Лучше для | I/O | CPU | много I/O |

**Мини-итог:**
- CPU-bound → процессы (`ProcessPoolExecutor`).
- I/O-bound, мало задач → потоки (`ThreadPoolExecutor`).
- I/O-bound, тысячи соединений → `asyncio`.
- Никогда не блокируйте событийный цикл синхронным кодом.
