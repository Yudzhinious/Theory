# День 9 — Многозадачность: threading, multiprocessing, asyncio

> Цель: для любой задачи выбрать правильный инструмент и объяснить, почему.

---

## 1. Процесс vs Поток

- **Процесс** — экземпляр программы со своим адресным пространством и памятью. Процессы изолированы, каждый со своим интерпретатором и GIL.
- **Поток** — «лёгкая» единица внутри процесса, разделяет память с другими потоками. Требует синхронизации.

---

## 2. Concurrency vs Parallelism

- **Concurrency (конкурентность)** — несколько задач прогрессируют по очереди (asyncio, потоки).
- **Parallelism (параллельность)** — задачи реально выполняются одновременно на разных ядрах (multiprocessing).

---

## 3. Когда что использовать

| Тип задачи | Инструмент | Почему |
|---|---|---|
| CPU-интенсивные (расчёты, ML) | `multiprocessing` | обходит GIL — у каждого процесса свой |
| I/O-интенсивные (сеть, БД, файлы) | `asyncio` или `threading` | GIL отпускается на время I/O |
| Много соединений (веб-сервер) | `asyncio` | масштабируется на тысячи задач в одном потоке |
| Простые I/O-задачи | `threading` | проще в написании, чем asyncio |

---

## 4. `threading`

```python
import threading, time

def worker(name, delay):
    for i in range(3):
        print(f"{name}: {i}")
        time.sleep(delay)

threads = [threading.Thread(target=worker, args=(f"T{i}", 0.3)) for i in range(3)]
for t in threads: t.start()
for t in threads: t.join()
```

**Синхронизация** нужна при работе с общими данными:
```python
lock = threading.Lock()
def increment():
    global counter
    for _ in range(100_000):
        with lock:          # критическая секция
            counter += 1
```

Примитивы: `Lock`, `RLock`, `Semaphore`, `Event`, `Condition`, `Queue`.

---

## 5. `multiprocessing`

```python
from multiprocessing import Pool

def square(x): return x * x

if __name__ == "__main__":          # важно на Windows!
    with Pool(processes=4) as pool:
        print(pool.map(square, range(10)))
```

- `Pool` — пул процессов для `map`/`apply`.
- `Queue`, `Pipe` — обмен данными между процессами.
- `Value`, `Array`, `Manager` — общая память.
- Каждый процесс независим, GIL не мешает.

---

## 6. `asyncio` — асинхронность

Однопоточная модель на **событийном цикле**. Корутины (`async def`) добровольно отдают управление на `await` во время I/O.

```python
import asyncio

async def fetch(name, delay):
    print(f"Старт {name}")
    await asyncio.sleep(delay)       # имитация I/O — отдаём управление
    print(f"Конец {name}")
    return name

async def main():
    results = await asyncio.gather(
        fetch("A", 2),
        fetch("B", 1),
    )
    print(results)

asyncio.run(main())
```

**Ключевые понятия:**
- **event loop** — цикл, управляющий корутинами;
- **coroutine** — `async def`;
- **await** — точка передачи управления;
- **Task** — обёртка для конкурентного выполнения;
- **Future** — «обещание» результата.

**Важно:** блокирующий синхронный код (например, `requests.get`) «замораживает» весь цикл. Используй `run_in_executor`:
```python
loop = asyncio.get_running_loop()
result = await loop.run_in_executor(None, blocking_func, arg)
```

---

## 7. `concurrent.futures` — высокоуровневый интерфейс

```python
from concurrent.futures import ThreadPoolExecutor, ProcessPoolExecutor

def task(n): return n * n

with ThreadPoolExecutor(max_workers=4) as ex:      # для I/O
    results = list(ex.map(task, range(10)))

with ProcessPoolExecutor() as ex:                  # для CPU
    results = list(ex.map(task, range(10)))
```

## 8. Сравнение

| | threading | multiprocessing | asyncio |
|---|---|---|---|
| Параллелизм CPU | нет (GIL) | да | нет |
| Модель | потоки | процессы | один поток + event loop |
| Память | общая (нужны локи) | раздельная | общая (кооперативно) |
| Накладные расходы | средние | высокие | низкие |
| Лучше для | I/O | CPU | много I/O |
