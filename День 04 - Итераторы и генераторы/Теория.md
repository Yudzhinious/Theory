# День 4 — Итераторы и генераторы

> Цель: понять протокол итерации, научиться писать генераторы и объяснить, зачем экономить память.

---

## 0. Как читать этот конспект

Итераторы и генераторы — тема, где важно не заучить термины, а увидеть **причинно-следственную связь**: «ленивость» экономит память, «одноразовость» — её обратная сторона. Сначала разберём протокол итерации, затем генераторы, затем практические приёмы.

Главная идея дня: **данные можно не хранить, а вычислять по одному по мере надобности**.

## 1. Итерируемое vs итератор

- **Iterable (итерируемое)** — объект, по которому можно пройти циклом `for`. Имеет `__iter__()`. Примеры: `list`, `str`, `dict`, `range`.
- **Iterator (итератор)** — объект, который выдаёт элементы по одному. Имеет `__iter__()` (возвращает себя) и `__next__()`.

```python
nums = [1, 2, 3]      # iterable
it = iter(nums)       # iterator
next(it)   # 1
next(it)   # 2
next(it)   # 3
next(it)   # StopIteration
```

Цикл `for` внутри вызывает `iter()` и затем `next()`, пока не поймает `StopIteration`.

### Аналогия

- **Итерируемое** — книга (по ней можно листать страницы).
- **Итератор** — закладка: она помнит, где ты остановился, и двигается вперёд.

### Как `for` работает под капотом

```python
nums = [1, 2, 3]

# for x in nums: ...
# эквивалентно:
it = iter(nums)          # получить итератор
while True:
    try:
        x = next(it)     # взять следующий
    except StopIteration:
        break            # закончились
    print(x)
```

### Итерируемое vs итератор

```python
lst = [1, 2, 3]
it = iter(lst)

print(hasattr(lst, "__iter__"))   # True — итерируемое
print(hasattr(it, "__next__"))    # True — итератор
print(iter(it) is it)             # True — итератор возвращает себя
```

### Типичная ошибка

```python
# ❌ Итерируемое не всегда итератор
nums = [1, 2, 3]
# next(nums)     # TypeError: 'list' object is not an iterator

# ✅ сначала получить итератор
it = iter(nums)
print(next(it))  # 1
```

### Мини-итог

Итерируемое умеет отдавать итератор; итератор помнит позицию и отдаёт элементы по одному. `for` — это синтаксический сахар над `iter`/`next`/`StopIteration`.

## 2. Свой итератор

```python
class Countdown:
    def __init__(self, start):
        self.current = start
    def __iter__(self):
        return self
    def __next__(self):
        if self.current <= 0:
            raise StopIteration
        self.current -= 1
        return self.current + 1

list(Countdown(3))   # [3, 2, 1]
```

### Пошаговый разбор

```python
class Countdown:
    def __init__(self, start):
        self.current = start

    def __iter__(self):
        return self          # итератор — сам объект

    def __next__(self):
        if self.current <= 0:
            raise StopIteration   # сигнал «элементы закончились»
        self.current -= 1
        return self.current + 1

cd = Countdown(3)
print(next(cd))   # 3
print(next(cd))   # 2
print(next(cd))   # 1
# next(cd)        # StopIteration
```

### Ловушка: итератор одноразовый

```python
cd = Countdown(3)
print(list(cd))   # [3, 2, 1]
print(list(cd))   # [] — итератор уже исчерпан
```

### Как сделать многоразовый

```python
class CountdownIterable:
    def __init__(self, start):
        self.start = start
    def __iter__(self):
        current = self.start          # новое состояние на каждый обход
        while current > 0:
            yield current
            current -= 1

c = CountdownIterable(3)
print(list(c))   # [3, 2, 1]
print(list(c))   # [3, 2, 1] — можно снова!
```

### Мини-итог

Свой итератор — класс с `__iter__` и `__next__`. Если `__iter__` возвращает новый генератор/итератор, объект становится многоразовым.

## 3. Генераторы: `yield`

Функция с `yield` возвращает **генератор** — ленивый итератор. При каждом `next()` выполнение продолжается с места последнего `yield`.

```python
def count_up_to(n):
    i = 0
    while i < n:
        yield i
        i += 1

g = count_up_to(3)
list(g)   # [0, 1, 2]
```

**Главное преимущество:** элементы не хранятся в памяти, а вычисляются по требованию. Идеально для больших/бесконечных последовательностей.

```python
sum(x*x for x in range(10_000_000))   # без создания огромного списка
```

### Пошаговое выполнение генератора

```python
def count_up_to(n):
    print("старт")
    i = 0
    while i < n:
        yield i          # пауза: отдаём значение наружу
        print("продолжение", i)
        i += 1

g = count_up_to(3)
print(next(g))   # старт / 0
print(next(g))   # продолжение 0 / 1
print(next(g))   # продолжение 1 / 2
# next(g)        # продолжение 2 / StopIteration
```

Видно, что функция **приостанавливается** на `yield` и продолжает с того же места.

### `yield` vs `return`

| | `return` | `yield` |
|---|---|---|
| Результат | одно значение | поток значений |
| Функция | завершается | приостанавливается |
| Тип результата | само значение | генератор |

### Экономия памяти

```python
import sys

def gen(n):
    for i in range(n):
        yield i

lst = [i for i in range(1_000_000)]
g = gen(1_000_000)

print(sys.getsizeof(lst))   # ~8 МБ (список)
print(sys.getsizeof(g))     # ~200 байт (генератор!)
```

### Бесконечный генератор

```python
def naturals():
    n = 0
    while True:      # бесконечный цикл — но генератор ленивый
        yield n
        n += 1

from itertools import islice
print(list(islice(naturals(), 5)))   # [0, 1, 2, 3, 4]
```

### Мини-итог

Генератор — функция, которая «замирает» на `yield`. Он ленив: значения вычисляются по требованию, поэтому память почти не тратится.

## 4. Генераторные выражения vs list comprehension

| | `[x for x in ...]` | `(x for x in ...)` |
|---|---|---|
| Тип | `list` | `generator` |
| Вычисление | сразу (жадное) | ленивое |
| Память | вся коллекция | один элемент |
| Повторная итерация | да | нет (одноразовый) |
| Индексация/срезы | да | нет |

```python
g = (x for x in range(3))
list(g)   # [0, 1, 2]
list(g)   # [] — генератор исчерпан
```

### Наглядное сравнение памяти

```python
import sys

list_comp = [x * x for x in range(1_000_000)]
gen_exp = (x * x for x in range(1_000_000))

print(sys.getsizeof(list_comp))   # ~8 МБ
print(sys.getsizeof(gen_exp))     # ~200 байт
```

### Одноразовость

```python
g = (x for x in range(3))
print(list(g))   # [0, 1, 2]
print(list(g))   # [] — уже пусто

# ✅ если нужно несколько раз — сделай список или новую фабрику
data = list(x for x in range(3))
```

### Когда что выбирать

| Задача | Выбор |
|---|---|
| Нужно много раз обходить | список |
| Нужны индексы/срезы | список |
| Большие/бесконечные данные | генератор |
| Передача в `sum`/`any`/`all` | генератор |

### Мини-итог

Скобки решают всё: `[...]` — список (жадный), `(...)` — генератор (ленивый, одноразовый). Генератор экономит память, но не терпит повторного обхода.

## 5. `yield from` и методы генератора

**`yield from`** делегирует другому итерируемому:
```python
def chain(*its):
    for it in its:
        yield from it

list(chain([1, 2], (3, 4), "ab"))   # [1, 2, 3, 4, 'a', 'b']
```

**`.send(value)`** — передать значение внутрь генератора:
```python
def echo():
    while True:
        received = yield
        print("Получено:", received)

g = echo()
next(g)          # инициализация до первого yield
g.send("hi")     # Получено: hi
```

**`.throw()`** — бросить исключение в точке `yield`; **`.close()`** — закрыть генератор.

### `yield from` вместо цикла

```python
# Без yield from
def chain(*its):
    for it in its:
        for x in it:
            yield x

# С yield from — короче
def chain(*its):
    for it in its:
        yield from it

print(list(chain([1, 2], [3, 4])))   # [1, 2, 3, 4]
```

### `send` — двусторонняя связь

```python
def accumulator():
    total = 0
    while True:
        x = yield total   # отдаём total, получаем x
        if x is None:
            break
        total += x

acc = accumulator()
next(acc)          # 0 — инициализация
print(acc.send(5)) # 5
print(acc.send(3)) # 8
```

> Важно: перед первым `send` нужно вызвать `next()` (или `send(None)`), чтобы генератор дошёл до `yield`.

### `throw` и `close`

```python
def gen():
    try:
        yield 1
        yield 2
    except ValueError:
        print("поймали ValueError")
    finally:
        print("закрываемся")

g = gen()
print(next(g))       # 1
g.throw(ValueError)  # поймали ValueError / закрываемся
```

### Мини-итог

`yield from` делегирует итерируемое, `send` позволяет «говорить» с генератором, `throw`/`close` управляют его завершением. Это основа корутин.

## 6. `itertools` — полезные инструменты

```python
from itertools import islice, count, chain, cycle, product, groupby

list(islice(count(), 5))          # [0, 1, 2, 3, 4]  (ленивый срез!)
list(product([1, 2], "ab"))       # [(1,'a'), (1,'b'), (2,'a'), (2,'b')]
```

> Срез по генератору напрямую не работает (`gen[2:5]` — ошибка). Используй `itertools.islice`.

### Часто используемые функции

```python
from itertools import count, cycle, repeat, islice, chain, product

print(list(islice(count(10, 2), 3)))    # [10, 12, 14] — с 10, шаг 2
print(list(islice(cycle("ab"), 5)))     # ['a', 'b', 'a', 'b', 'a']
print(list(repeat("x", 3)))             # ['x', 'x', 'x']
print(list(chain([1], [2, 3])))         # [1, 2, 3]
print(list(product([1, 2], "ab")))      # [(1,'a'), (1,'b'), (2,'a'), (2,'b')]
```

### `islice` — срез для итераторов

```python
from itertools import islice

def naturals():
    n = 0
    while True:
        yield n
        n += 1

print(list(islice(naturals(), 2, 5)))   # [2, 3, 4]
```

### `groupby` требует сортировки

```python
from itertools import groupby

data = [("a", 1), ("a", 2), ("b", 3), ("a", 4)]
for key, group in groupby(data, key=lambda x: x[0]):
    print(key, list(group))
# a [('a', 1), ('a', 2)]
# b [('b', 3)]
# a [('a', 4)]   ← 'a' снова отдельно, т.к. не отсортировано!
```

### Мини-итог

`itertools` — набор ленивых инструментов: бесконечные генераторы, срезы (`islice`), комбинаторика. Помни: `islice` — вместо срезов, `groupby` требует сортировки.

## 7. Генераторы в реальном коде

- Чтение больших файлов построчно:
  ```python
  def read_lines(path):
      with open(path) as f:
          for line in f:
              yield line.strip()
  ```
- Пайплайны обработки данных без загрузки всего в память.
- Бесконечные последовательности.

### Построчное чтение файла

```python
def read_lines(path):
    with open(path, encoding="utf-8") as f:
        for line in f:
            yield line.strip()

# Файл на гигабайт читается без загрузки в память
for line in read_lines("huge.txt"):
    if "ERROR" in line:
        print(line)
```

### Ленивый конвейер

```python
def read_numbers(path):
    with open(path) as f:
        for line in f:
            yield int(line)

def only_even(nums):
    for n in nums:
        if n % 2 == 0:
            yield n

def squared(nums):
    for n in nums:
        yield n * n

# Конвейер: ничего не выполняется, пока не начнём обход
pipeline = squared(only_even(read_numbers("data.txt")))
for value in pipeline:
    print(value)
```

### Мини-итог

Генераторы превращают обработку больших данных в поток с постоянной памятью. Конвейеры из генераторов — идиоматичный способ обработки.

## 9. Частые ошибки (сводка)

```python
# ❌ 1. Повторный обход генератора
g = (x for x in range(3))
list(g)   # [0, 1, 2]
list(g)   # []

# ✅
data = list(x for x in range(3))

# ❌ 2. Срез генератора
# g[1:3]          # TypeError

# ✅
from itertools import islice
list(islice(g, 1, 3))

# ❌ 3. len генератора
# len(g)          # TypeError

# ✅
sum(1 for _ in g)  # подсчёт вручную

# ❌ 4. Возврат значения через return в генераторе
def g():
    yield 1
    return 5       # это НЕ значение генератора, а StopIteration.value
```

## 10. Мини-итог дня

1. Итерируемое даёт итератор; итератор помнит позицию.
2. `for` = `iter` + `next` + обработка `StopIteration`.
3. Генератор — ленивая функция с `yield`, экономит память.
4. `(...)` — генератор, `[...]` — список.
5. `yield from` делегирует, `send`/`throw`/`close` управляют генератором.
6. `itertools` даёт `islice`, `count`, `chain`, `groupby` и др.
7. Генератор одноразовый и без `len`/индексов.

**Связка:** comprehension из Дня 2 и `itertools` — мост к асинхронности и конвейерам обработки данных.
