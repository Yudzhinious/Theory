> Генератор — не «функция со списком», а объект с собственным кадром выполнения. Понимание этого уровня объясняет `send`/`throw`/`yield from` и связь с корутинами.

## 1. Протокол итерации изнутри

- **Iterable** реализует `__iter__()` → возвращает итератор.
- **Iterator** реализует `__iter__()` (возвращает себя) и `__next__()`.
- `for` вызывает `iter()`, затем `next()`, ловя `StopIteration`.

```python
it = iter([1, 2, 3])
while True:
    try:
        x = next(it)
    except StopIteration:
        break
```

### Формальное определение

```python
from collections.abc import Iterable, Iterator

print(isinstance([1, 2], Iterable))     # True
print(isinstance([1, 2], Iterator))     # False — список не итератор
print(isinstance(iter([1, 2]), Iterator))  # True
```

### Полный цикл вручную

```python
data = [10, 20, 30]
it = iter(data)          # __iter__

while True:
    try:
        value = next(it)  # __next__
    except StopIteration:
        break             # конец
    print(value)
# 10 / 20 / 30
```

### Мини-итог

Протокол итерации — два метода: `__iter__` (дать итератор) и `__next__` (дать следующий элемент или бросить `StopIteration`). `for` — обёртка над этим протоколом.

## 2. Состояние генератора

Генератор — это функция с `yield`, при вызове возвращающая объект-генератор. Он хранит **кадр (frame)** с локальными переменными и позицией.

```python
import inspect
def g():
    yield 1

gen = g()
inspect.getgeneratorstate(gen)   # 'GEN_CREATED'
next(gen)
inspect.getgeneratorstate(gen)   # 'GEN_SUSPENDED'
```

`gen.gi_frame`, `gen.gi_running` — детали для отладки.

### Четыре состояния

| Состояние | Значение |
|---|---|
| `GEN_CREATED` | создан, ещё не запущен |
| `GEN_RUNNING` | выполняется прямо сейчас |
| `GEN_SUSPENDED` | приостановлен на `yield` |
| `GEN_CLOSED` | завершён или закрыт |

```python
import inspect

def g():
    yield 1
    yield 2

gen = g()
print(inspect.getgeneratorstate(gen))   # GEN_CREATED
next(gen)
print(inspect.getgeneratorstate(gen))   # GEN_SUSPENDED
next(gen)
next(gen, None)                          # StopIteration
print(inspect.getgeneratorstate(gen))   # GEN_CLOSED
```

### Кадр генератора

```python
def g():
    x = 10
    yield x

gen = g()
next(gen)
frame = gen.gi_frame
print(frame.f_locals)   # {'x': 10} — локальные переменные сохранены
```

### Мини-итог

Генератор хранит кадр с локальными переменными и точкой выполнения. Именно поэтому он может «проснуться» и продолжить с того же места.

## 3. `send`, `throw`, `close`, `yield from`

```python
def echo():
    total = 0
    while True:
        x = yield total     # получаем значение через send
        total += x

g = echo()
next(g)          # 0 — инициализация
g.send(5)        # 5
g.send(3)        # 8
```

- **`.throw(exc)`** — бросить исключение в точке `yield`.
- **`.close()`** — вызвать `GeneratorExit`.
- **`yield from`** делегирует итерируемому и **возвращает** его `StopIteration.value`:

```python
def sub():
    yield 1
    return "done"

def main():
    result = yield from sub()   # result == "done"
    print(result)
```

**PEP 479:** `StopIteration`, вылетевший из генератора, превращается в `RuntimeError` — используй `return`.

### `send` пошагово

```python
def echo():
    total = 0
    while True:
        x = yield total
        total += x

g = echo()
print(next(g))       # 0 — дошли до первого yield
print(g.send(5))     # 5 — x=5, total=5
print(g.send(3))     # 8 — x=3, total=8
```

### `close` и `GeneratorExit`

```python
def gen():
    try:
        yield 1
        yield 2
    finally:
        print("очистка ресурсов")

g = gen()
print(next(g))   # 1
g.close()        # очистка ресурсов
```

### `yield from` возвращает значение

```python
def sub():
    yield 1
    yield 2
    return "итог"

def main():
    result = yield from sub()
    print("получено:", result)

list(main())     # получено: итог
```

### PEP 479

```python
def bad():
    raise StopIteration   # ❌ внутри генератора превратится в RuntimeError

# ✅ используй return
def good():
    return
```

### Мини-итог

`send` — двусторонний канал, `throw`/`close` — управление завершением, `yield from` — делегирование с возвратом значения. Всё это делает генераторы основой корутин.

## 4. Ленивые пайплайны

Генераторы позволяют строить конвейеры без загрузки данных в память:

```python
def read(path):
    with open(path) as f:
        yield from f

lines = (line.strip() for line in read("big.txt"))
non_empty = (l for l in lines if l)
for l in non_empty:
    ...
```

Обработка миллиона строк при O(1) памяти.

### Разбор конвейера

```python
def read(path):
    with open(path, encoding="utf-8") as f:
        yield from f            # отдаём строки по одной

lines = (line.strip() for line in read("big.txt"))
non_empty = (line for line in lines if line)
lengths = (len(line) for line in non_empty)

total = sum(lengths)            # запускает весь конвейер
print(total)
```

Каждый этап обрабатывает по одному элементу — память не зависит от размера файла.

### Преимущества и цена

| Плюс | Минус |
|---|---|
| O(1) память | сложнее отлаживать |
| Работа с бесконечными данными | одноразовость |
| Естественная композиция | нужен `list()` для повторного обхода |

### Мини-итог

Конвейеры из генераторов — идиома обработки больших данных. Каждый этап ленив, поэтому память постоянна.

## 5. `itertools` — глубже

| Функция | Назначение |
|---|---|
| `count`, `cycle`, `repeat` | бесконечные/повторяющиеся |
| `chain`, `chain.from_iterable` | конкатенация |
| `islice` | ленивый срез |
| `groupby` | группировка по ключу (требует сортировки) |
| `accumulate` | накопительные суммы |
| `product`, `permutations`, `combinations` | комбинаторика |
| `tee` | разветвление итератора |
| `zip_longest`, `takewhile`, `dropwhile`, `starmap` | утилиты |

```python
from itertools import accumulate, groupby, islice, count
list(accumulate([1, 2, 3]))          # [1, 3, 6]
list(islice(count(10, 2), 3))        # [10, 12, 14]
```

`groupby` объединяет **подряд идущие** одинаковые ключи — сначала сортируй.

### `accumulate` с функцией

```python
from itertools import accumulate
import operator

print(list(accumulate([1, 2, 3, 4])))                       # [1, 3, 6, 10]
print(list(accumulate([1, 2, 3, 4], operator.mul)))         # [1, 2, 6, 24]
```

### `groupby` и сортировка

```python
from itertools import groupby

data = [("b", 2), ("a", 1), ("a", 3), ("b", 5)]
data.sort(key=lambda x: x[0])   # обязательно отсортировать
for key, group in groupby(data, key=lambda x: x[0]):
    print(key, list(group))
# a [('a', 1), ('a', 3)]
# b [('b', 2), ('b', 5)]
```

### `tee` — разветвление

```python
from itertools import tee

it = iter([1, 2, 3])
a, b = tee(it)
print(list(a))   # [1, 2, 3]
print(list(b))   # [1, 2, 3] — независимые копии
```

> `tee` буферизует элементы, поэтому не увлекайся ветвлением.

### Комбинаторика

```python
from itertools import permutations, combinations, product

print(list(permutations("ab")))     # [('a','b'), ('b','a')]
print(list(combinations("abc", 2))) # [('a','b'), ('a','c'), ('b','c')]
print(list(product([0, 1], repeat=2)))  # [(0,0),(0,1),(1,0),(1,1)]
```

### Мини-итог

`itertools` — стандартный набор ленивых строительных блоков. Помни особенности: `groupby` требует сортировки, `tee` буферизует.

## 6. Генераторы vs корутины

- **Генератор** отдаёт значения наружу (`yield`).
- **Корутина** (`async def`) может приостанавливаться на `await`, отдавая управление event loop.
- **Async-генератор** сочетает: `async def` + `yield`, обходится через `async for`.

```python
async def agen():
    for i in range(3):
        await asyncio.sleep(0)
        yield i

async def main():
    async for x in agen():
        print(x)
```

### Сравнительная таблица

| | Генератор | Корутина | Async-генератор |
|---|---|---|---|
| Ключевые слова | `def` + `yield` | `async def` + `await` | `async def` + `yield` |
| Обход | `for` | `await` | `async for` |
| Управление | вызывающий | event loop | event loop |
| Задача | поток данных | конкурентность | поток async-данных |

### `yield` как основа корутин

Исторически корутины выросли из генераторов: `yield` позволял приостановить функцию. `async`/`await` — это синтаксический сахар над тем же механизмом.

### Мини-итог

Генератор — про поток значений, корутина — про конкурентное ожидание. Async-генератор соединяет оба: асинхронно отдаёт поток значений.

## 7. Генераторы как контекстные менеджеры

`@contextmanager` строит контекстный менеджер из генератора: код до `yield` — вход, после — выход.

```python
from contextlib import contextmanager

@contextmanager
def tag(name):
    print(f"<{name}>")
    try:
        yield
    finally:
        print(f"</{name}>")
```

### Использование

```python
from contextlib import contextmanager

@contextmanager
def tag(name):
    print(f"<{name}>")
    try:
        yield
    finally:
        print(f"</{name}>")

with tag("div"):
    print("содержимое")
# <div>
# содержимое
# </div>
```

### С возвратом значения

```python
from contextlib import contextmanager

@contextmanager
def opened(path):
    f = open(path, "w", encoding="utf-8")
    try:
        yield f
    finally:
        f.close()

with opened("out.txt") as f:
    f.write("привет")
```

### Почему `try/finally`

Если внутри `with` произойдёт исключение, `finally` гарантирует освобождение ресурса — ровно как у классовых контекстных менеджеров.

### Мини-итог

`@contextmanager` — элегантный способ писать контекстные менеджеры генератором: до `yield` — захват ресурса, после — освобождение.

## 8. Одноразовость и ловушки

- Генератор **одноразовый** — после исчерпания пуст.
- Нельзя индексировать/срезать; для среза — `islice`.
- Нельзя узнать `len` заранее.
- Если нужно переиспользовать — сделай список или фабрику-функцию.

### Демонстрация

```python
g = (x for x in range(3))
print(list(g))   # [0, 1, 2]
print(list(g))   # [] — исчерпан

# ❌
# g[0]           # TypeError
# len(g)         # TypeError
```

### Срез через islice

```python
from itertools import islice

g = (x for x in range(10))
print(list(islice(g, 2, 5)))   # [2, 3, 4]
```

### Подсчёт без len

```python
g = (x for x in range(5))
count = sum(1 for _ in g)
print(count)   # 5
```

### Как переиспользовать

```python
# Фабрика — каждый вызов даёт свежий генератор
def make_gen():
    return (x for x in range(3))

print(list(make_gen()))   # [0, 1, 2]
print(list(make_gen()))   # [0, 1, 2]
```

### Мини-итог

Одноразовость — плата за ленивость. Если нужен повторный доступ или длина — материализуй в список.
