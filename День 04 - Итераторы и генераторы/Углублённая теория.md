## 1. Протокол итерации изнутри

- **Iterable** реализует `__iter__()` → возвращает итератор.
- **Iterator** реализует `__iter__()` (возвращает себя) и `__next__()`.
- `for` вызывает `iter()`, затем `next()`, ловя `StopIteration`.

```python
it = iter([1, 2, 3])
while True:
    try:
        x = next(it)
    except StopIteration:
        break
```

## 2. Состояние генератора

Генератор — это функция с `yield`, при вызове возвращающая объект-генератор. Он хранит **кадр (frame)** с локальными переменными и позицией.

```python
import inspect
def g():
    yield 1

gen = g()
inspect.getgeneratorstate(gen)   # 'GEN_CREATED'
next(gen)
inspect.getgeneratorstate(gen)   # 'GEN_SUSPENDED'
```

`gen.gi_frame`, `gen.gi_running` — детали для отладки.

## 3. `send`, `throw`, `close`, `yield from`

```python
def echo():
    total = 0
    while True:
        x = yield total     # получаем значение через send
        total += x

g = echo()
next(g)          # 0 — инициализация
g.send(5)        # 5
g.send(3)        # 8
```

- **`.throw(exc)`** — бросить исключение в точке `yield`.
- **`.close()`** — вызвать `GeneratorExit`.
- **`yield from`** делегирует итерируемому и **возвращает** его `StopIteration.value`:

```python
def sub():
    yield 1
    return "done"

def main():
    result = yield from sub()   # result == "done"
    print(result)
```

**PEP 479:** `StopIteration`, вылетевший из генератора, превращается в `RuntimeError` — используй `return`.

## 4. Ленивые пайплайны

Генераторы позволяют строить конвейеры без загрузки данных в память:

```python
def read(path):
    with open(path) as f:
        yield from f

lines = (line.strip() for line in read("big.txt"))
non_empty = (l for l in lines if l)
for l in non_empty:
    ...
```

Обработка миллиона строк при O(1) памяти.

## 5. `itertools` — глубже

| Функция | Назначение |
|---|---|
| `count`, `cycle`, `repeat` | бесконечные/повторяющиеся |
| `chain`, `chain.from_iterable` | конкатенация |
| `islice` | ленивый срез |
| `groupby` | группировка по ключу (требует сортировки) |
| `accumulate` | накопительные суммы |
| `product`, `permutations`, `combinations` | комбинаторика |
| `tee` | разветвление итератора |
| `zip_longest`, `takewhile`, `dropwhile`, `starmap` | утилиты |

```python
from itertools import accumulate, groupby, islice, count
list(accumulate([1, 2, 3]))          # [1, 3, 6]
list(islice(count(10, 2), 3))        # [10, 12, 14]
```

`groupby` объединяет **подряд идущие** одинаковые ключи — сначала сортируй.

## 6. Генераторы vs корутины

- **Генератор** отдаёт значения наружу (`yield`).
- **Корутина** (`async def`) может приостанавливаться на `await`, отдавая управление event loop.
- **Async-генератор** сочетает: `async def` + `yield`, обходится через `async for`.

```python
async def agen():
    for i in range(3):
        await asyncio.sleep(0)
        yield i

async def main():
    async for x in agen():
        print(x)
```

## 7. Генераторы как контекстные менеджеры

`@contextmanager` строит контекстный менеджер из генератора: код до `yield` — вход, после — выход.

```python
from contextlib import contextmanager

@contextmanager
def tag(name):
    print(f"<{name}>")
    try:
        yield
    finally:
        print(f"</{name}>")
```

## 8. Одноразовость и ловушки

- Генератор **одноразовый** — после исчерпания пуст.
- Нельзя индексировать/срезать; для среза — `islice`.
- Нельзя узнать `len` заранее.
- Если нужно переиспользовать — сделай список или фабрику-функцию.
