# День 5 — Вопросы

---

**1. Что такое декоратор?**
<details><summary>Ответ</summary>
Функция, принимающая функцию и возвращающая новую функцию-обёртку. `@deco` — синтаксический сахар для `f = deco(f)`. Позволяет добавить поведение, не меняя код функции.
</details>

**2. Зачем нужен `functools.wraps`?**
<details><summary>Ответ</summary>
Чтобы обёртка сохранила метаданные исходной функции: `__name__`, `__doc__`, `__annotations__`. Без него `func.__name__` будет `wrapper`.
</details>

**3. Как написать декоратор с параметром?**
<details><summary>Ответ</summary>
Три уровня: внешняя функция принимает параметры и возвращает декоратор; декоратор принимает функцию и возвращает обёртку.
</details>

**4. В каком порядке применяются декораторы в цепочке?**
```python
@A
@B
def f(): ...
```
<details><summary>Ответ</summary>
Снизу вверх: `f = A(B(f))`. Сначала применяется `B`, затем `A`.
</details>

**5. Что такое контекстный менеджер?**
<details><summary>Ответ</summary>
Объект с методами `__enter__`/`__exit__`, используемый в `with` для гарантированного освобождения ресурсов (файлы, соединения, блокировки, транзакции).
</details>

**6. Как подавить исключение в `__exit__`?**
<details><summary>Ответ</summary>
Вернуть `True` из `__exit__`. Если вернуть `False`/`None` — исключение пробросится дальше.
</details>

**7. Чем `@contextmanager` отличается от класса?**
<details><summary>Ответ</summary>
`@contextmanager` пишется как генератор: до `yield` — вход, после — выход. Короче, но менее гибко, чем класс (нет состояния/нескольких методов).
</details>

**8. Что делает `contextlib.suppress`?**
<details><summary>Ответ</summary>
Подавляет указанные исключения внутри блока `with`, не прерывая программу.
</details>

**9. Реализуй декоратор `@debug`, печатающий аргументы и результат.**
<details><summary>Ответ</summary>

```python
from functools import wraps
def debug(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        print(f"{func.__name__}{args} {kwargs}")
        result = func(*args, **kwargs)
        print(f"-> {result}")
        return result
    return wrapper
```
</details>

**10. Почему `with open(...)` лучше, чем `f = open(...); f.close()`?**
<details><summary>Ответ</summary>
`with` закроет файл даже при исключении (через `__exit__`), исключая утечки ресурсов. Ручной `close()` можно случайно пропустить.
</details>

## Мини-задача
Напиши контекстный менеджер `@contextmanager def temp_env(**kw)`, который временно меняет переменные окружения и восстанавливает их после выхода.
<details><summary>Решение</summary>

```python
import os
from contextlib import contextmanager

@contextmanager
def temp_env(**kw):
    old = dict(os.environ)
    os.environ.update({k: str(v) for k, v in kw.items()})
    try:
        yield
    finally:
        os.environ.clear()
        os.environ.update(old)
```
</details>
