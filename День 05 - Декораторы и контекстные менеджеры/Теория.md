# День 5 — Декораторы и контекстные менеджеры

> Цель: уметь написать декоратор и контекстный менеджер с нуля и объяснить, как они работают.

---

## 0. Коротко о главном

- **Декоратор** — это функция (или класс), которая принимает другую функцию и возвращает новую, расширяя её поведение, не меняя исходный код.
- **Контекстный менеджер** — объект, который управляет ресурсом (файл, соединение, блокировка) и гарантирует очистку через `with`.
- Обе темы основаны на одном: **функции — это объекты**, их можно передавать, возвращать и хранить.

Аналогия: декоратор — это чехол для телефона. Телефон (функция) остаётся тем же, но теперь у него появились новые свойства (защита, подставка). Чехол надевается один раз при объявлении.

## 1. Что такое декоратор

Декоратор — функция, которая принимает функцию и возвращает новую (обёртку). Синтаксис `@deco` — это сахар для `func = deco(func)`.

```python
import time
from functools import wraps

def timer(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"{func.__name__}: {time.perf_counter() - start:.4f}s")
        return result
    return wrapper

@timer
def slow_sum(n):
    return sum(range(n))

slow_sum(1_000_000)
```

**Пример вывода:**
```
slow_sum: 0.0231s
```

### Что произошло по шагам

1. Интерпретатор встречает `@timer` над `slow_sum`.
2. Вызывает `timer(slow_sum)` — передаёт **саму функцию**, не её результат.
3. `timer` создаёт внутри функцию `wrapper` и возвращает её.
4. Имя `slow_sum` теперь указывает на `wrapper`.
5. Когда мы пишем `slow_sum(1_000_000)`, на самом деле вызывается `wrapper(1_000_000)`, а тот внутри вызывает исходную функцию и печатает время.

### Разбор строки `def wrapper(*args, **kwargs)`

- `*args` собирает позиционные аргументы в кортеж.
- `**kwargs` собирает именованные в словарь.
- Благодаря им обёртка подходит под **любую** функцию, а не под конкретную сигнатуру.
- Затем они «распаковываются» при вызове: `func(*args, **kwargs)`.

### Почему нужен `return result`

Если забыть `return result`, функция вернёт `None`. Это одна из самых частых ошибок в самодельных декораторах.

```python
def bad_deco(func):
    def wrapper(*a, **k):
        func(*a, **k)      # результат потерян
    return wrapper

@bad_deco
def add(a, b):
    return a + b

print(add(2, 3))   # None — ошибка!
```

**Зачем `@wraps`:** без него обёртка подменяет `__name__`, `__doc__`, аннотации исходной функции. `wraps` копирует метаданные.

```python
import functools

def deco(func):
    def wrapper(*a, **k):
        """Это докстринг обёртки."""
        return func(*a, **k)
    return wrapper

@deco
def original():
    """Докстринг оригинала."""
    return 42

print(original.__name__)   # 'wrapper' — потеряли имя!
print(original.__doc__)    # 'Это докстринг обёртки.'
```

С `@wraps(func)` внутри — `original.__name__` останется `'original'`. Это важно для отладки, документации, IDE и фреймворков, которые читают метаданные.

## 2. Декоратор с аргументами

Нужен дополнительный уровень вложенности: внешняя функция принимает параметры и возвращает декоратор.

```python
from functools import wraps

def repeat(times):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            for _ in range(times):
                result = func(*args, **kwargs)
            return result
        return wrapper
    return decorator

@repeat(3)
def greet(name):
    print(f"Привет, {name}!")

greet("Аня")   # напечатает 3 раза
```

**Пример вывода:**
```
Привет, Аня!
Привет, Аня!
Привет, Аня!
```

Порядок вызовов: `repeat(3)` → `decorator` → `wrapper`.

### Почему три уровня

- Уровень 1 — `repeat(times)`: принимает настройки декоратора.
- Уровень 2 — `decorator(func)`: принимает саму функцию.
- Уровень 3 — `wrapper(*args)`: вызывается вместо исходной функции.

Когда пишут `@repeat(3)`, сначала выполняется `repeat(3)` и получается `decorator`. Затем `decorator` применяется к `greet`. То есть `greet = repeat(3)(greet)`.

### Аналогия

Это как настройка перед покупкой: «повтори 3 раза» — это заказ, `decorator` — официант, который берёт заказ, а `wrapper` — блюдо, которое готовится именно так.

## 3. Цепочка декораторов

Применяются **снизу вверх**:

```python
@deco_A
@deco_B
def f(): ...
# эквивалентно: f = deco_A(deco_B(f))
```

Сначала оборачивает `deco_B`, затем `deco_A`.

**При вызове** функции порядок обратный: сначала сработает код «до» из `deco_A` (он снаружи), потом из `deco_B`, потом сама `f`. После возврата — сначала «после» у `deco_B`, затем у `deco_A`.

```python
def a(func):
    def wrapper(*args, **kw):
        print("A: вход")
        res = func(*args, **kw)
        print("A: выход")
        return res
    return wrapper

def b(func):
    def wrapper(*args, **kw):
        print("B: вход")
        res = func(*args, **kw)
        print("B: выход")
        return res
    return wrapper

@a
@b
def work():
    print("работа")

work()
```

**Вывод:**
```
A: вход
B: вход
работа
B: выход
A: выход
```

Вложенность напоминает матрёшку: `A` снаружи, `B` внутри, а `work` — в самом центре.

## 4. Классические применения

- логирование и замер времени;
- кэширование (`@functools.lru_cache`);
- проверка прав/аутентификация;
- повторные попытки (retry);
- регистрация функций (роуты во фреймворках: `@app.get("/")`).

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    return n if n < 2 else fib(n-1) + fib(n-2)
```

Без кэша `fib(35)` делал бы миллионы вызовов. С `lru_cache` каждый `n` считается один раз, и сложность падает с `O(2^n)` до `O(n)`.

**Типичные ошибки:**

- `@lru_cache` **требует хешируемых** аргументов: списки и словари передавать нельзя (нужен кортеж).
- Кэш хранит ссылки на аргументы и результаты, поэтому для больших данных он может «съесть» память — задавайте `maxsize`.

```python
@lru_cache(maxsize=128)
def get_user(user_id):
    ...
```

**Сравнение применений:**

| Применение | Инструмент | Что даёт |
|---|---|---|
| Замер времени | свой `timer` | метрики |
| Кэш | `lru_cache`/`cache` | ускорение |
| Права | свой `@requires_role` | безопасность |
| Retry | `@retry` / `tenacity` | устойчивость |
| Роуты | `@app.get` | регистрация |

## 5. Контекстный менеджер

Объект, управляющий ресурсом через `with`. Реализует `__enter__` и `__exit__`.

```python
with open("file.txt") as f:
    data = f.read()
# файл гарантированно закрыт, даже при исключении
```

**Протокол:**
- `__enter__(self)` — вызывается при входе, результат попадает в переменную после `as`.
- `__exit__(self, exc_type, exc_val, exc_tb)` — вызывается при выходе; если вернуть `True`, исключение **подавляется**.

### Зачем это нужно

Без `with` приходится писать `try/finally`:

```python
f = open("file.txt")
try:
    data = f.read()
finally:
    f.close()
```

`with` делает то же самое короче и не даёт забыть про закрытие. Аналогия: `with` — это автоматические двери. Вы вошли — дверь сама закроется за вами, даже если вы убегаете (исключение).

### Что означают аргументы `__exit__`

- `exc_type` — класс исключения (`ValueError`) или `None`, если исключения не было.
- `exc_val` — сам объект исключения (с сообщением).
- `exc_tb` — трассировка (traceback).

Если исключения не было, все три равны `None`.

## 6. Свой контекстный менеджер

**Через класс:**
```python
class ManagedFile:
    def __init__(self, path, mode="r"):
        self.path, self.mode = path, mode
    def __enter__(self):
        self.file = open(self.path, self.mode)
        return self.file
    def __exit__(self, exc_type, exc_val, exc_tb):
        self.file.close()
        return False   # исключение не подавляем

with ManagedFile("data.txt", "w") as f:
    f.write("hello")
```

Пошагово:
1. `ManagedFile("data.txt", "w")` — создаётся объект (файл ещё не открыт).
2. `__enter__` открывает файл и возвращает его — он попадает в `f`.
3. Тело `with` пишет в файл.
4. При выходе (обычном или из-за ошибки) вызывается `__exit__`, который закрывает файл.
5. `return False` означает: «исключение я не поглощаю, пусть летит дальше».

**Через `@contextmanager` (проще):**
```python
from contextlib import contextmanager

@contextmanager
def timer(name):
    import time
    start = time.perf_counter()
    try:
        yield
    finally:
        print(f"{name}: {time.perf_counter() - start:.4f}s")

with timer("sleep"):
    import time; time.sleep(0.5)
```

Всё до `yield` — это `__enter__`, всё после — `__exit__`. Если нужно передать значение в `as`, пишите `yield value`.

```python
@contextmanager
def managed_file(path):
    f = open(path)
    try:
        yield f          # это значение попадёт в `as f`
    finally:
        f.close()

with managed_file("data.txt") as f:
    print(f.read())
```

**Важно:** `try/finally` вокруг `yield` обязателен, иначе при исключении ресурс не освободится.

## 7. Полезные готовые менеджеры

| Менеджер | Назначение |
|---|---|
| `open()` | файлы |
| `threading.Lock` | блокировки |
| `contextlib.suppress` | подавление исключений |
| `contextlib.redirect_stdout` | перенаправление вывода |
| `unittest.mock.patch` | подмена объектов в тестах |
| `asyncio.timeout` | таймауты (3.11+) |

```python
from contextlib import suppress
with suppress(FileNotFoundError):
    import os; os.remove("no_file.txt")   # ошибка не всплывёт
```

`redirect_stdout` удобен для перехвата вывода:

```python
import io
from contextlib import redirect_stdout

buf = io.StringIO()
with redirect_stdout(buf):
    print("перехвачено")
print(buf.getvalue())   # 'перехвачено\n'
```

**Типичная ошибка с `suppress`:** слишком широкий список исключений скрывает настоящие баги.

```python
with suppress(Exception):   # плохо: спрячет всё
    do_something()
```

Лучше указывать конкретный тип, который вы действительно ожидаете.

## 8. Мини-итог и связки

- Декоратор — это функция-обёртка, которая добавляет поведение, не меняя код функции.
- `@wraps` сохраняет метаданные; без него теряются имя и докстринг.
- Декоратор с аргументами — три уровня вложенности.
- Декораторы применяются снизу вверх, а выполняются сверху вниз.
- Контекстный менеджер гарантирует освобождение ресурса; `__exit__` может подавить исключение, вернув `True`.
- `@contextmanager` превращает генератор в менеджер; до `yield` — вход, после — выход.

Связки: декораторы опираются на замыкания и функции как объекты; контекстные менеджеры — на протокол dunder-методов. Детали (дескрипторы, `ExitStack`, async-версии) — в `Углублённая теория.md`.
