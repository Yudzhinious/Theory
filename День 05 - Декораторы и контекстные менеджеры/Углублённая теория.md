## 1. Декоратор — это просто вызов

```python
@deco
def f(): ...
# эквивалент:
f = deco(f)
```

Декоратор может быть функцией, классом или объектом с `__call__`. `@deco(arg)` — сначала вызывается `deco(arg)`, возвращая декоратор.

---

## 2. Декоратор-класс и сохранение состояния

```python
class CountCalls:
    def __init__(self, func):
        self.func = func
        self.count = 0
    def __call__(self, *args, **kwargs):
        self.count += 1
        return self.func(*args, **kwargs)

@CountCalls
def hello():
    return "hi"

hello(); hello()
print(hello.count)   # 2
```

## 3. `functools` в декораторах

- `wraps` — копирует `__name__`, `__doc__`, `__wrapped__`, `__annotations__`.
- `lru_cache`/`cache` — мемоизация (требует хешируемых аргументов).
- `cached_property` — кэширует результат как атрибут (для классов).
- `singledispatch` — диспетчеризация по типу первого аргумента.

```python
from functools import cached_property
class Data:
    @cached_property
    def heavy(self):
        return sum(range(10**6))   # посчитается один раз
```

## 4. Дескрипторный протокол — «магия» атрибутов

Дескриптор — объект, определяющий `__get__`/`__set__`/`__delete__`. На нём построены `property`, `staticmethod`, `classmethod`, методы.

```python
class Positive:
    def __set_name__(self, owner, name):
        self.name = name
    def __get__(self, obj, objtype=None):
        return obj.__dict__.get(self.name)
    def __set__(self, obj, value):
        if value <= 0:
            raise ValueError("должно быть > 0")
        obj.__dict__[self.name] = value

class Product:
    price = Positive()

p = Product()
p.price = 100        # __set__
p.price = -1         # ValueError
```

**`property`** — частный случай дескриптора. **Data descriptor** (с `__set__`) имеет приоритет над `instance.__dict__`; **non-data** (только `__get__`) — нет.

## 5. Контекстные менеджеры: детали

- `__enter__` может вернуть значение для `as`.
- `__exit__(exc_type, exc_val, exc_tb)` возвращает `True`, чтобы **подавить** исключение.
- Исключение внутри `with` попадает в `__exit__`; если вернуть falsy — пробрасывается.

```python
class Suppress:
    def __enter__(self): return self
    def __exit__(self, *exc): return True
```

## 6. `contextlib` — арсенал

| Инструмент | Назначение |
|---|---|
| `contextmanager` | CM из генератора |
| `closing` | вызывает `.close()` на выходе |
| `suppress(*excs)` | подавить исключения |
| `redirect_stdout/stderr` | перенаправить вывод |
| `nullcontext` | пустой CM (для условного `with`) |
| `ExitStack` | динамический набор CM, гарантированная очистка |
| `AsyncExitStack` | то же для async |

```python
from contextlib import ExitStack
with ExitStack() as stack:
    files = [stack.enter_context(open(f)) for f in paths]
    # все файлы закроются при выходе
```

`@contextmanager`:
```python
@contextmanager
def managed(conn):
    try:
        yield conn
        conn.commit()
    except Exception:
        conn.rollback()
        raise
```

## 7. Асинхронные контекстные менеджеры

```python
class AsyncResource:
    async def __aenter__(self): ...
    async def __aexit__(self, *exc): ...

async with AsyncResource() as r:
    ...
```

`@asynccontextmanager` — аналог для async-генераторов.

---

## 8. Вложенность и порядок

```python
with A() as a, B() as b:
    ...
# A.__enter__ → B.__enter__ → ... → B.__exit__ → A.__exit__
```

Выход — в обратном порядке (как стек). `ExitStack` позволяет строить это динамически.
