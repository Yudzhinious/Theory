# День 13 — Вопросы

---

**1. Django vs FastAPI — ключевые отличия?**
<details><summary>Ответ</summary>
Django — full-stack (ORM, админка, шаблоны, синхронный). FastAPI — микрофреймворк для API, асинхронный, type hints + Pydantic, автодокументация, без встроенного ORM/админки.
</details>

**2. Когда выбрать Django, а когда FastAPI?**
<details><summary>Ответ</summary>
Django — сайты, CMS, порталы с админкой и серверным рендерингом. FastAPI — высоконагруженные API, микросервисы, real-time, ML-сервисы.
</details>

**3. Что такое Pydantic и зачем он?**
<details><summary>Ответ</summary>
Библиотека валидации и сериализации данных на основе type hints. В FastAPI описывает схемы запросов/ответов, автоматически проверяет и преобразует данные.
</details>

**4. Что такое Dependency Injection в FastAPI?**
<details><summary>Ответ</summary>
Механизм `Depends`, позволяющий объявлять зависимости (сессия БД, текущий пользователь, настройки) и автоматически подставлять их в эндпоинты. Упрощает переиспользование и тестирование.
</details>

**5. Монолит vs микросервисы?**
<details><summary>Ответ</summary>
Монолит — единое приложение, проще в разработке/отладке. Микросервисы — независимые сервисы, отдельный деплой и масштабирование, но сложнее (сеть, согласованность, наблюдаемость).
</details>

**6. Зачем нужен брокер сообщений?**
<details><summary>Ответ</summary>
Асинхронная связь между сервисами: развязка (decoupling), буферизация при недоступности получателя, балансировка нагрузки, гарантия доставки.
</details>

**7. RabbitMQ vs Kafka?**
<details><summary>Ответ</summary>
RabbitMQ — очереди, FIFO, сообщения удаляются после прочтения, хорош для задач/маршрутизации. Kafka — распределённый лог, сообщения хранятся и перечитываются, для стриминга/аналитики/логов.
</details>

**8. VM vs контейнер?**
<details><summary>Ответ</summary>
VM виртуализирует железо и содержит полную ОС (тяжёлая, медленный старт). Контейнер изолирует процесс и делит ядро хоста (лёгкий, быстрый старт).
</details>

**9. Image vs container?**
<details><summary>Ответ</summary>
Image — неизменяемый шаблон (слои) для создания контейнеров. Container — запущенный экземпляр образа.
</details>

**10. Что такое Dockerfile и volume?**
<details><summary>Ответ</summary>
Dockerfile — инструкция сборки образа. Volume — постоянное хранилище, сохраняющее данные вне жизненного цикла контейнера.
</details>

## Мини-задача
Напиши минимальный FastAPI-эндпоинт, принимающий JSON `{"name": "..."}` и возвращающий приветствие с валидацией непустого имени.
<details><summary>Решение</summary>

```python
from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI()

class HelloIn(BaseModel):
    name: str = Field(min_length=1)

@app.post("/hello")
def hello(data: HelloIn):
    return {"message": f"Привет, {data.name}!"}
```
Если `name` пустой — FastAPI автоматически вернёт 422.
</details>
