## 1. FastAPI изнутри

- Построен на **Starlette** (ASGI) и **Pydantic** (валидация).
- **Dependency Injection:** граф зависимостей через `Depends`; поддерживает `yield` (setup/teardown), кэширование зависимостей.
- **async def** эндпоинты идут в event loop; **обычные `def`** — в threadpool (чтобы не блокировать loop).
- **Lifespan** — startup/shutdown (вместо устаревших `@app.on_event`).
- **Middleware**, роутеры (`APIRouter`), фоновые задачи (`BackgroundTasks`), WebSocket.
- Автодокументация OpenAPI/Swagger на `/docs`, ReDoc на `/redoc`.

```python
from contextlib import asynccontextmanager
from fastapi import FastAPI

@asynccontextmanager
async def lifespan(app: FastAPI):
    # startup
    yield
    # shutdown

app = FastAPI(lifespan=lifespan)
```

## 2. Pydantic v2

- Валидация и сериализация по type hints; ядро на Rust (pydantic-core) — быстрее v1.
- `BaseModel`, `Field`, `field_validator`, `model_validator`, `ConfigDict`.
- `model_dump()`/`model_validate()` вместо `.dict()`/`.parse_obj()`.
- `BaseSettings` (pydantic-settings) — конфиги из env.

```python
from pydantic import BaseModel, Field, field_validator

class User(BaseModel):
    model_config = {"from_attributes": True}   # из ORM-объектов
    name: str = Field(min_length=1)
    age: int = Field(ge=0)

    @field_validator("name")
    @classmethod
    def strip(cls, v): return v.strip()
```

## 3. Django глубоко

- **ORM:** `QuerySet` ленив; `select_related` (JOIN для FK), `prefetch_related` (отдельные запросы для M2M) — против N+1.
- **Middleware** — цепочка обработки запроса/ответа.
- **Signals** — `post_save`, `pre_delete` и т.д. (осторожно: неявные связи).
- **DRF:** сериализаторы, ViewSet, Router, permissions, throttling.
- **Миграции**, `manage.py`, настройки, `settings.py`, admin.
- Синхронный ORM; async — через `sync_to_async`/`async_to_sync`.

## 4. Брокеры сообщений глубоко

- **Delivery semantics:** at-most-once (возможна потеря), at-least-once (возможны дубли), exactly-once (сложно, обычно идемпотентность потребителя).
- **RabbitMQ:** exchanges (direct/topic/fanout/headers), queues, bindings, ack/nack, prefetch, dead-letter queue, TTL.
- **Kafka:** топики → партиции, **offset**, **consumer groups** (параллелизм), retention (хранит по времени/размеру), порядок гарантирован только внутри партиции, ключ сообщения → партиция.
- **Паттерны:** **Outbox** (атомарно писать в БД + событие), **Saga** (распределённые транзакции через компенсации), **CQRS**, **event sourcing**.

## 5. Микросервисные паттерны

- **API Gateway** — единая точка входа, маршрутизация, аутентификация.
- **Service Discovery** — находит инстансы.
- **Circuit Breaker** — разрывает поток к упавшему сервису.
- **Bulkhead**, **Timeout**, **Retry**, **Rate limit**.
- **Distributed tracing** (OpenTelemetry), централизованные логи, метрики.
- **Идемпотентность** и **eventual consistency** вместо распределённых транзакций.

## 6. Docker глубоко

- **Слои образа** — кэшируются; изменяй редко меняющиеся слои раньше (`requirements.txt` до `COPY . .`).
- **Multi-stage build** — собирай в одном образе, копируй артефакт в маленький финальный.
- **`.dockerignore`** — не копировать лишнее.
- **Volume** — постоянные данные; **bind mount** — код хоста в контейнер.
- **Networks** — контейнеры общаются по именам сервисов (в compose).
- **Compose** — многоконтейнерные приложения.

```dockerfile
FROM python:3.12-slim AS base
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["uvicorn", "main:app", "--host", "0.0.0.0"]
```

Best practices: не root, pinned версии, маленький base (`-slim`/`alpine`), healthcheck, один процесс на контейнер.
