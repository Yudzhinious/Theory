# День 12 — Вопросы

---

**1. Что такое идемпотентность? Какие методы идемпотентны?**
<details><summary>Ответ</summary>
Повторный запрос даёт тот же результат, что и один. Идемпотентны GET, PUT, DELETE, HEAD, OPTIONS. POST — нет.
</details>

**2. PUT vs PATCH?**
<details><summary>Ответ</summary>
PUT заменяет ресурс целиком (непереданные поля обнуляются), PATCH частично обновляет только переданные поля.
</details>

**3. Разница 401 и 403?**
<details><summary>Ответ</summary>
401 Unauthorized — клиент не аутентифицирован (нужно войти). 403 Forbidden — аутентифицирован, но прав недостаточно.
</details>

**4. Что означает 201, 204, 404, 500?**
<details><summary>Ответ</summary>
201 — создано; 204 — успех без тела ответа; 404 — ресурс не найден; 500 — внутренняя ошибка сервера.
</details>

**5. Назови принципы REST.**
<details><summary>Ответ</summary>
Клиент-сервер, stateless, кэширование, единообразный интерфейс, слои, код по требованию (опц.). RESTful API следует этим правилам.
</details>

**6. Почему REST stateless и в чём плюс?**
<details><summary>Ответ</summary>
Сервер не хранит состояние клиента между запросами — каждый запрос самодостаточен. Плюс: легче масштабировать и распределять нагрузку.
</details>

**7. Разница идентификации, аутентификации и авторизации?**
<details><summary>Ответ</summary>
Идентификация — предъявление имени; аутентификация — проверка подлинности; авторизация — проверка и выдача прав.
</details>

**8. Сессии vs JWT — плюсы и минусы?**
<details><summary>Ответ</summary>
Сессии: сервер хранит состояние, легко отозвать, но сложно масштабировать. JWT: stateless, удобно для микросервисов, но сложно отозвать — делают короткоживущим.
</details>

**9. Из чего состоит JWT?**
<details><summary>Ответ</summary>
Header (алгоритм), Payload (claims: id, роль, exp), Signature (подпись секретным ключом). Разделены точками.
</details>

**10. WSGI vs ASGI?**
<details><summary>Ответ</summary>
WSGI — синхронный, блокирующий, только HTTP/1.1 (Gunicorn). ASGI — асинхронный, поддерживает WebSocket/HTTP2 (Uvicorn), используется FastAPI.
</details>

## Мини-задача
Спроектируй REST-эндпоинты для сущности `article` (статьи блога).
<details><summary>Решение</summary>

```text
GET    /articles            → список статей
GET    /articles/{id}       → одна статья
POST   /articles            → создать
PUT    /articles/{id}       → заменить
PATCH  /articles/{id}       → частично обновить
DELETE /articles/{id}       → удалить
```
Коды: 200 при чтении/обновлении, 201 при создании, 204 при удалении, 404 если нет, 400 при ошибке валидации.
</details>
