## 1. Полный порядок параметров

```python
def f(pos_only, /, normal, *, kw_only):
    ...
```

- До `/` — **только позиционные**.
- После `*` — **только именованные** (keyword-only).
- `*args` собирает лишние позиционные, `**kwargs` — именованные.

Вызов с `*`/`**` распаковывает:
```python
args = (1, 2); kwargs = {"a": 3}
f(*args, **kwargs)
```

### Полный синтаксис и порядок

Порядок строго такой:
1. позиционные-или-именованные,
2. `/`,
3. позиционные-или-именованные после `/`,
4. `*` или `*args`,
5. keyword-only,
6. `**kwargs`.

```python
def full(a, b, /, c, d, *args, e, f=10, **kwargs):
    print(a, b, c, d, args, e, f, kwargs)

full(1, 2, 3, 4, 5, 6, e=7, extra=8)
# 1 2 3 4 (5, 6) 7 10 {'extra': 8}
```

### Только позиционные (`/`)

```python
def div(a, b, /):
    return a / b

print(div(10, 2))       # 5.0
# div(a=10, b=2)        # ❌ TypeError — только позиционно
```

Зачем: позволяет менять имена параметров, не ломая вызывающий код (актуально для стандартной библиотеки).

### Только именованные (`*`)

```python
def configure(*, debug=False, level=1):
    return debug, level

print(configure(debug=True))   # (True, 1)
# configure(True)              # ❌ TypeError
```

### Распаковка

```python
def add(a, b, c):
    return a + b + c

args = [1, 2, 3]
print(add(*args))          # 6

kwargs = {"a": 1, "b": 2, "c": 3}
print(add(**kwargs))       # 6

# Комбинация
print(add(1, *[2, 3]))     # 6
```

### Мини-итог

`/` запрещает передачу по имени, `*` — по позиции. Это инструменты проектирования API, делающие вызовы явными и устойчивыми к изменениям.

## 2. Значения по умолчанию вычисляются при определении

```python
import time
def log(msg, t=time.time()):   # time.time() вызовется ОДИН раз
    print(t, msg)
```

Отсюда ловушка с изменяемым `acc=[]`. Проверка — `f.__defaults__` (позиционные) и `f.__kwdefaults__` (именованные).

### Доказательство: время фиксируется

```python
import time

def log(msg, t=time.time()):
    return t

first = log("a")
time.sleep(1)
second = log("b")
print(first == second)   # True — время одно и то же!
```

### Просмотр дефолтов

```python
def f(a, b=1, *, c=2):
    pass

print(f.__defaults__)     # (1,)
print(f.__kwdefaults__)   # {'c': 2}
```

### Как правильно «динамический» дефолт

```python
import time

# ❌ фиксируется при определении
def log_bad(msg, t=time.time()):
    return t

# ✅ вычисляется при каждом вызове
def log_good(msg, t=None):
    if t is None:
        t = time.time()
    return t
```

### Мини-итог

Дефолты — часть объекта-функции, а не вызова. Если значение должно вычисляться каждый раз, используй `None` как маркер.

## 3. Замыкания и ячейки

Замыкание хранит переменные во **ячейках** (`cell`):

```python
def outer():
    x = 10
    def inner():
        return x
    return inner

fn = outer()
fn.__closure__[0].cell_contents   # 10
```

**Late binding** в цикле:
```python
funcs = [lambda: i for i in range(3)]     # все -> 2
funcs = [lambda i=i: i for i in range(3)] # 0,1,2
```
Причина: лямбда захватывает **имя**, а не значение на момент создания.

### Что такое ячейка

Когда внутренняя функция ссылается на переменную внешней, CPython превращает эту переменную в **ячейку** (`cell`), разделяемую между функциями.

```python
def outer():
    x = 10
    def inner():
        return x
    print(inner.__closure__)                 # (<cell at ...>,)
    print(inner.__closure__[0].cell_contents) # 10
    return inner

outer()
```

### Демонстрация late binding

```python
def make_funcs():
    funcs = []
    for i in range(3):
        funcs.append(lambda: i)
    return funcs

for f in make_funcs():
    print(f())     # 2 2 2
```

### Исправления

```python
# Способ 1: default-аргумент
funcs = [lambda i=i: i for i in range(3)]

# Способ 2: фабрика (функция, создающая замыкание)
def make(i):
    return lambda: i
funcs = [make(i) for i in range(3)]

# Способ 3: functools.partial
from functools import partial
funcs = [partial(lambda i: i, i) for i in range(3)]
```

### Мини-итог

Замыкание — функция + ячейки с захваченными переменными. Late binding — следствие того, что захватывается ссылка на ячейку, а не снимок значения.

## 4. `nonlocal` и изменяемое состояние

```python
def make_counter():
    n = 0
    def inc():
        nonlocal n
        n += 1
        return n
    return inc
```

Альтернатива — класс или `itertools.count`.

### Сравнение подходов к счётчику

```python
# 1. Замыкание
def make_counter():
    n = 0
    def inc():
        nonlocal n
        n += 1
        return n
    return inc

# 2. Класс
class Counter:
    def __init__(self):
        self.n = 0
    def inc(self):
        self.n += 1
        return self.n

# 3. itertools.count
import itertools
counter = itertools.count(1)
print(next(counter))   # 1
print(next(counter))   # 2
```

### Когда что выбирать

| Подход | Плюс | Минус |
|---|---|---|
| Замыкание | компактно | нет интроспекции состояния |
| Класс | явное состояние | многословнее |
| `itertools.count` | быстро, лениво | только счётчик |

### Мини-итог

`nonlocal` позволяет замыканию иметь изменяемое состояние. Альтернативы — класс и `itertools.count`.

## 5. Функции как объекты: атрибуты и интроспекция

```python
def f(a: int, b: int = 1) -> int:
    """doc"""
    return a + b

f.__name__        # 'f'
f.__doc__         # 'doc'
f.__annotations__ # {'a': int, 'b': int, 'return': int}
f.__defaults__    # (1,)
f.__code__.co_varnames   # ('a', 'b')
```

`inspect.signature(f)` даёт полную сигнатуру — так работают декораторы и фреймворки.

### Разбор атрибутов

```python
def f(a: int, b: int = 1) -> int:
    """Сумма."""
    return a + b

print(f.__name__)          # f
print(f.__doc__)           # Сумма.
print(f.__annotations__)   # {'a': int, 'b': int, 'return': int}
print(f.__defaults__)      # (1,)
print(f.__code__.co_argcount)   # 2 — число аргументов
```

### `inspect.signature`

```python
import inspect

def f(a: int, b: int = 1) -> int:
    return a + b

sig = inspect.signature(f)
print(sig)                       # (a: int, b: int = 1) -> int
for name, param in sig.parameters.items():
    print(name, param.default, param.annotation)
# a <class 'inspect._empty'> <class 'int'>
# b 1 <class 'int'>
```

Именно так декораторы и фреймворки (например, FastAPI) узнают параметры функции.

### Мини-итог

Функция — объект с богатой интроспекцией: имя, докстрока, аннотации, дефолты, байткод. Это основа метапрограммирования и декораторов.

## 6. Функциональные инструменты

- **`functools.partial`** — фиксирует часть аргументов.
- **`functools.reduce`** — свёртка.
- **`functools.lru_cache` / `cache`** — мемоизация.
- **`functools.singledispatch`** — перегрузка по типу (аналог множественной диспетчеризации).

```python
from functools import partial, reduce, lru_cache, singledispatch

add10 = partial(lambda a, b: a + b, 10)
reduce(lambda a, b: a * b, [1, 2, 3, 4])   # 24

@lru_cache(maxsize=None)
def fib(n): return n if n < 2 else fib(n-1) + fib(n-2)

@singledispatch
def show(x): return "unknown"
@show.register
def _(x: int): return "int"
```

### `partial` подробнее

```python
from functools import partial

def power(base, exp):
    return base ** exp

square = partial(power, exp=2)
cube = partial(power, exp=3)
print(square(5))    # 25
print(cube(3))      # 27
```

### `lru_cache` — ускорение рекурсии

```python
from functools import lru_cache
import time

@lru_cache(maxsize=None)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

t0 = time.perf_counter()
print(fib(35))          # 9227465 — быстро благодаря кэшу
print(time.perf_counter() - t0)

print(fib.cache_info()) # hits/misses
```

Без кэша `fib(35)` выполнял бы миллионы вызовов; с кэшем — десятки.

### `singledispatch` — перегрузка по типу

```python
from functools import singledispatch

@singledispatch
def describe(x):
    return "неизвестно"

@describe.register(int)
def _(x):
    return "целое"

@describe.register(str)
def _(x):
    return "строка"

print(describe(5))      # целое
print(describe("hi"))   # строка
print(describe(1.5))    # неизвестно
```

### Мини-итог

`functools` даёт готовые кирпичи: фиксацию аргументов, свёртку, мемоизацию и диспетчеризацию по типу. Мемоизация превращает экспоненциальную рекурсию в линейную.

## 7. Callable-объекты

Любой объект с `__call__` — вызываемый:

```python
class Adder:
    def __init__(self, n): self.n = n
    def __call__(self, x): return x + self.n

add5 = Adder(5)
add5(10)   # 15
callable(add5)  # True
```

Так работают декораторы-классы и «функции с состоянием».

### Функция vs callable-объект

```python
class Multiplier:
    def __init__(self, n):
        self.n = n
    def __call__(self, x):
        return x * self.n

m = Multiplier(3)
print(m(5))          # 15
print(callable(m))   # True

print(callable(5))   # False
print(callable("a")) # False
```

### Состояние в callable-объекте

```python
class Counter:
    def __init__(self):
        self.count = 0
    def __call__(self):
        self.count += 1
        return self.count

c = Counter()
print(c(), c(), c())   # 1 2 3
```

### Мини-итог

`__call__` позволяет объекту вести себя как функция, сохраняя состояние. Это мост между ООП и функциональным стилем.

## 8. Рекурсия: ограничения и замена

- Нет оптимизации хвостовой рекурсии (TCO).
- Ограничение глубины: `sys.getrecursionlimit()` (по умолчанию ~1000).
- Глубокая рекурсия → `RecursionError`; иногда помогает перевод на итерацию со стеком.

```python
def fact(n, acc=1):
    return acc if n <= 1 else fact(n-1, acc*n)
```

### Проверка лимита

```python
import sys
print(sys.getrecursionlimit())   # обычно 1000

def deep(n):
    if n == 0:
        return 0
    return deep(n - 1)

# deep(10000)   # RecursionError
```

### Хвостовая рекурсия не оптимизируется

```python
def fact(n, acc=1):
    return acc if n <= 1 else fact(n - 1, acc * n)

# Python НЕ превращает это в цикл — глубина стека всё равно растёт
```

### Итеративная замена

```python
def fact_iter(n):
    result = 1
    for i in range(2, n + 1):
        result *= i
    return result

print(fact_iter(5))   # 120 — без ограничения по глубине
```

### Мини-итог

Рекурсия элегантна, но ограничена стеком и не оптимизируется. Для больших глубин — итерация или явный стек.

## 9. Полезные мелочи

- **Walrus `:=`**: `if (n := len(a)) > 10: ...`.
- **Слияние словарей**: `a | b` (3.9+).
- **Распаковка в вызове**: `f(*args, **kwargs)`.
- **`enumerate`/`zip`/`reversed`** — читаемее ручных индексов.

### Walrus

```python
data = [1, 2, 3, 4]
if (n := len(data)) > 3:
    print(f"элементов {n}")   # элементов 4
```

### `enumerate`, `zip`, `reversed`

```python
for i, val in enumerate(["a", "b"], start=1):
    print(i, val)             # 1 a / 2 b

for a, b in zip([1, 2], ["x", "y"]):
    print(a, b)               # 1 x / 2 y

print(list(reversed([1, 2, 3])))   # [3, 2, 1]
```

### Слияние словарей

```python
a = {"x": 1}
b = {"y": 2}
print(a | b)      # {'x': 1, 'y': 2} (3.9+)
```

### Мини-итог

Мелкие приёмы делают код короче и читаемее. Walrus удобен, когда значение нужно и в условии, и внутри.

## 10. Что ещё спросят

- Порядок и виды параметров (`/`, `*`, `*args`, `**kwargs`)?
- Почему значение по умолчанию вычисляется один раз?
- Как работает замыкание на уровне ячеек?
- Что такое late binding?
- Как `lru_cache` ускоряет рекурсию?
- Чем `partial` отличается от лямбды?

### Ядра ответов

| Вопрос | Ядро |
|---|---|
| Порядок параметров | pos-only `/`, затем `*`/`*args`, keyword-only, `**kwargs` |
| Дефолт один раз | вычисляется при `def` и хранится в `__defaults__` |
| Ячейки | `cell_contents` замыкания |
| Late binding | захват имени, а не значения |
| `lru_cache` | кэширует результаты, убирает повторные вычисления |
| `partial` vs lambda | `partial` фиксирует аргументы без нового кода |

## 11. Мини-итог дня (углублённый)

1. Полный порядок параметров: pos-only `/`, `*args`, keyword-only, `**kwargs`.
2. Дефолты вычисляются один раз и живут в функции.
3. Замыкания хранят переменные в ячейках; late binding — захват имени.
4. Функция — объект с интроспекцией (`__code__`, `__annotations__`).
5. `functools` даёт `partial`, `reduce`, `lru_cache`, `singledispatch`.
6. `__call__` превращает объект в вызываемый.
7. Рекурсия ограничена стеком; TCO нет.

**Связка:** декораторы (День 7) целиком строятся на замыканиях, `*args/**kwargs` и интроспекции.
