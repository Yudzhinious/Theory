# День 6 — Вопросы

---

**1. Назови и кратко объясни 4 принципа ООП.**
<details><summary>Ответ</summary>
Инкапсуляция — сокрытие состояния; наследование — создание класса на основе другого; полиморфизм — один интерфейс, разное поведение; абстракция — выделение существенного, скрытие деталей.
</details>

**2. Как реализована инкапсуляция в Python?**
<details><summary>Ответ</summary>
Через соглашения: `_x` — protected, `__x` — name mangling (`_Class__x`). Настоящей приватности нет, но есть `@property` для контроля доступа.
</details>

**3. Что делает name mangling?**
<details><summary>Ответ</summary>
Атрибут `__x` внутри класса `A` превращается в `_A__x`. Это затрудняет доступ, но не запрещает его.
</details>

**4. `@staticmethod` vs `@classmethod`?**
<details><summary>Ответ</summary>
`staticmethod` не получает ни `self`, ни `cls` — утилитарная функция. `classmethod` получает `cls`, может обращаться к атрибутам класса; часто используется как альтернативный конструктор.
</details>

**5. Что такое `@property`?**
<details><summary>Ответ</summary>
Декоратор, превращающий метод в «атрибут». Позволяет иметь геттер, сеттер (`@x.setter`) и делитер (`@x.deleter`), контролируя чтение/запись.
</details>

**6. `__new__` vs `__init__`?**
<details><summary>Ответ</summary>
`__new__` создаёт и возвращает объект (статический по смыслу, вызывается первым), `__init__` инициализирует уже созданный объект. `__new__` нужен редко — например, для singleton.
</details>

**7. Что такое утиная типизация?**
<details><summary>Ответ</summary>
Полиморфизм без наследования: код полагается на наличие нужного метода, а не на тип объекта. «Если крякает как утка — это утка».
</details>

**8. `__str__` vs `__repr__`?**
<details><summary>Ответ</summary>
`__repr__` — однозначное представление для отладки (для разработчика), `__str__` — читаемое для пользователя (используется в `print`). Если нет `__str__`, используется `__repr__`.
</details>

**9. Зачем `__eq__` и `__hash__` вместе?**
<details><summary>Ответ</summary>
Если переопределить `__eq__`, объект становится нехешируемым (hash становится `None`). Чтобы использовать в `set`/`dict`, нужно явно определить `__hash__`, согласованный с `__eq__`.
</details>

**10. Реализуй класс `Counter` с `__add__` и `__repr__`.**
<details><summary>Ответ</summary>

```python
class Money:
    def __init__(self, amount):
        self.amount = amount
    def __add__(self, other):
        return Money(self.amount + other.amount)
    def __repr__(self):
        return f"Money({self.amount})"

print(Money(10) + Money(5))   # Money(15)
```
</details>

## Мини-задача
Реализуй singleton через `__new__` и проверь, что два вызова дают один объект.
<details><summary>Решение</summary>

```python
class Config:
    _instance = None
    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance

a, b = Config(), Config()
print(a is b)   # True
```
</details>
