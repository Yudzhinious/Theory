## 1. Поиск атрибута: `__getattribute__` и `__getattr__`

- **`__getattribute__`** вызывается **всегда** при доступе к атрибуту.
- **`__getattr__`** вызывается **только если** обычный поиск не нашёл атрибут (обработка отсутствующих).

```python
class Proxy:
    def __getattr__(self, name):
        return f"нет атрибута {name}"
    def __setattr__(self, name, value):
        object.__setattr__(self, name, value)
```

Порядок: data descriptors → instance `__dict__` → non-data descriptors/класс → `__getattr__`.

## 2. `__set_name__` и `__init_subclass__`

```python
class Field:
    def __set_name__(self, owner, name):
        self.name = name   # имя, под которым дескриптор присвоен

class Base:
    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        print("создан подкласс", cls.__name__)
```

`__init_subclass__` — «лёгкая» альтернатива метаклассу для настройки подклассов (PEP 487).

## 3. `__slots__` — детали

- Убирает `__dict__`, экономит память.
- Нельзя добавлять новые атрибуты.
- Наследник без `__slots__` снова получает `__dict__`.
- Несовместим с `cached_property` (нужен `__dict__`).
- `@dataclass(slots=True)` в 3.10+.

```python
class Point:
    __slots__ = ("x", "y")
    def __init__(self, x, y): self.x, self.y = x, y
```

## 4. Dunder-методы, которые стоит знать

| Метод | Зачем |
|---|---|
| `__repr__`/`__str__` | представление |
| `__eq__`/`__hash__` | равенство/хеш |
| `__lt__` и др. | сравнения (сортировка) |
| `__len__`, `__bool__` | размер/истинность |
| `__getitem__`/`__setitem__` | индексация |
| `__contains__` | `in` |
| `__iter__`/`__next__` | итерация |
| `__call__` | вызов объекта |
| `__enter__`/`__exit__` | `with` |
| `__add__`/`__radd__` | арифметика |
| `__format__` | f-строки |
| `__getattr__`/`__setattr__` | динамические атрибуты |

```python
class Vec:
    def __init__(self, x): self.x = x
    def __add__(self, o): return Vec(self.x + o.x)
    def __radd__(self, o): return Vec(self.x + o)   # 3 + vec
    def __repr__(self): return f"Vec({self.x})"
```

**`__radd__`** нужен, когда объект справа, а слева — встроенный тип.

## 5. `dataclass` vs `NamedTuple` vs обычный класс

| | dataclass | NamedTuple | обычный |
|---|---|---|---|
| Изменяемый | да (или `frozen`) | нет | да |
| `__eq__`/`__repr__` | авто | авто | вручную |
| Хешируемый | если `frozen` | да | вручную |
| Индексация | нет | да | нет |
| Наследование | удобно | ограничено | полное |

## 6. Композиция, миксины, делегирование

- **Композиция** («has-a») часто лучше наследования («is-a»).
- **Миксин** — класс с одной узкой функциональностью, подмешиваемый через наследование.

```python
class JsonMixin:
    def to_json(self):
        import json
        return json.dumps(self.__dict__)
```

Делегирование: `__getattr__` пробрасывает вызовы вложенному объекту.

---

## 7. `super()` — детали

- `super()` внутри метода — «следующий класс в MRO», не обязательно родитель.
- В `__init__` подкласса вызывай `super().__init__(...)`.
- `super(C, obj)` — явная форма.

## 8. Классовые vs экземплярные атрибуты

```python
class C:
    shared = []          # ОБЩИЙ для всех — ловушка!
    def __init__(self):
        self.own = []    # свой у каждого
```

Изменяемый атрибут класса — источник багов. Для значений по умолчанию используй `__init__` или `field(default_factory=...)`.
