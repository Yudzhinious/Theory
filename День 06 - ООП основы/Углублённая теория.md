## 1. Поиск атрибута: `__getattribute__` и `__getattr__`

- **`__getattribute__`** вызывается **всегда** при доступе к атрибуту.
- **`__getattr__`** вызывается **только если** обычный поиск не нашёл атрибут (обработка отсутствующих).

```python
class Proxy:
    def __getattr__(self, name):
        return f"нет атрибута {name}"
    def __setattr__(self, name, value):
        object.__setattr__(self, name, value)
```

Порядок: data descriptors → instance `__dict__` → non-data descriptors/класс → `__getattr__`.

### Пошагово

```python
class Demo:
    def __getattribute__(self, name):
        print(f"ищем {name}")
        return object.__getattribute__(self, name)

    def __getattr__(self, name):
        return f"заглушка для {name}"

d = Demo()
d.x          # печатает "ищем x", затем "заглушка для x"
```

1. `d.x` → вызывается `__getattribute__("x")`.
2. Он пытается найти `x` обычным путём — не находит.
3. Тогда Python вызывает `__getattr__("x")`, который возвращает заглушку.

### Типичная ошибка: бесконечная рекурсия

```python
class Bad:
    def __getattr__(self, name):
        return self.name        # снова обращается к атрибуту → рекурсия!
```

Правильно обращаться к `self.__dict__` или `object.__getattribute__`:

```python
class Good:
    def __getattr__(self, name):
        return self.__dict__.get(name, "нет")
```

### Применение: ленивые атрибуты

```python
class Lazy:
    def __getattr__(self, name):
        print(f"вычисляю {name}...")
        value = name.upper()
        setattr(self, name, value)   # кэшируем
        return value

l = Lazy()
print(l.foo)    # вычисляю foo... / FOO
print(l.foo)    # FOO (без вычисления)
```

## 2. `__set_name__` и `__init_subclass__`

```python
class Field:
    def __set_name__(self, owner, name):
        self.name = name   # имя, под которым дескриптор присвоен

class Base:
    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        print("создан подкласс", cls.__name__)
```

`__init_subclass__` — «лёгкая» альтернатива метаклассу для настройки подклассов (PEP 487).

### Когда что использовать

| Инструмент | Когда вызывается | Для чего |
|---|---|---|
| `__set_name__` | при создании класса, для каждого дескриптора | узнать имя атрибута |
| `__init_subclass__` | при создании каждого подкласса | регистрация, валидация, настройка |
| Метакласс | при создании класса | тяжёлая магия (ORM) |

### Пример: реестр плагинов

```python
class Plugin:
    registry = {}
    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        Plugin.registry[cls.__name__] = cls

class Audio(Plugin): pass
class Video(Plugin): pass

print(Plugin.registry)   # {'Audio': ..., 'Video': ...}
```

Это элегантнее метакласса и понятнее.

## 3. `__slots__` — детали

- Убирает `__dict__`, экономит память.
- Нельзя добавлять новые атрибуты.
- Наследник без `__slots__` снова получает `__dict__`.
- Несовместим с `cached_property` (нужен `__dict__`).
- `@dataclass(slots=True)` в 3.10+.

```python
class Point:
    __slots__ = ("x", "y")
    def __init__(self, x, y): self.x, self.y = x, y
```

### Сколько экономит

```python
import sys

class WithDict:
    def __init__(self): self.x = 1

class WithSlots:
    __slots__ = ("x",)
    def __init__(self): self.x = 1

print(sys.getsizeof(WithDict()))    # ~48 + __dict__ (~104)
print(sys.getsizeof(WithSlots()))   # ~48
```

Экономия заметна на миллионах объектов: словарь `__dict__` на каждый экземпляр дорог.

### Подводные камни

```python
class Point:
    __slots__ = ("x", "y")

p = Point()
p.x = 1
p.z = 2      # AttributeError: 'Point' object has no attribute 'z'
```

Наследник без слотов теряет экономию:

```python
class Point3D(Point):
    pass          # снова есть __dict__

p = Point3D()
p.z = 3           # работает — но памяти больше
```

Чтобы сохранить эффект, у наследника тоже должны быть слоты:

```python
class Point3D(Point):
    __slots__ = ("z",)
```

### Сравнение

| | `__slots__` | обычный класс |
|---|---|---|
| Память на объект | меньше | больше |
| Новые атрибуты | запрещены | разрешены |
| `__dict__` | нет | есть |
| Гибкость | ниже | выше |
| Когда использовать | много мелких объектов | обычный код |

## 4. Dunder-методы, которые стоит знать

| Метод | Зачем |
|---|---|
| `__repr__`/`__str__` | представление |
| `__eq__`/`__hash__` | равенство/хеш |
| `__lt__` и др. | сравнения (сортировка) |
| `__len__`, `__bool__` | размер/истинность |
| `__getitem__`/`__setitem__` | индексация |
| `__contains__` | `in` |
| `__iter__`/`__next__` | итерация |
| `__call__` | вызов объекта |
| `__enter__`/`__exit__` | `with` |
| `__add__`/`__radd__` | арифметика |
| `__format__` | f-строки |
| `__getattr__`/`__setattr__` | динамические атрибуты |

```python
class Vec:
    def __init__(self, x): self.x = x
    def __add__(self, o): return Vec(self.x + o.x)
    def __radd__(self, o): return Vec(self.x + o)   # 3 + vec
    def __repr__(self): return f"Vec({self.x})"
```

**`__radd__`** нужен, когда объект справа, а слева — встроенный тип.

### Как работает `__radd__`

```python
print(Vec(1) + Vec(2))    # Vec(3) — вызывается Vec.__add__
print(3 + Vec(1))         # Vec(4) — int.__add__ не сработал → Vec.__radd__
```

Порядок: Python пробует `int.__add__(3, vec)`, получает `NotImplemented`, тогда вызывает `Vec.__radd__(vec, 3)`.

### Итерация

```python
class Countdown:
    def __init__(self, start): self.start = start
    def __iter__(self):
        n = self.start
        while n > 0:
            yield n
            n -= 1

print(list(Countdown(3)))   # [3, 2, 1]
```

Если есть `__iter__` как генератор, отдельный `__next__` не нужен.

## 5. `dataclass` vs `NamedTuple` vs обычный класс

| | dataclass | NamedTuple | обычный |
|---|---|---|---|
| Изменяемый | да (или `frozen`) | нет | да |
| `__eq__`/`__repr__` | авто | авто | вручную |
| Хешируемый | если `frozen` | да | вручную |
| Индексация | нет | да | нет |
| Наследование | удобно | ограничено | полное |
| Распаковка | нет | да | нет |

```python
from dataclasses import dataclass, field

@dataclass
class User:
    name: str
    age: int = 0
    tags: list = field(default_factory=list)   # безопасный мутабельный дефолт

u = User("Аня", 20)
print(u)              # User(name='Аня', age=20, tags=[])
```

### `frozen` и хеширование

```python
@dataclass(frozen=True)
class Point:
    x: int
    y: int

p = Point(1, 2)
print({p: "точка"})   # работает как ключ словаря
```

### Опасность мутабельного дефолта

```python
@dataclass
class Bad:
    items: list = []          # ОШИБКА: общий список на все экземпляры

@dataclass
class Good:
    items: list = field(default_factory=list)
```

## 6. Композиция, миксины, делегирование

- **Композиция** («has-a») часто лучше наследования («is-a»).
- **Миксин** — класс с одной узкой функциональностью, подмешиваемый через наследование.

```python
class JsonMixin:
    def to_json(self):
        import json
        return json.dumps(self.__dict__)
```

Делегирование: `__getattr__` пробрасывает вызовы вложенному объекту.

### Композиция vs наследование

```python
# Плохо: Car наследует Engine — это не «is-a»
class Car(Engine): ...

# Хорошо: у Car есть Engine — «has-a»
class Car:
    def __init__(self):
        self.engine = Engine()
```

| | Наследование | Композиция |
|---|---|---|
| Связь | «is-a» | «has-a» |
| Связанность | сильная | слабая |
| Гибкость | ниже | выше |
| Когда | реальное родство | замена части |

### Делегирование

```python
class Logger:
    def log(self, msg): print(f"[LOG] {msg}")

class Service:
    def __init__(self): self.logger = Logger()
    def do(self): self.logger.log("работаю")

Service().do()   # [LOG] работаю
```

Делегирование через `__getattr__`:

```python
class Wrapper:
    def __init__(self, obj): self._obj = obj
    def __getattr__(self, name):
        return getattr(self._obj, name)
```

## 7. `super()` — детали

- `super()` внутри метода — «следующий класс в MRO», не обязательно родитель.
- В `__init__` подкласса вызывай `super().__init__(...)`.
- `super(C, obj)` — явная форма.

### Почему не `Animal.__init__(self)`

Прямой вызов родителя ломает множественное наследование: один и тот же базовый класс может вызваться дважды. `super()` идёт строго по MRO.

```python
class A:
    def __init__(self): print("A")
class B(A):
    def __init__(self): print("B"); super().__init__()
class C(A):
    def __init__(self): print("C"); super().__init__()
class D(B, C):
    def __init__(self): print("D"); super().__init__()

D()   # D → B → C → A (A вызывается один раз)
```

## 8. Классовые vs экземплярные атрибуты

```python
class C:
    shared = []          # ОБЩИЙ для всех — ловушка!
    def __init__(self):
        self.own = []    # свой у каждого
```

Изменяемый атрибут класса — источник багов. Для значений по умолчанию используй `__init__` или `field(default_factory=...)`.

### Как правильно «неизменяемые» константы

```python
class Config:
    TIMEOUT = 30          # константа — можно и в классе
    RETRIES = 3
```

Проблема только с **изменяемыми** значениями (список, словарь, множество).

### Демонстрация бага

```python
class Cart:
    items = []

c1, c2 = Cart(), Cart()
c1.items.append("яблоко")
print(c2.items)     # ['яблоко'] — у второго тоже появилось!
```

## 9. Мини-итог

- `__getattribute__` вызывается всегда, `__getattr__` — только для отсутствующих атрибутов.
- `__set_name__` и `__init_subclass__` покрывают большинство задач, где раньше нужны были метаклассы.
- `__slots__` экономит память, но лишает гибкости; наследник должен тоже объявить слоты.
- Dunder-методы делают объект «родным» для синтаксиса Python.
- `dataclass` удобен для данных, `NamedTuple` — для неизменяемых записей, обычный класс — максимум контроля.
- Предпочитайте композицию наследованию; миксины дают узкую функциональность.
- Остерегайтесь изменяемых атрибутов класса.
