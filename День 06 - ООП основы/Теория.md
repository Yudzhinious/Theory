# День 6 — ООП: основы

> Цель: уверенно объяснить 4 принципа ООП, написать класс с инкапсуляцией и dunder-методами.

---

## 0. Коротко о главном

- **Класс** — чертёж, **экземпляр** — построенный по нему объект.
- Четыре принципа ООП: инкапсуляция, наследование, полиморфизм, абстракция.
- Python — объектно-ориентированный «насквозь»: даже `int` и `str` — объекты, а функции — тоже объекты.
- Инкапсуляция в Python держится на **соглашениях**, а не на жёстких запретах.

Аналогия: класс — это чертёж автомобиля, экземпляр — конкретная машина с вашим VIN. Один чертёж — много машин.

---

## 1. Четыре принципа ООП

- **Инкапсуляция** — сокрытие внутреннего состояния, доступ через интерфейс.
- **Наследование** — новый класс на основе существующего.
- **Полиморфизм** — один интерфейс, разное поведение.
- **Абстракция** — выделение существенного, скрытие деталей.

### Разбор на одном примере

Представьте банкомат:

| Принцип | Как проявляется |
|---|---|
| Инкапсуляция | Вы не трогаете деньги напрямую — только через кнопки |
| Наследование | «Банкомат Сбербанка» наследует «Банкомат» |
| Полиморфизм | Кнопка «снять» работает и в разных банках по-своему |
| Абстракция | Вам не важно, как внутри устроен счётчик купюр |

## 2. Класс и экземпляр

```python
class User:
    species = "human"                 # атрибут класса (общий)

    def __init__(self, name, age):    # конструктор
        self.name = name              # атрибут экземпляра
        self.age = age

    def greet(self):                  # метод (self — экземпляр)
        return f"Привет, {self.name}"

u = User("Аня", 20)
u.greet()          # 'Привет, Аня'
User.species       # 'human'
```

- `__init__` — инициализация уже созданного объекта.
- `self` — ссылка на экземпляр, передаётся автоматически.

### Пошаговый разбор создания

1. Вызывается `User("Аня", 20)`.
2. Python сначала создаёт пустой объект (через `__new__`).
3. Затем вызывает `__init__(obj, "Аня", 20)` — `self` автоматически равен объекту.
4. Записываются атрибуты `name` и `age` в `obj.__dict__`.
5. Возвращается готовый объект.

### Атрибуты класса vs экземпляра

```python
u1 = User("Аня", 20)
u2 = User("Боря", 22)
print(u1.species)          # human — из класса
u1.species = "robot"       # создали атрибут ЭКЗЕМПЛЯРА
print(u1.species)          # robot
print(u2.species)          # human — класс не изменился
print(User.species)        # human
```

**Ловушка:** изменяемый атрибут класса общий для всех.

```python
class Team:
    members = []          # ОБЩИЙ список — ошибка!

t1, t2 = Team(), Team()
t1.members.append("Аня")
print(t2.members)         # ['Аня'] — неожиданно!
```

Правильно — создавать в `__init__`:

```python
class Team:
    def __init__(self):
        self.members = []   # у каждого свой список
```

## 3. Инкапсуляция и name mangling

В Python нет настоящих `private`/`protected`, есть соглашения:

- `_name` — «защищённый» (protected), соглашение «не трогай снаружи».
- `__name` — **name mangling**: интерпретатор переименовывает в `_Класс__name`. Это не настоящая приватность.

```python
class Account:
    def __init__(self):
        self._balance = 0        # protected
        self.__pin = "1234"      # mangled

a = Account()
a._balance          # 0 — доступ есть, но так не принято
a.__pin             # AttributeError
a._Account__pin     # '1234' — обход через mangled имя
```

### Зачем name mangling

Он защищает от случайного перекрытия имён при наследовании:

```python
class Base:
    def __init__(self):
        self.__secret = "base"

class Child(Base):
    def __init__(self):
        super().__init__()
        self.__secret = "child"    # это _Child__secret, а не _Base__secret
```

Оба `__secret` сосуществуют, не затирая друг друга.

### Как правильно

| Хочу | Пишу | Смысл |
|---|---|---|
| Публичный | `name` | часть интерфейса |
| Для внутреннего использования | `_name` | «не влезай» |
| Избежать конфликта имён в наследниках | `__name` | mangling |
| Только чтение снаружи | `@property` | контролируемый доступ |

**Типичная ошибка:** считать `__name` реальной защитой. От неё легко обойти, это лишь соглашение.

## 4. `@property` — геттер/сеттер/делитер

Позволяет обращаться к методу как к атрибуту и контролировать доступ.

```python
class Temperature:
    def __init__(self):
        self._celsius = 0

    @property
    def celsius(self):               # геттер
        return self._celsius

    @celsius.setter
    def celsius(self, value):        # сеттер
        if value < -273.15:
            raise ValueError("Ниже абсолютного нуля!")
        self._celsius = value

    @celsius.deleter
    def celsius(self):               # делитер
        del self._celsius

t = Temperature()
t.celsius = 25       # вызывает setter
print(t.celsius)     # 25 — вызывает getter
```

### Как это работает

`@property` — это **дескриптор**: он подменяет обычный атрибут объектом, который при чтении вызывает геттер, а при записи — сеттер. Снаружи всё выглядит как атрибут, но под капотом — методы.

### Вычисляемые свойства

```python
class Rectangle:
    def __init__(self, w, h):
        self.w, self.h = w, h

    @property
    def area(self):                  # вычисляется на лету
        return self.w * self.h

r = Rectangle(3, 4)
print(r.area)     # 12
r.w = 5
print(r.area)     # 20
```

### Сравнение с обычными методами

| | Атрибут | `@property` | Метод |
|---|---|---|---|
| Синтаксис | `obj.x` | `obj.x` | `obj.x()` |
| Валидация | нет | да | да |
| Вычисление на лету | нет | да | да |
| Меняет интерфейс | — | нет | да (нужны скобки) |

**Плюс `@property`:** можно начать с простого атрибута, а позже добавить валидацию, не меняя внешний код.

## 5. Наследование и `super()`

```python
class Animal:
    def __init__(self, name):
        self.name = name
    def speak(self):
        raise NotImplementedError

class Dog(Animal):
    def speak(self):
        return f"{self.name}: Гав!"

class Puppy(Dog):
    def speak(self):
        return super().speak() + " (тоненько)"
```

`super()` возвращает прокси к следующему классу в MRO (детали — День 7).

### Пошагово

1. `Puppy("Рекс")` → `__init__` наследуется от `Animal`, `self.name = "Рекс"`.
2. `Puppy.speak` вызывает `super().speak()` → идёт по MRO к `Dog.speak`.
3. `Dog.speak` возвращает `"Рекс: Гав!"`.
4. Добавляется `" (тоненько)"` → `"Рекс: Гав! (тоненько)"`.

### `isinstance` и `issubclass`

```python
p = Puppy("Рекс")
print(isinstance(p, Puppy))    # True
print(isinstance(p, Animal))   # True — наследует
print(issubclass(Puppy, Dog))  # True
```

### Типичные ошибки

- Забыть вызвать `super().__init__()` — родительские атрибуты не создадутся.
- Слишком глубокая иерархия — код становится хрупким. Часто композиция лучше.

## 6. Полиморфизм и утиная типизация

```python
class Cat:
    def sound(self): return "Мяу"
class Dog:
    def sound(self): return "Гав"

def make_sound(animal):
    return animal.sound()   # важно наличие метода, а не тип

make_sound(Cat())   # 'Мяу'
make_sound(Dog())   # 'Гав'
```

«Если объект ведёт себя как утка — это утка». Python проверяет наличие метода, а не тип.

### Полиморфизм через общий интерфейс

```python
class Shape:
    def area(self): ...

class Circle(Shape):
    def __init__(self, r): self.r = r
    def area(self): return 3.14 * self.r ** 2

class Square(Shape):
    def __init__(self, a): self.a = a
    def area(self): return self.a ** 2

for s in [Circle(1), Square(2)]:
    print(s.area())     # 3.14, 4
```

Один вызов `s.area()` — разное поведение. Это и есть полиморфизм.

### Плюс и минус утиной типизации

| Плюс | Минус |
|---|---|
| Гибкость, минимум церемоний | Ошибки видны только в рантайме |
| Не нужно наследование | IDE хуже подсказывает |

## 7. `@staticmethod` и `@classmethod`

| | `@staticmethod` | `@classmethod` |
|---|---|---|
| Первый аргумент | нет | `cls` |
| Доступ к атрибутам класса | нет | да |
| Применение | утилиты | альтернативные конструкторы, фабрики |

```python
class Person:
    def __init__(self, name, age):
        self.name, self.age = name, age

    @classmethod
    def from_birth_year(cls, name, year):
        return cls(name, 2026 - year)   # альтернативный конструктор

    @staticmethod
    def is_adult(age):
        return age >= 18

p = Person.from_birth_year("Аня", 2005)
Person.is_adult(20)   # True
```

### Почему `cls`, а не `Person`

Если у класса есть наследник, `cls` укажет на него — фабрика создаст правильный тип.

```python
class Student(Person):
    pass

s = Student.from_birth_year("Боря", 2006)
print(type(s))     # <class 'Student'>
```

### Когда что использовать

- `@staticmethod` — функция логически относится к классу, но не использует ни `self`, ни `cls`.
- `@classmethod` — нужен доступ к классу: альтернативный конструктор, фабрика, регистрация.

## 8. Магические (dunder) методы

```python
class Vector:
    def __init__(self, x, y):
        self.x, self.y = x, y
    def __repr__(self):              # для отладки
        return f"Vector({self.x}, {self.y})"
    def __str__(self):               # для пользователя (print)
        return f"({self.x}, {self.y})"
    def __add__(self, other):        # v1 + v2
        return Vector(self.x + other.x, self.y + other.y)
    def __eq__(self, other):         # v1 == v2
        return (self.x, self.y) == (other.x, other.y)
    def __len__(self):
        return 2
```

Популярные: `__init__`, `__repr__`, `__str__`, `__eq__`, `__hash__`, `__len__`, `__getitem__`, `__iter__`, `__call__`, `__enter__/__exit__`.

### `__repr__` vs `__str__`

| | `__repr__` | `__str__` |
|---|---|---|
| Для кого | разработчик | пользователь |
| Вызов | `repr(x)`, в отладчике, в списках | `str(x)`, `print(x)` |
| Цель | однозначно воспроизвести объект | читаемый вид |
| Fallback | если нет `__str__`, берётся `__repr__` | — |

```python
class Money:
    def __init__(self, amount): self.amount = amount
    def __repr__(self): return f"Money({self.amount})"
    def __str__(self): return f"{self.amount} руб."

m = Money(100)
print(m)          # 100 руб.
print([m])        # [Money(100)]  — используется __repr__
```

### `__eq__` и `__hash__`

Если определяете `__eq__`, Python **обнуляет** `__hash__` — объект перестаёт быть хешируемым. Если нужен хеш — определите и `__hash__`.

```python
class Point:
    def __init__(self, x, y): self.x, self.y = x, y
    def __eq__(self, o): return (self.x, self.y) == (o.x, o.y)
    def __hash__(self): return hash((self.x, self.y))

print({Point(1, 2)})   # работает как ключ словаря
```

### Другие полезные dunder

```python
class Box:
    def __init__(self, items): self.items = list(items)
    def __getitem__(self, i): return self.items[i]      # box[0]
    def __iter__(self): return iter(self.items)          # for x in box
    def __contains__(self, x): return x in self.items    # x in box
    def __call__(self, x): return x * 2                  # box(3)

b = Box([10, 20, 30])
print(b[1])        # 20
print(20 in b)     # True
print(b(3))        # 6
```

## 9. `__new__` vs `__init__`

- `__new__` — **создаёт** объект (возвращает экземпляр). Нужен для `tuple`/`str`-подобных и паттернов (singleton).
- `__init__` — **инициализирует** уже созданный объект.

```python
class Singleton:
    _instance = None
    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance
```

### Порядок вызовов

1. `__new__(cls, ...)` создаёт и возвращает объект.
2. `__init__(self, ...)` настраивает его.
3. Если `__new__` вернул объект **другого** класса, `__init__` не вызовется.

### Сравнение

| | `__new__` | `__init__` |
|---|---|---|
| Роль | создаёт объект | настраивает объект |
| Первый аргумент | `cls` | `self` |
| Возвращает | объект | `None` |
| Нужен обычно | редко | почти всегда |

```python
class Singleton:
    _instance = None
    def __new__(cls, *a, **k):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance

a, b = Singleton(), Singleton()
print(a is b)     # True
```

## 10. Мини-итог и связки

- Класс — шаблон, экземпляр — конкретный объект; атрибуты класса общие, экземпляра — свои.
- Инкапсуляция в Python — соглашения `_x`/`__x` + `@property`.
- Наследование даёт повторное использование, `super()` идёт по MRO.
- Полиморфизм и утиная типизация: важен метод, а не тип.
- Dunder-методы встраивают объект в синтаксис языка (`+`, `==`, `len`, `with`).
- `__new__` создаёт, `__init__` настраивает.
