## 0. Как думать о структурах данных

**Структура данных** — это способ организовать данные так, чтобы нужные операции были
быстрыми. Нет «лучшей» структуры: есть подходящая под задачу.

> **Аналогия.** Это как тара для вещей. Список — стопка тарелок (быстро сверху, медленно
> из середины). Очередь — лента в магазине. Словарь — гардероб с номерками: по номеру
> сразу находишь вещь. Выбирай тару под задачу.

Два главных вопроса при выборе:

1. **Какая операция самая частая?** (поиск, вставка, удаление, доступ по индексу)
2. **Насколько важна память и порядок?**

**O-нотация** (асимптотика) показывает, как растёт время работы при росте данных:

| Обозначение | Название | Пример |
|---|---|---|
| O(1) | Константа | доступ по индексу |
| O(log n) | Логарифм | бинарный поиск |
| O(n) | Линейная | проход по списку |
| O(n log n) | Линеарифмическая | хорошие сортировки |
| O(n²) | Квадрат | двойной цикл |

## 1. Стек (Stack) — LIFO

Последний пришёл — первый вышел. Реализация — `list` (в конец) или `deque`.

```python
stack = []
stack.append(1); stack.append(2)   # push
stack.pop()                        # 2 (pop)
stack[-1]                          # 1 (peek)
```

**O(1)** на push/pop. Применение: откат, парсинг скобок, DFS, вызовы функций.

### 1.1 Разбор на примере: проверка скобок

```python
def is_balanced(s: str) -> bool:
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in s:
        if ch in "([{":
            stack.append(ch)              # открывающую — в стек
        elif ch in ")]}":
            if not stack or stack.pop() != pairs[ch]:
                return False              # нет пары или не та скобка
    return not stack                       # стек пуст => всё закрыто

print(is_balanced("({[]})"))   # True
print(is_balanced("(]"))       # False
```

### 1.2 Типичная ошибка

```python
# ПЛОХО: pop из пустого стека -> IndexError
stack = []
stack.pop()

# ХОРОШО: проверять перед извлечением
if stack:
    stack.pop()
```

## 2. Очередь (Queue) — FIFO

Первый пришёл — первый вышел. Для O(1) с обеих сторон — `collections.deque` (у `list` `pop(0)` — O(n)).

```python
from collections import deque
q = deque()
q.append(1); q.append(2)   # enqueue
q.popleft()                # 1 (dequeue)
```

Применение: очереди задач, BFS, планировщики.

### 2.1 Почему `list.pop(0)` медленный

```python
lst = [1, 2, 3, 4, 5]
lst.pop(0)     # удаляет первый -> все остальные сдвигаются влево: O(n)
```

`deque` (double-ended queue) устроен как список блоков и умеет добавлять/забирать
с обоих концов за O(1).

```python
from collections import deque
q = deque([1, 2, 3])
q.appendleft(0)    # [0, 1, 2, 3] — O(1)
q.pop()            # 3             — O(1)
```

### 2.2 Очередь с приоритетом

См. раздел 6 (heapq): элементы извлекаются не по порядку прихода, а по «важности».

## 3. Связный список (Linked List)

Узлы со ссылкой на следующий (и/или предыдущий). Вставка/удаление при известном узле — **O(1)**, доступ по индексу — **O(n)**.

```python
class Node:
    def __init__(self, value):
        self.value = value
        self.next = None

a = Node(1); b = Node(2)
a.next = b
```

Плюс: не нужен непрерывный блок памяти. Минус: нет произвольного доступа, больше накладных расходов. В Python на практике чаще `list`.

### 3.1 Разбор: обход и разворот

```python
def to_list(head):
    out, node = [], head
    while node:
        out.append(node.value)     # O(n) — идём по ссылкам
        node = node.next
    return out

def reverse(head):
    prev = None
    while head:
        nxt = head.next            # запомнили следующий
        head.next = prev           # развернули ссылку
        prev, head = head, nxt
    return prev                    # новый первый узел
```

### 3.2 Сравнение со списком

| Критерий | Массив / `list` | Связный список |
|---|---|---|
| Доступ по индексу | O(1) | O(n) |
| Вставка в начало | O(n) | O(1) |
| Вставка при известном узле | O(n) | O(1) |
| Память | Компактно | Доп. указатели |
| Кэш CPU | Дружелюбен | Плохо |

## 4. Хеш-таблица (Hash Table)

Основа `dict`/`set`. Ключ → хеш → «ведро». Средний поиск/вставка **O(1)**, худший O(n) при коллизиях. Требует хешируемых ключей.

### 4.1 Как это работает по шагам

1. У ключа вычисляется **хеш** — число: `hash("Аня")`.
2. По модулю размера таблицы выбирается **ведро** (индекс).
3. В ведре хранится пара «ключ → значение».
4. При поиске повторяем шаги 1–2 и сравниваем ключ (на случай коллизий).

```python
d = {"Аня": 25, "Борис": 30}
print(d["Аня"])          # 25 — почти мгновенно, O(1)
print(hash("Аня"))       # большое число (меняется между запусками!)
```

### 4.2 Хешируемость

```python
d = {(1, 2): "точка"}     # tuple хешируем — можно ключом
# d = {[1, 2]: "x"}       # TypeError: list не хешируется (изменяемый)
```

Хешируемыми могут быть только **неизменяемые** объекты: числа, строки, `tuple`,
`frozenset`. Список и словарь — нельзя, ведь их содержимое может измениться и «сломать»
ведро.

### 4.3 Типичная ошибка: плохой ключ

```python
# ПЛОХО: изменяемый ключ невозможен
cache = {}
cache[[1, 2]] = "x"        # TypeError

# ХОРОШО: кортеж вместо списка
cache[(1, 2)] = "x"
```

## 5. Деревья и BST

**Бинарное дерево поиска (BST):** левый < узел < правый.
- Поиск/вставка/удаление: **O(log n)** в среднем, **O(n)** в худшем (вырожденное дерево).
- Сбалансированные деревья (AVL, красно-чёрные) держат O(log n).

```python
class TreeNode:
    def __init__(self, value):
        self.value = value
        self.left = None
        self.right = None
```

Обходы: **in-order** (сортированный порядок), **pre-order**, **post-order**.

### 5.1 Разбор: вставка и поиск в BST

```python
def insert(root, value):
    if root is None:
        return TreeNode(value)
    if value < root.value:
        root.left = insert(root.left, value)     # меньше -> налево
    elif value > root.value:
        root.right = insert(root.right, value)   # больше -> направо
    return root

def search(root, value):
    if root is None or root.value == value:
        return root
    if value < root.value:
        return search(root.left, value)
    return search(root.right, value)
```

### 5.2 Обходы и их смысл

```python
def inorder(node):
    if node:
        inorder(node.left)      # сначала левое
        print(node.value)       # потом узел
        inorder(node.right)     # потом правое
# in-order по BST даёт элементы по возрастанию
```

| Обход | Порядок | Применение |
|---|---|---|
| pre-order | узел → лево → право | копирование дерева |
| in-order | лево → узел → право | сортированный вывод |
| post-order | лево → право → узел | удаление дерева |
| level-order | по уровням (BFS) | поиск в ширину |

### 5.3 Почему BST может выродиться

Если вставлять уже отсортированные числа `1, 2, 3, 4`, дерево станет «цепочкой» —
как связный список, и поиск будет O(n). Поэтому существуют **самобалансирующиеся**
деревья.

## 6. Куча (Heap) и приоритетная очередь

`heapq` — min-heap на списке. Минимум/максимум — **O(1)**, вставка/извлечение — **O(log n)**.

```python
import heapq
h = [3, 1, 2]
heapq.heapify(h)          # [1, 3, 2]
heapq.heappush(h, 0)
heapq.heappop(h)          # 0
```

Применение: планировщики, top-K, алгоритм Дейкстры.

### 6.1 Разбор: top-3 самых больших

```python
import heapq
nums = [5, 1, 9, 3, 7, 2]
print(heapq.nlargest(3, nums))   # [9, 7, 5]
print(heapq.nsmallest(3, nums))  # [1, 2, 3]
```

### 6.2 Max-heap через отрицание

В Python только min-heap. Чтобы получить максимум — храним числа со знаком минус:

```python
import heapq
maxh = [-x for x in [5, 1, 9]]
heapq.heapify(maxh)              # [-9, -1, -5]
print(-heapq.heappop(maxh))      # 9
```

## 7. Графы и обходы

Граф = вершины + рёбра. Представление: список смежности (`dict[вершина] -> list`) или матрица смежности.

- **BFS** (поиск в ширину) — очередь, кратчайший путь в невзвешенном графе.
- **DFS** (поиск в глубину) — стек/рекурсия, обход вглубь.

```python
from collections import deque

def bfs(graph, start):
    visited, queue = {start}, deque([start])
    order = []
    while queue:
        v = queue.popleft()
        order.append(v)
        for n in graph.get(v, []):
            if n not in visited:
                visited.add(n)
                queue.append(n)
    return order
```

### 7.1 DFS на стеке

```python
def dfs(graph, start):
    visited, stack = set(), [start]
    order = []
    while stack:
        v = stack.pop()               # берём последний -> вглубь
        if v not in visited:
            visited.add(v)
            order.append(v)
            stack.extend(graph.get(v, []))
    return order
```

### 7.2 Сравнение BFS и DFS

| | BFS | DFS |
|---|---|---|
| Структура | очередь | стек/рекурсия |
| Идёт | по уровням | вглубь |
| Кратчайший путь (невзвеш.) | Да | Нет |
| Память | Шире (много соседей) | Глубже |
| Применение | путь, уровни | циклы, топосорт, компоненты |

> **Аналогия.** BFS — как круги по воде от брошенного камня. DFS — как идти по лабиринту,
> углубляясь в первый коридор до тупика, потом возвращаться.

## 8. Рекурсия и мемоизация

Рекурсия — функция вызывает себя; нужен **базовый случай**. Глубина ограничена (`sys.setrecursionlimit`).

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    return n if n < 2 else fib(n-1) + fib(n-2)
```

Мемоизация превращает экспоненциальный Фибоначчи в O(n).

### 8.1 Почему без мемоизации так плохо

```python
def fib_slow(n):
    return n if n < 2 else fib_slow(n-1) + fib_slow(n-2)

# fib_slow(5) вызывает fib_slow(3) несколько раз — дерево вызовов растёт как 2^n
```

С `lru_cache` каждый `n` считается один раз — **O(n)**.

### 8.2 Типичная ошибка

```python
# ПЛОХО: нет базового случая -> RecursionError
def countdown(n):
    return countdown(n - 1)

# ХОРОШО: базовый случай останавливает рекурсию
def countdown(n):
    if n <= 0:
        return
    countdown(n - 1)
```

## 9. Шпаргалка сложностей

| Структура | Доступ | Поиск | Вставка | Удаление |
|---|---|---|---|---|
| `list` | O(1) | O(n) | O(1)* | O(n) |
| `dict`/`set` | — | O(1) ср. | O(1) ср. | O(1) ср. |
| `deque` | O(n) | O(n) | O(1) | O(1) |
| Связный список | O(n) | O(n) | O(1) | O(1) |
| BST (сбаланс.) | O(log n) | O(log n) | O(log n) | O(log n) |
| Heap | O(1) min | O(n) | O(log n) | O(log n) |

\* в конец; в начало — O(n).

### 9.1 Когда что выбрать

- Нужен быстрый поиск по ключу → `dict`/`set`.
- Нужен порядок и индексы → `list`.
- Нужны частые операции с обоих концов → `deque`.
- Нужен всегда минимальный элемент → `heapq`.
- Нужен быстрый поиск в отсортированных данных → бинарный поиск / BST.

## 10. Мини-итог

- Стек (LIFO) и очередь (FIFO) — базовые «контейнеры» алгоритмов.
- `list` быстр на конце, `deque` — с обоих концов.
- Хеш-таблицы дают O(1) в среднем, но требуют хешируемых ключей.
- BST быстр, но нужен баланс; heap даёт быстрый минимум.
- BFS/DFS — два способа обойти граф.
- Мемоизация ускоряет рекурсию за счёт памяти.
