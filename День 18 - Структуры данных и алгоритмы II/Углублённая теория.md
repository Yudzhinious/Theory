## 1. Динамический массив и амортизация

- `list` — массив указателей с запасом ёмкости.
- `append` — O(1) амортизированно: редкие resize O(n), усредняются.
- Вставка/удаление в середине — O(n) (сдвиг).
- `array`/`numpy` — компактное хранение чисел (без объектов).

### 1.1 Что такое амортизация на примере

`list` хранит указатели в непрерывном блоке. Когда места не хватает, Python выделяет
**больший** блок (примерно ×1.125–2) и копирует туда элементы — это O(n). Но копирование
происходит редко, поэтому «в среднем» на один `append` уходит O(1).

```text
append 1..4: места хватает
append 5:   resize -> копия 4 элементов (редко)
append 6..8: снова хватает
append 9:   resize -> копия 8 элементов (ещё реже)
```

> **Аналогия.** Вы переписываете список дел в блокнот. Когда страница кончилась,
> берёте блокнот в два раза больше и переписываете всё. Это дорого, но случается
> редко — в среднем одна строка дописывается мгновенно.

### 1.2 `list` vs `array` vs `numpy`

| | `list` | `array('i')` | `numpy.ndarray` |
|---|---|---|---|
| Хранит | Указатели на объекты | Сырые числа | Сырые числа + vectorization |
| Память | Большая | Компактная | Компактная |
| Скорость математики | Медленно | Средне | Очень быстро |
| Разные типы | Да | Нет | Нет |

## 2. Связные списки (варианты)

- **Singly** — только вперёд; **doubly** — в оба конца; **circular** — замкнутый.
- Вставка/удаление при известном узле — O(1); доступ — O(n).
- В Python `deque` — фактически список блоков (эффективнее чистого связного списка).
- Применение: LRU-кэш (двусвязный + хеш-таблица), редакторы, буферы.

```python
class Node:
    __slots__ = ("val", "prev", "next")
    def __init__(self, val): self.val, self.prev, self.next = val, None, None
```

### 2.1 `__slots__` — зачем

По умолчанию каждый объект держит `__dict__` (словарь атрибутов) — накладно при
миллионах узлов. `__slots__` фиксирует набор атрибутов и экономит память.

```python
class WithDict:
    def __init__(self, v): self.v = v

class WithSlots:
    __slots__ = ("v",)
    def __init__(self, v): self.v = v

import sys
print(sys.getsizeof(WithDict(1)))    # ~56 + dict
print(sys.getsizeof(WithSlots(1)))   # ~32 (без dict)
```

### 2.2 LRU-кэш = двусвязный список + хеш-таблица

Чтобы за O(1) и находить элемент, и «освежать» его позицию, комбинируют:

- **хеш-таблицу** — доступ к узлу по ключу;
- **двусвязный список** — порядок использования (свежие в голове, старые в хвосте).

В Python для этого есть готовый `functools.lru_cache` и `collections.OrderedDict`.

## 3. Хеш-таблицы: коллизии

- **Chaining** — список в каждом ведре.
- **Open addressing** (CPython) — пробирование с «perturb»; хранит индексы, а не пары.
- **Load factor** — доля заполнения; при превышении — resize и rehash.
- Хеш-функция должна давать равномерное распределение; плохие хеши → O(n).

### 3.1 Два способа разрешать коллизии

```text
Chaining (цепочки):
ведро 3 -> [("ключ1", v1), ("ключ2", v2)]

Open addressing (открытая адресация):
индекс 3 занят -> пробуем 4 -> 5 -> ... пока не найдём свободный
```

| Способ | Плюсы | Минусы |
|---|---|---|
| Chaining | Просто, устойчив к заполнению | Доп. память на списки |
| Open addressing | Компактно, кэш-дружелюбно | Чувствителен к load factor |

### 3.2 Load factor и rehash

Когда таблица заполнена примерно на 2/3, CPython создаёт новую, вдвое большую, и
пересчитывает позиции всех ключей (`rehash`). Именно поэтому `dict` «не любит»
экстремально большие объёмы и плохие хеши.

### 3.3 Типичная ошибка: изменяемый ключ

```python
# ПЛОХО: список нельзя положить в set
# {[1, 2], [3, 4]}    # TypeError: unhashable type: 'list'

# ХОРОШО: кортежи
{(1, 2), (3, 4)}
```

## 4. Деревья

- **Binary tree / BST** — поиск O(log n) в среднем.
- **AVL / Red-Black** — самобалансирующиеся, гарантируют O(log n).
- **B-tree / B+tree** — основа индексов БД и файловых систем (много ветвлений).
- **Trie (префиксное дерево)** — автодополнение, словари.
- Обходы: pre/in/post-order, level-order (BFS).

```python
def inorder(node):
    if node:
        yield from inorder(node.left)
        yield node.value
        yield from inorder(node.right)
```

### 4.1 Почему нужен баланс

```text
Вставляем 1,2,3,4,5 в BST:

Вырожденное:            Сбалансированное (AVL):
1                              3
 \                            / \
  2                          2   4
   \                        /     \
    3                      1       5
     \
      4
       \
        5
Поиск O(n)              Поиск O(log n)
```

### 4.2 Типы деревьев и применения

| Дерево | Особенность | Где используется |
|---|---|---|
| BST | Левый < узел < правый | Учебное, простые задачи |
| AVL | Строгий баланс | Частые поиски |
| Red-Black | Мягкий баланс | `std::map`, многие стандартные библиотеки |
| B-tree/B+tree | Много ветвлений | Индексы БД, ФС |
| Trie | Общие префиксы | Автодополнение, поиск слов |

### 4.3 Trie на пальцах

```python
class TrieNode:
    def __init__(self):
        self.children = {}
        self.is_word = False

root = TrieNode()
def insert(word):
    node = root
    for ch in word:
        node = node.children.setdefault(ch, TrieNode())
    node.is_word = True
```

Хранение `cat`, `car`, `care` делит общий префикс `ca` — экономия памяти и быстрый
поиск по префиксу.

## 5. Куча и приоритетная очередь

- **Binary heap** — полное дерево в массиве; `heapq` — min-heap.
- `heapify` — O(n) (не O(n log n)!), push/pop — O(log n), peek — O(1).
- Применение: top-K, Дейкстра, планировщики, merge K списков.

```python
import heapq
heapq.nsmallest(3, data)
# max-heap через отрицание
maxh = [-x for x in data]; heapq.heapify(maxh)
```

### 5.1 Почему `heapify` за O(n)

Наивно: вставить n элементов по O(log n) → O(n log n). Но `heapify` идёт снизу вверх
и «просеивает» вниз. Большинство узлов находятся внизу, где просеивание короткое,
поэтому суммарная работа — O(n).

### 5.2 Применение: merge K отсортированных списков

```python
import heapq

def merge_k(lists):
    heap = [(lst[0], i, 0) for i, lst in enumerate(lists) if lst]
    heapq.heapify(heap)
    out = []
    while heap:
        val, i, j = heapq.heappop(heap)
        out.append(val)
        if j + 1 < len(lists[i]):
            heapq.heappush(heap, (lists[i][j+1], i, j+1))
    return out
```

## 6. Графы и алгоритмы

- Представление: список смежности (разреженные), матрица (плотные).
- **BFS** — кратчайший путь в невзвешенном, O(V+E).
- **DFS** — обход, циклы, топосортировка, компоненты.
- **Dijkstra** — кратчайшие пути (неотрицательные), O((V+E) log V) с кучей.
- **Bellman-Ford** — отрицательные веса, O(VE).
- **Floyd-Warshall** — все пары, O(V³).
- **Topological sort** — порядок зависимостей (Kahn/DFS).
- **Union-Find (DSU)** — компоненты, Kruskal; с сжатием путей почти O(1).

```python
# Union-Find
parent = list(range(n))
def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]   # path compression
        x = parent[x]
    return x
def union(a, b):
    parent[find(a)] = find(b)
```

### 6.1 Представления графа

```python
# Список смежности — экономично для разреженных графов
graph = {"A": ["B", "C"], "B": ["A"], "C": ["A"]}

# Матрица смежности — быстро проверять ребро, но O(V^2) памяти
#      A B C
# A [[0,1,1],
# B  [1,0,0],
# C  [1,0,0]]
```

| | Список смежности | Матрица смежности |
|---|---|---|
| Память | O(V+E) | O(V²) |
| Проверка ребра | O(степень) | O(1) |
| Перебор соседей | Быстро | O(V) |
| Хорошо для | Разреженных | Плотных |

### 6.2 Топологическая сортировка (Kahn)

Порядок, в котором каждая задача идёт после своих зависимостей:

```python
from collections import deque

def topo_sort(graph):
    indeg = {u: 0 for u in graph}
    for u in graph:
        for v in graph[u]:
            indeg[v] += 1
    q = deque([u for u in indeg if indeg[u] == 0])
    order = []
    while q:
        u = q.popleft()
        order.append(u)
        for v in graph[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)
    return order if len(order) == len(graph) else None   # None => цикл
```

### 6.3 Алгоритмы на графах — сводка

| Алгоритм | Задача | Сложность |
|---|---|---|
| BFS | Кратчайший путь (невзвеш.) | O(V+E) |
| DFS | Обход, циклы, компоненты | O(V+E) |
| Dijkstra | Кратчайшие пути (вес ≥ 0) | O((V+E) log V) |
| Bellman-Ford | Отрицательные веса | O(VE) |
| Floyd-Warshall | Все пары | O(V³) |
| Kahn/DFS | Топосортировка | O(V+E) |
| Union-Find | Компоненты | почти O(1) на операцию |

## 7. Поиск и приёмы

- **Бинарный поиск** — O(log n), но нужен отсортированный массив; `bisect`.
- **Two pointers**, **sliding window**, **prefix sums**.
- **Quickselect** — k-й элемент за O(n) в среднем.

### 7.1 Бинарный поиск через `bisect`

```python
import bisect
arr = [1, 3, 5, 7, 9]
i = bisect.bisect_left(arr, 5)     # индекс вставки 5 -> 2
print(arr[i])                      # 5
```

### 7.2 Приёмы на массивах

```python
# Two pointers: есть ли пара с суммой target в отсортированном массиве
def has_pair(arr, target):
    l, r = 0, len(arr) - 1
    while l < r:
        s = arr[l] + arr[r]
        if s == target: return True
        if s < target: l += 1
        else: r -= 1
    return False

# Prefix sums: сумма подмассива за O(1)
pref = [0]
for x in [1, 2, 3, 4]:
    pref.append(pref[-1] + x)
print(pref[3] - pref[1])           # сумма arr[1:3]
```

## 8. Анализ сложности

- **Худший / средний / амортизированный** случаи.
- **Время** и **память** (in-place vs O(n)).
- **Trade-offs:** время ↔ память (кэш, предподсчёт).
- Асимптотика не учитывает константы — на малых данных простой алгоритм может быть быстрее.

### 8.1 Три вида оценки

```text
Худший:          гарантия «не хуже» (dict: O(n) при коллизиях)
Средний:         ожидание на «типичных» данных (dict: O(1))
Амортизированный: усреднение по серии операций (list.append: O(1))
```

| Оценка | Вопрос | Пример |
|---|---|---|
| Худший | Что в самом плохом случае? | QuickSort O(n²) |
| Средний | Что в среднем? | QuickSort O(n log n) |
| Амортизированный | Что на длинной серии? | `append`, `dict` |

### 8.2 Trade-off время ↔ память

```python
# Медленнее, но без доп. памяти: считать сумму каждый раз O(n)
def range_sum(arr, i, j):
    return sum(arr[i:j])

# Быстрее (O(1)), но O(n) памяти: предпосчитать префиксные суммы
pref = [0]
for x in arr:
    pref.append(pref[-1] + x)
```

## 10. Мини-итог

- `list` — динамический массив с амортизированным `append`.
- Связные списки дают O(1) вставку, но O(n) доступ; `__slots__` экономит память.
- Хеш-таблицы: коллизии (цепочки/адресация), load factor, rehash.
- Балансирующиеся деревья гарантируют O(log n); B-tree — основа индексов; trie — префиксы.
- `heapify` за O(n); heap — для top-K и Дейкстры.
- Графы: BFS/DFS/Dijkstra/Bellman-Ford/Floyd/Union-Find.
- Асимптотику всегда уточняют: худший/средний/амортизированный.
